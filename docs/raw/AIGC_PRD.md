## 1. 产品概述

### 1.1 背景与痛点

失去亲人的人手里，通常只剩下**几张模糊、破损、褪色的老照片**：

- 唯一一张清晰照是 20 年前用胶卷拍的，扫描后糊、有划痕、偏色；
- 找不到一张"他在自己家里吃饭""她带孙子在公园"的生活照；
- 家里从来没有过全家福，或者那张全家福在搬迁中丢了。

市面上现有工具解决不了这件事：修图软件只能去噪，AI 换脸工具产出的是**塑料感、过度磨皮、一眼假的"AI 仿真人"**——对这类用户而言，这不是安慰，是二次伤害。他们需要的不是"更像"的脸，而是**"这看起来真像当年拍的那张照片"**。

### 1.2 产品定位

> **一句话**：把几张模糊破损的老照片，变成一组「看起来就是手机/相机随手拍出来的」真实生活场景照与全家福。

- **不是**「AI 换脸」「数字复活」「让照片动起来」；
- **而是**「照片修复 + 真实感场景补拍」——像一位懂摄影、懂那个年代影像质感的暗房师傅，帮这家人把缺失的照片补上。

### 1.3 目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 主要用户 · 中青年子女（30–55 岁） | 替父母/自己整理老照片，手机操作，不懂 AI | 让逝去的父亲重新出现在一张像样的照片里 |
| 次要用户 · 年长亲属（55 岁+） | 由子女引导使用，对"假"极度敏感 | 全家福要"看着是真的" |
| 边界用户 · 影像修复从业者 | 批量处理需求 | 效果稳定、可控 |

### 1.4 价值主张

1. **真实** —— 交付物必须经得起"这是一张真照片吗"的审视；
2. **像他** —— 面部特征必须能被家人一眼认出；
3. **像那个年代** —— 不只是像照片，还要像**那个年代拍的照片**；
4. **体面** —— 全程温和、不猎奇、不渲染悲伤。

## 2. 核心设计原则：绝对真实感（最高优先级）

> 本节为全文档最高优先级约束。**任何功能、任何优化，与本节冲突时以本节为准。**

### 2.1 "真实感"的定义

生成的图片必须让观看者的第一反应是 **"这是一张拍出来的照片"**，而不是"这是一张 AI 图"。具体对标三类真实影像：

| 目标质感 | 参考样态 |
|---|---|
| 早期胶片扫描 | 颗粒、轻微偏色（偏黄/偏青）、边缘失焦、有划痕与灰点 |
| 2000s 数码/手机拍摄 | 略低的动态范围、轻微噪点、闪光灯压脸、构图随意 |
| 2010s+ 手机拍摄 | 通透、细节清晰、白平衡基本准确、阴天漫射光、构图随意 |

### 2.2 必须保留（Preserve）

- **面部身份特征**：五官比例、痣、疤、牙齿形态、发型、脸型轮廓、表情习惯 —— 与源照片的相似度是硬指标（见 §2.4）；
- **皮肤真实纹理**：毛孔、细纹、法令纹、老年斑、真实肤色不均；
- **年代感**：色调偏移、颗粒/噪点、轻微对焦不实、镜头畸变、闪光灯痕迹、背景略杂乱。

### 2.3 严禁出现（红线 / Anti-AI）

| 类别 | 具体禁止项 |
|---|---|
| 皮肤 | 塑料感、蜡像感、过度磨皮、零毛孔、均匀到不真实的高光 |
| 质感 | 3D 渲染感、CG、插画/油画/动漫风、HDR 过度、锐化过度 |
| 面部 | 五官对称完美、眼睛出现不自然的"AI 高光"、牙齿过白过齐、妆容夸张 |
| 年龄 | **把老人"磨"年轻**——皱纹、老年斑、皮肤松弛被抹平（见 §5.7） |
| 背景 | 过饱和、虚化逻辑错误、背景元素重复/糊成一片、与年代不符的现代物件 |
| 整体 | "一眼 AI"的精致感、商业广告大片感、影楼摆拍感 |

**产品级验收口诀**：*宁可丑一点、旧一点、有点糊，也绝不允许"完美"。*

### 2.4 可度量的验收标准

| 指标 | 定义 | MVP 目标 |
|---|---|---|
| **盲测真实率** | 生成图与真实老照片混排，请评审判断"哪张是 AI 生成的"；生成图被误判为真实照片的比例 | ≥ 60% |
| **面部相似度** | 生成图与源照片的人脸特征向量余弦相似度（ArcFace 类模型） | ≥ 0.55 |
| **年龄保真度** | 评审对生成图人物年龄的估计与源照片年龄的偏差 | ≤ 5 岁 |
| **AI 感投诉率** | 用户主动反馈"太假/不像真人/塑料感"的请求占比 | ≤ 5% |
| **年代一致性** | 评审判断"这张像是那个年代拍的"的通过率 | ≥ 70% |
| **年代穿帮率** | 生成图中出现该年代之后物件的比例（见 §12） | ≤ 3% |

> 盲测样本集：至少 30 组源照片 + 生成结果，评审 ≥ 5 人，且包含逝者家属本人。

## 3. 核心使用流程

```
上传老照片  →  ① 修复增强  →  ② 选择【年代 + 场景】→ ③ 写实生成  →  ④ 导出/保存
                  │                    │                        │
                  │                    │                        └─ （可选）多人全家福融合
                  │                    └─ 系统自动匹配该组合的质感包与空间包
                  └─ （可选）反推提示词，自动推荐年代与场景
```

1. 用户上传 1–5 张老照片（自动做清晰度评分，提示哪张更适合作为基准）；
2. 系统修复增强，用户确认"这就是他"（**强制确认节点**，避免后续全盘错误）；
3. 用户选择 **年代**（50–70 / 80–90 / 00 / 10–20 年代）与 **场景**（老式照相馆 / 农村院子 / 城市公园 / 家庭客厅 / 工作单位门口），也可自定义描述；
4. 系统按 §5 矩阵自动拼装该组合的写实 prompt，并把修复图作为**参考图**传入，生成 2–4 张候选图（可重复生成，保留历史）；
5. 用户挑选、下载；如需全家福，追加家人照片做融合。

## 4. 功能需求

> 原则：**功能少而深**。以下 5 项为核心，务必保证 `F1 修复 → F2 场景生成` 这条主链路完全跑通。

### F1 · 模糊照片修复与增强（前置核心）

| 项 | 内容 |
|---|---|
| 优先级 | P0（主链路起点，不做则后面全废） |
| 描述 | 对单张模糊/破损/褪色老照片做修复：对比度与动态范围提升、去噪去划痕、面部细节还原、分辨率提升 |
| 输入 | 原图（jpg/png/heic，建议 ≥ 500×500） |
| 输出 | 修复图 + 质量评分（清晰度、人脸可检出、破损程度） |
| 关键规则 | ① **不改变人物身份**，只提清晰度；② 不做美颜、不磨皮、不改变脸型；③ 过度破损时明确告知"该照片修复效果有限，建议换一张"，而非硬修 |
| 验收 | 修复后清晰度显著提升；人脸可稳定检出；家属确认"是本人"；画面**仍然保留年代质感**，不出现"修复后变得像新照片" |

### F2 · 多场景人物生成（主功能）

| 项 | 内容 |
|---|---|
| 优先级 | P0（产品核心价值） |
| 描述 | 以 F1 修复后的面部特征为身份锚点，生成该人物在**指定年代 × 指定场景**下的真实照片（详见 §5） |
| 输入 | 修复图（作为参考图传入模型）+ **年代（E1–E4）** + **场景（S1–S5 或自定义）** + 生成张数 |
| 输出 | 2–4 张候选图（含 seed、年代/场景代号、prompt 版本，可复现） |
| 关键规则 | ① 身份一致性：**不同场景之间必须是同一个人**，年龄设定与源照片一致；② **用户只选年代与场景，不直接编辑底层 prompt**；系统按 §5 矩阵自动拼装质感包与空间包（高级用户可选开放编辑）；③ 光影需贴合环境，且符合所选年代的典型照明；④ 年代穿帮校验：画面中不得出现该年代之后才有的物件（见 §12）；⑤ **年龄保真**：不得把老人磨年轻（见 §5.7）；⑥ 默认**不加可见水印**（合规标识见 §8.3） |
| 验收 | 盲测真实率 ≥ 60%；跨场景身份一致；**年龄保真度 ≤ 5 岁**；年代一致性 ≥ 70%；无年代穿帮；通过 §2.3 红线检查 |

#### F2.1 年代与场景的选择交互

- **双轴选择器**：先选年代（四个大卡片，带该年代的样片风格缩略与一句话说明），再选场景（五个卡片 + "自己描述"入口）；
- **实时样片预览**：每个年代卡片展示同一个人物在该年代的示例效果，帮助不懂摄影的用户理解"年代感"到底指什么；
- **低置信组合提示**：当年代与场景组合较少见时（如 00 年代 + 农村院子），不阻止生成，但提示"这个组合比较少见，效果可能不如常见组合自然"（组合常见度见 §5.5 与 §9 的 `confidence` 字段）；
- **一键复现**：历史记录中保留年代 + 场景组合，可"用同样的设定再生成一组"。

### F3 · 多人场景融合（全家福）

| 项 | 内容 |
|---|---|
| 优先级 | P1（高情感价值，但依赖 F1/F2 稳定后再做） |
| 描述 | 将 F2 生成的目标人物，与用户提供的家人现有照片自然合成为一张全景照 |
| 输入 | 目标人物（修复图/生成图）+ 1–4 张家人照片 + 年代 + 场景预设 |
| 输出 | 1–3 张全景全家福 |
| 关键规则 | ① **光影统一**：所有人物共享同一光源方向、色温、阴影强度；② **质感统一**：边缘、噪点、颗粒、清晰度一致，避免"一个人是高清、另一个人是糊的"；③ **比例与透视正确**：身高、站位、远近关系合理；④ **年代统一**：所有人物的服装与画面陈设同属所选年代；⑤ 不强行合成姿势明显冲突的照片 |
| 验收 | 评审无法指出"哪个人是后期贴上去的"；光影/质感/年代一致性通过；人物身份均可辨认 |
| 失败兜底 | 合成质量不达标时不交付，明确告知原因，而不是给一张违和的图 |

### F4 · 图片反推提示词（辅助）

| 项 | 内容 |
|---|---|
| 优先级 | P2（提升可控性，不阻塞主链路） |
| 描述 | 用户上传一张（可以是模糊的）老照片，AI 分析其场景、光线、年代、人物着装，输出一段可编辑的细节描述词，供 F2 复用 |
| 输入 | 任意照片 |
| 输出 | 结构化描述（场景 / 光线 / 年代 / 服饰 / 构图）+ 一段自然语言提示词 + **推荐的年代与场景代号** |
| 用途 | ① 用户想让新照片"跟这张感觉一样"；② 降低用户自己写 prompt 的门槛；③ **自动把用户的老照片归入 E1–E4 与 S1–S5，用户直接采纳即可** |

### F5 · 极简账号与历史记录

| 项 | 内容 |
|---|---|
| 优先级 | P0（必须，但保持极简） |
| 描述 | 手机号/邮箱验证码登录（一键登录亦可）；查看历史记录 |
| 登录 | 不做复杂注册流程、不做密码、不做社交绑定 |
| 历史记录 | 按时间倒序列出「原图 → 修复图 → 生成图」的完整链路，标注年代 × 场景，支持：继续生成、删除、下载 |
| 关键规则 | ① 用户可**随时彻底删除**任何照片及其衍生结果（含服务端原图）；② 删除后不可恢复，避免隐私残留 |

### F6 · 支撑能力（必要的细节，非独立功能）

| 能力 | 说明 |
|---|---|
| 身份确认节点 | F1 → F2 之间强制让用户确认面部，避免在错误基础上批量生成 |
| **身份锚点提取** | 用 §6.2 的多模态模型读参考图，产出结构化的面部特征描述（`anchor` 文本），作为 prompt 的【身份锚点】段；与参考图一起使用，双保险 |
| 生成候选与重试 | 每次生成 2–4 张，可"再来一组"；重试记录保留，避免覆盖 |
| Prompt 版本管理 | 每个年代包 / 场景包 / 组合档案都有版本号，可回滚、可 A/B |
| 情感安全提示 | 首次进入时温和提示："我们会尽力还原照片的样子，但这是基于照片的重建，无法替代真实。" 全程不出现"复活""重生"等措辞 |
| 授权确认 | 生成前需用户勾选确认：对照片中人物拥有合法使用权、已获其他近亲属同意 |
| 内容安全审核 | 生成前后均做审核，拒绝违法与恶意用途（见 §12） |

## 5. 年代 × 场景 匹配矩阵（真实感匹配引擎）

> 本节是核心交互机制：**用户只做两个选择——「年代」和「场景」，系统负责保证这张照片"像是那个年代、那个地方真实拍出来的"。**

### 5.1 设计原理：两层正交组合

真实老照片的观感由两个彼此独立的维度决定，二者相乘而非相加：

| 层 | 由谁决定 | 决定什么 |
|---|---|---|
| **影像质感层** | **年代** | 色调、颗粒、动态范围、光比、器材痕迹（这是"看起来像老照片"的关键） |
| **空间光线层** | **场景** | 空间元素、光源方向与性质、构图方式、道具陈设 |

最终 prompt 由四段拼装而成：

```
最终 prompt = 身份锚点（F1 修复图特征 / F6 锚点提取）
            + 年代质感包（§5.2）
            + 场景空间包（§5.3）
            + 写实锚定词（§7.1）
            ± 组合微调片段（§5.4 矩阵）
```

这样设计的好处：**4 个年代 × 5 个场景 = 20 种组合**，只需维护 4 段质感包 + 5 段空间包（9 段文本），而不是 20 段独立 prompt；新增一个场景只需加一段空间包，即可自动获得全部 4 个年代的版本。

### 5.2 年代轴（Era Axis · 影像质感层）

| 代号 | 年代 | 影像母题 | 色调 | 颗粒 / 画质 | 动态范围与光比 | 器材特征 | 典型服装道具 |
|---|---|---|---|---|---|---|---|
| **E1** | 50–70 年代 | 黑白 / 泛黄胶片 | 黑白影调，仅极轻微泛黄，全画面无彩色 | 明显胶片颗粒、细小划痕与灰点、四角轻微暗角 | 高光易过曝，暗部压得很深，反差大 | 中画幅 / 双反相机，固定焦段，浅景深，人物居中端正 | 中山装、列宁装、工装、搪瓷缸、木家具、领袖像 |
| **E2** | 80–90 年代 | 彩色胶卷 | 偏青或偏暖红，色彩浓郁但不艳丽，有轻微偏色 | 明显彩色颗粒、轻微色染、边缘轻微色散 | 中等反差，闪光灯直打时高光轻微溢出 | 135 胶片机 / 傻瓜相机，变焦，直出 | 的确良衬衫、军绿色、运动服、二八大杠自行车、蕾丝桌布、挂历 |
| **E3** | 00 年代 | 早期数码相机 / 手机 | 略灰，白平衡偏冷或偏绿 | 数码噪点明显、低动态范围、轻微紫边 | 反差偏高，闪光灯压脸，高光明显溢出 | 卡片机 / 早期手机，直出 JPEG，锐化略过度 | 运动服、塑料椅、瓷砖地、挂历、饮水机 |
| **E4** | 2010–2020 年代 | 智能手机 | 白平衡基本准确但不完美，色彩自然略显平淡，不做浓艳调色 | 画面通透、细节清晰，带手机算法轻微的降噪与锐化痕迹 | 动态范围较高，天空高光轻微溢出，暗部保留细节 | 手机主摄，自动模式，随手拍，构图随意 | 现代休闲装、运动鞋、塑料椅、共享单车、现代家电 |

> 每个年代包还带有**默认参数**：E1 为黑白、建议 1:1 或 3:4 画幅；E2 / E3 / E4 为彩色、建议 3:4 或 4:3。

### 5.3 场景轴（Scene Axis · 空间光线层）

> 场景定义为**跨年代的中性空间**，同一场景在不同年代的具体差异由 §5.4 矩阵单元格承担。例如"城市公园"在 E1 是荒草土路，在 E4 是草坪步道与远处高楼。

| 代号 | 场景 | 空间元素 | 光源 | 构图 / 视角 | 典型道具 |
|---|---|---|---|---|---|
| **S1** | 老式照相馆 | 布景幕布、木质背景板、铁艺椅、假花 | 影棚顶灯 + 相机直闪，硬光 | 正面半身、居中、略显拘谨的摆拍 | 假花、木质相框、布幕 |
| **S2** | 农村院子 | 土墙、木门、柴垛、水缸 | 自然日光 / 阴天散射 | 平视，人物略偏画面一侧 | 石磨、竹筐、晾衣绳 |
| **S3** | 城市公园 | 草坪与河道/湖面、成排树木、长椅、步道与栏杆 | 自然日光或阴天散射 | 日常拍摄视角，人物与环境自然融合 | 长椅、自行车、冰棍、公园门票 |
| **S4** | 家庭客厅 | 沙发、五斗柜、电视柜、墙上挂历 | 室内灯 / 窗光 | 生活抓拍视角 | 搪瓷杯、暖水瓶、电视机 |
| **S5** | 工作单位门口 | 单位大门、标语墙、传达室 | 日光 / 逆光 | 站姿合影 | 自行车、公文包、军绿挎包 |

### 5.4 组合矩阵（20 组关键视觉特征）

> 读法：行 = 场景，列 = 年代。单元格是该组合**最需要被还原的视觉特征**，也是验收时的检查点。

| 场景 ＼ 年代 | **E1 · 50–70** | **E2 · 80–90** | **E3 · 00** | **E4 · 10–20** |
|---|---|---|---|---|
| **S1 老式照相馆** | 黑白硬闪光，布幕背景，高光过曝，人物居中端正，"证件式"合影 | 彩色胶卷，影楼布景 + 假花，闪光灯直打，色彩偏红，布幕质感明显 | 早期数码，白平衡偏灰，直闪压脸，布景已显廉价 | 照相馆已少见；若拍摄则为手机随手拍，室内混合光、白平衡偏黄，背景略显杂乱 |
| **S2 农村院子** | 黑白，土墙高反差，日光硬阴影，颗粒粗 | 彩色胶卷，土墙泛青，日光柔和，色彩浓郁 | 数码感，土墙偏灰，动态范围低，天空易死白 | 手机拍摄，院子已有水泥地/瓷砖，色彩自然、细节清晰，天光平淡 |
| **S3 城市公园** | 黑白，树影反差强，湖面高光过曝 | 彩色胶卷，树叶偏青绿，阳光斑驳，颗粒明显 | 数码噪点，树影发灰，色彩平淡，边缘紫边 | 手机随手拍，阴天漫射光，草坪与步道细节清晰，远处现代楼宇，天空高光轻微溢出 |
| **S4 家庭客厅** | 黑白，室内灯光昏暗，暗部死黑，窗光成高光 | 彩色胶卷，钨丝灯偏黄，闪光灯反光，色彩饱和 | 数码闪光灯压脸，白平衡偏绿，瓷砖/家具反光 | 手机拍摄，LED 吸顶灯，白平衡基本准确，室内通透，现代家电自然入镜 |
| **S5 工作单位门口** | 黑白，标语墙与大门，日光逆光，人脸偏暗 | 彩色胶卷，单位门头红字，日光平直，色彩偏红 | 数码，门头褪色，白平衡偏冷，天空过曝 | 手机拍摄，门头已翻新或搬迁，日光平淡，背景可能有现代车辆 |

### 5.5 组合规则与校验

1. **正交组合**：年代与场景独立取值，矩阵单元格仅用于**微调**（`prompt_override`），为空时直接用两层拼装结果；
2. **年代一致性硬校验**：场景中出现的服饰、发型、建筑、家具、道具，必须属于所选年代或**更早**。生成前置入年代约束，生成后做一次物件复核（可复用 F4 的视觉理解能力）；
3. **典型穿帮黑名单**：
   - **E1**：任何彩色元素、塑料日用品、家电、现代印刷品；
   - **E2**：智能手机、液晶屏、现代楼宇玻璃幕墙、现代汽车外观；
   - **E3**：全面屏手机、电动车、现代装修风格；
   - **E4**：无实质黑名单（已是最新年代），但不得出现明显未来感或科幻元素；
4. **组合常见度（confidence）**：矩阵每个组合带 0–1 的常见度权重，低于阈值时界面给出温和提示（不阻止）；
5. **候选策略**：同一组合一次生成 2–4 张，供用户挑选；
6. **禁止跨年代混搭**：不允许"E1 的质感 + E3 的道具"这类矛盾组合，界面上不提供该选项。

### 5.7 实测观察与已知风险（写实度）

在 E4 × S3 的实测中，参考图 + 年代场景包**显著优于裸 prompt**（画面质感、光线、场景可信度都更像真实手机照片），但仍观察到以下残留 AI 感，需在后续迭代中重点解决：

| 观察 | 说明 | 对策方向 |
|---|---|---|
| **年龄被"磨"年轻** | 模型倾向于把老人理想化，皱纹深度与老年斑密度下降，观感比源照片年轻 5–10 岁 | 在【身份锚点】中**显式声明"不要美化、不要减龄"**并写明皱纹/老年斑的具体位置与程度；把"年龄保真度"纳入 §2.4 验收 |
| **额头/面颊局部偏"抛光"** | 高频皮肤纹理在大面积平滑区域被抹平 | 强化"保留毛孔与皮肤纹理"权重；考虑加入局部纹理参考图 |
| **嘴部与牙齿最易失真** | 笑容时牙齿过于整齐均匀，唇形略僵 | 生成后复核；必要时提供"换一版表情" |
| **参考图构图被过度继承** | 第二张参考图是站姿全身照，输出构图与其高度相似 | 若需强烈改变构图，降低参考图权重或改用修复后的人像特写作为参考 |

> 以上均为**已实测**结论，不是推测。上线前必须用 §2.4 的盲测数据验证改善幅度。

### 5.8 与模型约束的关系（重要）

由于 `Doubao-Seedream-5.0-lite` **不支持 `negative_prompt`**（见 §6.1），"这个年代不该出现什么"无法通过负向词表达，必须全部转写为**正向的锚定描述**：

| 想禁止 | 转写为正向描述 |
|---|---|
| 不出现智能手机 | "画面中的通讯设备为 1980 年代常见的固定电话或不存在通讯设备" |
| 不出现现代建筑 | "背景建筑为 1980—1990 年代的砖混楼房，外墙为水泥或马赛克贴面" |
| 不出现彩色（E1） | "黑白照片，全画面无彩色，仅极轻微泛黄" |
| 不要把老人磨年轻 | "保留已有的深皱纹、老年斑与皮肤松弛，不做任何美化与减龄" |

## 7. Prompt 工程规范（真实感的核心实现手段）

由于 lite 不支持负向提示词，采用 **「正向写实锚定 + 反向特征的正面化表达」** 策略：把"不要塑料感"改写成"保留毛孔与细纹"。

### 7.1 写实锚定词库（务必注入每一条 prompt）

```
真实照片，随手拍的生活照，摄影质感，
自然皮肤纹理，可见毛孔与细纹，真实肤色不均，
自然光/室内暖光，[年代专属颗粒与画质描述]，
轻微的对焦不实，构图自然不刻意，[年代]年的影像质感
```

> 注意：锚定词中的"胶片"字样**不应无脑注入所有年代**——E3/E4 属于数码/手机年代，写"胶片质感"会与年代包冲突。年代专属的质感描述以 §5.2 的年代包为准。

### 7.2 反 AI 感的正面化表达（对照表）

| 想禁止（AI 感） | 改写为正向描述 |
|---|---|
| 过度磨皮 | 保留皮肤真实纹理、毛孔、细纹、法令纹 |
| 塑料感/蜡像感 | 自然的皮肤光泽、轻微油光、真实的肤色过渡 |
| 3D 渲染感 | 写真摄影质感、纪实摄影 |
| 过度锐化/HDR | 柔和的对比度、略低的动态范围、轻微失焦 |
| 影楼摆拍 | 随意的生活抓拍、不完美的构图 |
| 现代感穿帮 | 与照片年代一致的服饰与陈设、老式家具 |
| **把老人磨年轻** | 保留已有的深皱纹、老年斑与皮肤松弛，不做美化与减龄 |

### 7.3 Prompt 模板

```
【身份锚点】严格保持参考图中人物的面部特征与身份一致，不同场景之间必须是同一个人：<特征描述>
【年代】<年代质感包 · 见 §5.2>
【场景】<场景空间包 · 见 §5.3>
【质感】真实照片，随手拍的生活照，自然皮肤纹理，可见毛孔与细纹，
        真实肤色不均，柔和的对比度，构图自然不刻意
【年代一致】画面中的服饰、发型、建筑、陈设与道具必须属于 <年代> 或更早
```

> 模板固定，变量只有三段：`身份锚点`（来自 F1 或 §6.2 提取）、`年代质感包`、`场景空间包`。这样 prompt 可版本化管理、可 A/B。

### 7.4 验证机制

每条 prompt 模板上线前，须通过 §2.4 的盲测；不通过的模板进入优化队列，禁止直接上线。年代包 / 场景包 / 组合档案均独立编号版本。

## 8. 界面与交互设计

### 8.1 设计基调：简洁、温情

| 维度 | 规范 |
|---|---|
| 色彩 | 以暖白、米杏、浅木色为底；主色用柔和的暖棕/暖橙；忌高饱和、忌冷科技蓝紫 |
| 字体 | 中文衬线/类衬线用于标题（有信笺感），无衬线用于正文，字重偏细 |
| 留白 | 大留白，一屏一重点，不做信息堆叠 |
| 动效 | 极克制，避免炫技式转场；以淡入为主 |
| 文案语气 | 第二人称、平实、不说教、不煽情。例：*"我们先把这张照片修清楚一点。"* |
| 禁忌 | ✗ 殡葬色系（大面积黑/白）、✗ "复活""重生""让ta回来"、✗ 倒计时压迫感、✗ 夸张的成功提示 |

### 8.2 关键页面

| 页面 | 说明 |
|---|---|
| 首页 | 一句话说明 + 上传按钮，仅此而已 |
| 上传与评分 | 提示哪张更适合作为基准；不达标时给替代建议 |
| 修复确认页 | 左右对比原图/修复图，**"这就是他"** 确认按钮（强制） |
| **年代选择** | 四个大卡片（50–70 / 80–90 / 00 / 10–20 年代），每张配该年代样片与一句人话说明，如"黑白照，稍微泛黄，像老一辈的相片" |
| **场景选择** | 五个卡片（老式照相馆 / 农村院子 / 城市公园 / 家庭客厅 / 工作单位门口）+ "自己描述"入口；选择后实时预览"年代 × 场景"的组合样片 |
| 生成结果页 | 网格展示候选，标注年代 × 场景，支持放大、重生成、下载 |
| 全家福页 | 上传家人照片 → 选择年代与场景 → 合成 → 结果确认 |
| 历史记录 | 按链路展示，标注年代 × 场景，支持"用同样设定再生成"、删除 |

### 8.3 合规标识

- 依据《人工智能生成合成内容标识办法》：**隐式标识（元数据）必须写入**，由平台侧实现；
- 可见标识：默认关闭以保真实感，但**必须提供开关**并保留服务端标识记录；
- 分享到外部平台时，按目标平台要求自动补充可见标识。

## 9. 数据库表结构（基础）

> 以下为 MVP 基础模型，字段以 PostgreSQL 风格表述，实现时按团队技术栈调整。

```sql
-- 用户
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  phone         VARCHAR(20) UNIQUE,
  email         VARCHAR(128) UNIQUE,
  nickname      VARCHAR(64),
  status        SMALLINT   NOT NULL DEFAULT 1,   -- 1 正常 0 禁用
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_login_at TIMESTAMPTZ
);

-- 照片资产（原图 / 修复图 / 生成图 / 家人参考图 统一存放）
CREATE TABLE photos (
  id            BIGSERIAL PRIMARY KEY,
  user_id       BIGINT NOT NULL REFERENCES users(id),
  kind          VARCHAR(16) NOT NULL,   -- original|restored|generated|family_ref
  file_key      TEXT NOT NULL,          -- 对象存储 key，不存公网 URL
  width         INT,
  height        INT,
  sha256        CHAR(64),               -- 去重
  quality_score NUMERIC(4,3),           -- 清晰度/可用性评分
  deleted_at    TIMESTAMPTZ,            -- 软删除，便于彻底清理
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_photos_user ON photos(user_id, created_at DESC);

-- 修复任务（F1）
CREATE TABLE restore_jobs (
  id              BIGSERIAL PRIMARY KEY,
  user_id         BIGINT NOT NULL REFERENCES users(id),
  source_photo_id BIGINT NOT NULL REFERENCES photos(id),
  result_photo_id BIGINT REFERENCES photos(id),
  status          VARCHAR(16) NOT NULL,  -- pending|running|succeeded|failed
  params_json     JSONB,
  error_message   TEXT,
  created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at     TIMESTAMPTZ
);

-- ★ 年代预设（影像质感层 · §5.2）
CREATE TABLE eras (
  code          VARCHAR(8)  PRIMARY KEY,          -- E1 | E2 | E3 | E4
  name          VARCHAR(32) NOT NULL,             -- 80-90年代
  slug          VARCHAR(32) NOT NULL,             -- 1980s-1990s
  is_mono       BOOLEAN     NOT NULL DEFAULT false,
  default_size  VARCHAR(16) NOT NULL DEFAULT '2048x2048',
  style_json    JSONB       NOT NULL,             -- 色调/颗粒/动态范围/器材 结构化参数
  prompt_pack   TEXT        NOT NULL,             -- 质感层 prompt 片段
  pack_version  VARCHAR(16) NOT NULL DEFAULT 'v1',-- 便于 A/B 与回滚
  is_active     BOOLEAN     NOT NULL DEFAULT true,
  sort_order    INT         NOT NULL DEFAULT 0
);

-- ★ 场景预设（空间光线层 · §5.3，跨年代中性）
CREATE TABLE scene_presets (
  id              BIGSERIAL PRIMARY KEY,
  code            VARCHAR(8)  NOT NULL UNIQUE,    -- S1..S5
  name            VARCHAR(64) NOT NULL,           -- 城市公园
  slug            VARCHAR(32) NOT NULL,           -- city-park
  category        VARCHAR(32),                    -- studio|indoor|outdoor|workplace
  space_pack      TEXT        NOT NULL,           -- 空间/光源/构图 prompt 片段
  pack_version    VARCHAR(16) NOT NULL DEFAULT 'v1',
  cover_photo_id  BIGINT      REFERENCES photos(id),
  is_active       BOOLEAN     NOT NULL DEFAULT true,
  sort_order      INT         NOT NULL DEFAULT 0
);

-- ★ 年代 × 场景 组合档案（矩阵 · §5.4）
CREATE TABLE era_scene_profiles (
  id               BIGSERIAL PRIMARY KEY,
  era_code         VARCHAR(8)  NOT NULL REFERENCES eras(code),
  scene_id         BIGINT      NOT NULL REFERENCES scene_presets(id),
  visual_signature TEXT,                            -- 该组合的关键视觉特征（后台可读）
  prompt_override  TEXT,                            -- 组合级微调，为空则用两层拼装
  confidence       NUMERIC(3,2) NOT NULL DEFAULT 1.0, -- 组合常见度，低值触发界面提示
  is_active        BOOLEAN     NOT NULL DEFAULT true,
  UNIQUE (era_code, scene_id)
);

-- ★ 身份锚点（§6.2 面部特征提取结果，与基准照片绑定）
CREATE TABLE identity_anchors (
  id             BIGSERIAL PRIMARY KEY,
  user_id        BIGINT NOT NULL REFERENCES users(id),
  source_photos  JSONB  NOT NULL,           -- 参与提取的 photos.id 数组
  anchor_text    TEXT   NOT NULL,           -- 可直接注入 prompt 的一句话锚点
  features_json  JSONB  NOT NULL,           -- 结构化面部特征
  model          VARCHAR(64) NOT NULL,      -- doubao-seed-2-1-turbo-260628
  confirmed_by_user BOOLEAN NOT NULL DEFAULT false, -- 用户是否确认"这就是他"
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 生成任务（F2 场景生成 / F3 全家福融合）
CREATE TABLE generation_jobs (
  id                 BIGSERIAL PRIMARY KEY,
  user_id            BIGINT NOT NULL REFERENCES users(id),
  type               VARCHAR(16) NOT NULL,  -- scene | family_fusion
  source_photo_id    BIGINT REFERENCES photos(id),        -- 修复后的基准图
  family_ref_ids     JSONB,                 -- 家人参考照片 id 数组
  identity_anchor_id BIGINT REFERENCES identity_anchors(id), -- ★ 身份锚点
  era_code           VARCHAR(8) REFERENCES eras(code),    -- ★ 年代轴
  scene_preset_id    BIGINT REFERENCES scene_presets(id), -- ★ 场景轴
  match_profile_id   BIGINT REFERENCES era_scene_profiles(id), -- ★ 命中的组合档案
  reference_photo_ids JSONB,                -- ★ 实际传给模型的参考图 photos.id
  prompt             TEXT NOT NULL,         -- 实际拼装出的最终 prompt
  model              VARCHAR(64) NOT NULL,  -- doubao-seedream-5-0-lite-260128
  params_json        JSONB,                 -- size/output_format/...
  status             VARCHAR(16) NOT NULL,
  error_message      TEXT,
  created_at         TIMESTAMPTZ NOT NULL DEFAULT now(),
  finished_at        TIMESTAMPTZ
);
CREATE INDEX idx_gen_jobs_user ON generation_jobs(user_id, created_at DESC);
CREATE INDEX idx_gen_jobs_era_scene ON generation_jobs(era_code, scene_preset_id);

-- 生成结果（一个任务可产出多张候选）
CREATE TABLE generation_results (
  id            BIGSERIAL PRIMARY KEY,
  job_id        BIGINT NOT NULL REFERENCES generation_jobs(id),
  photo_id      BIGINT NOT NULL REFERENCES photos(id),
  seed          BIGINT,
  realism_score NUMERIC(4,3),            -- 自动真实感打分（可选）
  age_delta     SMALLINT,                -- ★ 自动估计的年龄偏差（岁）
  era_check     JSONB,                   -- ★ 年代穿帮复核结果
  user_feedback SMALLINT,                -- 1 喜欢 / -1 不喜欢 / NULL 未表态
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 反推提示词任务（F4）
CREATE TABLE prompt_reverse_jobs (
  id                  BIGSERIAL PRIMARY KEY,
  user_id             BIGINT NOT NULL REFERENCES users(id),
  source_photo_id     BIGINT NOT NULL REFERENCES photos(id),
  model               VARCHAR(64) NOT NULL,  -- doubao-seed-2-1-turbo-260628
  result_json         JSONB,                 -- 结构化场景描述
  result_prompt       TEXT,                  -- 自然语言提示词
  suggest_era_code    VARCHAR(8),            -- ★ 推荐年代
  suggest_scene_id    BIGINT,                -- ★ 推荐场景
  status              VARCHAR(16) NOT NULL,
  created_at          TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 授权与合规记录
CREATE TABLE consents (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT NOT NULL REFERENCES users(id),
  scope      VARCHAR(32) NOT NULL,       -- photo_usage | family_agreement
  agreed_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  revoked_at TIMESTAMPTZ
);

-- 操作审计
CREATE TABLE audit_logs (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT,
  action     VARCHAR(64) NOT NULL,
  target     VARCHAR(128),
  meta_json  JSONB,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

**设计要点**

- 照片只存对象存储 `file_key`，**不落公网 URL**；下载走短时签名；
- `deleted_at` 软删除 + 定时物理清理任务，满足"彻底删除"承诺；
- `generation_jobs` 保留完整参数（含 seed、参考图 id、锚点 id、年代/场景），保证结果可复现；
- **年代与场景拆成两张主表 + 一张组合表**（`eras` / `scene_presets` / `era_scene_profiles`），新增年代或场景只需插数据，不改代码；
- `identity_anchors` 独立成表并保留 `confirmed_by_user`，与 §4 F6 的"身份确认节点"对应；
- `pack_version` 支持 prompt 包灰度与回滚；`confidence` 驱动界面上的"该组合较少见"提示；
- 修复与生成拆成两张任务表，便于分别重试与计费统计。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单张修复 ≤ 30s；单次场景生成（2–4 张）≤ 60s；接口异步化 + 轮询/推送 |
| 成本 | 生图调用按张计费，单用户单次生成上限 4 张，防止滥用；提供每日额度 |
| 隐私 | 照片加密存储、传输 HTTPS、访问最小权限；**承诺不用于模型训练**；支持一键彻底删除 |
| 可用性 | 生成失败需明确提示并自动重试 1 次；不出现"白屏无反馈" |
| 兼容 | 移动端优先，支持 jpg/png/heic 上传 |
| 配置化 | 年代包 / 场景包 / 组合档案全部后台可配，新增年代或场景无需发版 |

## 11. MVP 范围与里程碑

**MVP 只做一条链路：`上传 → F1 修复 → 身份确认 → 选【年代 + 场景】→ F2 写实生成 → 下载`**

| 阶段 | 内容 | 目标 |
|---|---|---|
| M1 | F1 修复 + 身份确认 + 身份锚点提取；打通 Seedream 调用 | 「修复 + 写实生成」可跑通 |
| M2 | **年代 × 场景 匹配矩阵（§5）+ F2 多场景生成 + prompt 模板 + 盲测验证** | 盲测真实率 ≥ 60%，年代一致性 ≥ 70%，年龄保真度 ≤ 5 岁 |
| M3 | F5 账号与历史记录 | 可完整走完一次真实用户流程 |
| M4 | F3 全家福融合（含年代/场景统一） | 光影/质感/年代一致性达标 |
| M5 | F4 反推提示词（含年代/场景推荐） | 提升可控性 |

> **M2 前置交付物**：`.scratch/seedream_era_scene.js`（年代×场景 prompt 拼装与生成）与 `.scratch/extract_face_features.js`（面部特征提取），用于实测设定是否确实提升老照片真实感。

> **明确不做（MVP）**：视频生成、语音合成、数字人对话、"让照片动起来"。这些方向与"真实照片"的定位冲突，且极易造成心理伤害与合规风险。

## 12. 风险与合规

| 风险 | 说明 | 对策 |
|---|---|---|
| **深度伪造滥用** | 生成的真人影像可能被用于诈骗、造谣 | 强制实名登录、生成前授权确认、隐式+可选可见标识、异常调用风控 |
| **肖像权/近亲属纠纷** | 逝者肖像涉及其他继承人 | 生成前勾选确认条款；提供侵权投诉与下架通道 |
| **情感伤害** | 过度拟真或"复活"话术造成二次创伤 | 禁用"复活/重生"措辞；不做视频与语音；提供温和的使用说明 |
| **年代穿帮** | 生成图出现该年代之后才有的物件，破坏真实感 | 年代包内置正向约束 + 黑名单（§5.5）；生成后用多模态模型复核（§6.2）；纳入验收指标（§2.4） |
| **年龄被磨年轻** | 模型倾向美化，抹平皱纹与老年斑，家属一眼看出"不是他那个样子" | 锚点中显式声明皱纹/老年斑；把"年龄保真度"纳入验收（§2.4 与 §5.7） |
| **年代刻板化** | 过度堆砌年代符号，做出"年代主题cosplay"而非真实生活照 | 年代元素以"背景自然出现"为原则，禁止成为画面主体；A/B 时优先选更朴素的一版 |
| **效果不达预期** | 源照片过差导致生成失真 | 前置质量评分 + 明确告知 + 建议更换源图，不硬修 |
| **AI 感无法达标** | 真实感是硬指标，可能反复调优 | 建立盲测机制作为上线闸门；prompt 模板版本化管理 |
| **成本失控** | 生图按张计费 | 每用户每日额度 + 单次张数上限 |

## 附录 · 术语

| 术语 | 含义 |
|---|---|
| 身份锚点 | 用于保证跨图一致的人物面部特征约束；可由 §6.2 的多模态模型从参考照片提取 |
| 参考图 | 传给生图模型的照片资产（`image` 参数），是身份一致性的主要承载方式 |
| 盲测真实率 | 生成图被误判为真实照片的比例，本项目核心质量指标 |
| 年龄保真度 | 生成图人物年龄与源照片年龄的偏差，防止"把老人磨年轻" |
| 年代感 | 色调、颗粒、清晰度等符合特定年代影像特征的视觉属性 |
| **年代包（Era Pack）** | 由"年代"维度决定的影像质感 prompt 片段，共 4 个（E1–E4），见 §5.2 |
| **场景包（Scene Pack）** | 由"场景"维度决定的跨年代中性空间光线 prompt 片段，共 5 个（S1–S5），见 §5.3 |
| **匹配矩阵** | 年代 × 场景的 20 组组合档案，含关键视觉特征与微调片段，见 §5.4 |
| **年代穿帮** | 画面中出现所选年代之后才存在的物件或视觉元素 |
| 反 AI 感 | 消除塑料感、过度磨皮等典型生成痕迹的整体要求 |
| 写实锚定词 | prompt 中用于强制真实质感的固定词组（见 §7.1） |
