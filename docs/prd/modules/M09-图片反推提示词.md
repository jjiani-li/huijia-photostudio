> 一句话职责：F4 是**旁路**：从 `spec/00-总纲.md` §3 核心链路的第 ⑤ 步进入。它读一张（可以是模糊的）旧照片，给出「结构化场景描述 + 一段自然语言提示词 + 推荐的年代与场景」，让用户直接采纳，从而表达「让新照片跟这张感觉一样」。

## 1. 职责与边界

**做**

1. 复用 `modules/M03-身份锚点提取.md` 的多模态读图通路（`POST {ARK_BASE_URL}/chat/completions` + `content` 数组里的 `image_url`，已实测可用），读**一张**照片；
2. 产出 `result_json`（五键结构化描述）、`result_prompt`（自然语言提示词）、`suggest_era_code` / `suggest_scene_id`（推荐年代与场景），逐项对应 `spec/05-Prompt工程.md` §11 的输出契约；
3. 提供反推用的 system prompt 文本资产，覆盖场景 / 光线 / 年代 / 服饰 / 构图五段，并强制「只输出可解析的结构化结果」；
4. worker 内执行一次异步任务并落 `prompt_reverse_jobs`（`spec/01-领域模型与数据库.md` §3.15）；提供 `POST` / `GET` 两个端点（`spec/03-接口契约.md` §3.8）。

**不做**

- **不写入 `identity_anchors`**：这不是锚点提取，读图结果**不得**被当作身份锚点使用；
- **不产出任何图片**：本环节只「读」不「画」，生图见 `modules/M06-生成编排.md`；
- **不绕过 `buildPrompt`**：用户采纳推荐后，仍走 `spec/05-Prompt工程.md` §2 的拼装函数，反推结果只是选择年代与场景的辅助输入；
- **反推结果不得直接用于生图**：生图必须以用户已确认的锚点为前提（`spec/00-总纲.md` §3 的 ③④ 强制确认节点）；
- **不进入历史记录**：`GET /api/history` 只按 `identity_anchors` 组织，反推任务不出现在其中（`modules/M08-账号历史与彻底删除.md`）；
- **不占生成额度**：不写 `usage_counters.images`（`spec/03-接口契约.md` §3.8）。

## 3. 数据读写

只读写两张表：`prompt_reverse_jobs`（读写，见 `spec/01-领域模型与数据库.md` §3.15）与 `photos`（只读，`spec/02-schema.sql`），不触碰 `identity_anchors`。

**读**：`SELECT id, user_id, kind, storage_key, mime, bytes, deleted_at FROM photos WHERE id = ? AND deleted_at IS NULL`（校验入队与取读图来源）。

**写（`prompt_reverse_jobs`）**

| 时刻 | 操作 |
|---|---|
| 入队 | `INSERT INTO prompt_reverse_jobs(user_id, source_photo_id, model, status, created_at) VALUES(?, ?, ?, 'queued', ?)`（`model` 由服务层传入 `ARK_VISION_MODEL` 的当前值，**不内联字面量**） |
| claim | `UPDATE prompt_reverse_jobs SET status='running', started_at=? WHERE id=? AND status='queued'`（`changes = 0` 即放弃本次 claim） |
| 成功 | `UPDATE prompt_reverse_jobs SET status='succeeded', result_json=?, result_prompt=?, suggest_era_code=?, suggest_scene_id=?, finished_at=? WHERE id=? AND status='running'`（`status='running'` 是竞态守卫：超时兜底先落终态时不覆盖） |
| 失败 | `UPDATE prompt_reverse_jobs SET status='failed', error_code=?, error_message=?, finished_at=? WHERE id=?`；可自动重试的瞬时错误先置回 `queued` 并 `attempt + 1`（规则见 `spec/04-技术基线与目录结构.md` §4.6，本模块不复述） |

约束（`spec/01-领域模型与数据库.md` §2.4）：`succeeded` 时 `result_json` 与 `result_prompt` 必须非空；`failed` 时 **`error_code` 与 `error_message` 都必须非空**——`PromptReverseJob.error.code`（`spec/03-接口契约.md` §4）就取自 `error_code` 列。超时判定与回收读 `started_at`、自动重试读并自增 `attempt`，两者的阈值与规则一律按 `spec/03-接口契约.md` §2.2，不在本模块另设常数。**重复反推 = 插入新行**，不覆盖旧行。

## 4. 对外接口

不新增端点，全部见 `spec/03-接口契约.md` §3.8；字段名与形状以该 §3.8 与 §4 的 `PromptReverseJob` 为准，本文件不重复定义。

- `POST /api/prompt-reverse-jobs` → `202 { job }`（`status: 'queued'`）；请求 `{ photoId }`，照片可为 `original` 或 `preprocessed`；
- `GET /api/prompt-reverse-jobs/:id` → `200 { job }`；非终态时 `resultJson` / `resultPrompt` / `suggestEraCode` / `suggestSceneId` 为 `null`，`status='failed'` 时 `error = { code, message }`。

## 5. 关键流程与状态机

```
queued ──claim──▶ running ──┬──▶ succeeded（result_json / result_prompt 非空）
                            └──▶ failed（error_message 非空）
```

超时与回收沿用 `spec/03-接口契约.md` §2.2：worker 启动时把 `status='running'` 且启动超过 `WORKER_STALE_MINUTES`（默认 10 分钟）的任务回退为 `queued`；任务在 `running` 超过 `JOB_TIMEOUT_SECONDS`（默认 120s）按 `PROVIDER_TIMEOUT` 处理；仅对瞬时错误（`PROVIDER_TIMEOUT` / `PROVIDER_ERROR` / `STORAGE_ERROR`）自动重试 1 次。

### 5.1 模型与调用

| 项 | 值 |
|---|---|
| 模型 | `ARK_VISION_MODEL`（默认值以 `spec/08-本地开发指南.md` §4 为准），写入 `prompt_reverse_jobs.model` |
| 端点 | `POST {ARK_BASE_URL}/chat/completions`（`ARK_BASE_URL` 已含 `/api/v3`，只拼一次路径前缀） |
| 图像入参 | `content` 数组里的 `{ type: 'image_url', image_url: { url } }`；`url` 取**公网 URL 或 Base64 data URI**（`data:${mime};base64,...`，`mime` 取 `photos.mime` 落库值） |
| 超时 | 单次上游调用由 `ARK_TIMEOUT_SECONDS`（默认 120s）控制；整个任务由 `JOB_TIMEOUT_SECONDS` 控制；重试规则见上方状态机 |
| 取用 | **只取返回体的 `choices[0].message.content`**，**忽略 `reasoning_content`**（turbo 默认开启 thinking，会消耗 `reasoning_tokens`，见 `docs/火山引擎接口文档.md` §2.3、§3.1） |

messages 组装沿用 `modules/M03-身份锚点提取.md` §5.4 的规则：system 用字符串，user 用 `content` 数组且 **text 元素在图片之前**，本环节固定 1 张图。

### 5.2 `reverse-v1` system prompt 要求

存放于 `src/server/prompt/versions.ts`，导出名 `REVERSE_V1_SYSTEM_PROMPT`；业务代码里不得出现第二份副本。文本必须满足：

1. 覆盖**五段**，缺一不可：**场景**（地点与空间元素）、**光线**（方向 / 性质 / 色温）、**年代**（可判断的时期与影像特征）、**服饰**（服装、发型、配饰）、**构图**（机位、视角、景深层次）；
2. **只输出严格 JSON**，不使用 Markdown 代码块、不输出解释文字，键名与 `spec/05-Prompt工程.md` §11 完全一致；
3. 要求同时给出**推荐年代代号（`E1`–`E4`）与推荐场景 id（`scenes.id`）**，无法判断时输出 `null`，不得编造；
4. **禁止描述**「美化、减龄、换脸」类内容——不得出现磨皮、祛皱、去老年斑、显年轻、换脸 / 换人、改变性别或年龄等表述（与 `spec/05-Prompt工程.md` §4 的链路级防美化约束一致，红线见 `spec/00-总纲.md` §4.3）；
5. 只描述照片上**可视觉验证**的客观内容，不推测人物身份、性格、职业或人生经历。

### 5.3 输出与字段映射

输出契约的**权威定义**在 `spec/05-Prompt工程.md` §11（五键类型、`result_prompt`、`suggest_era_code`、`suggest_scene_id`），本文件不复制其字段表。任务表的字段映射如下：

| `prompt_reverse_jobs` 字段 | 来源 | 约束 |
|---|---|---|
| `result_json` | 模型返回的五键 JSON（`scene` / `lighting` / `era` / `wardrobe` / `composition`）序列化 | `succeeded` 时非空；五键必须全部出现且非空 |
| `result_prompt` | 模型返回的自然语言提示词全文 | `succeeded` 时非空 |
| `suggest_era_code` | 模型推荐的年代代号 | 取值 `E1`–`E4`，无法判断为 `NULL`（类型是**代号字符串**，指向 `eras.code`） |
| `suggest_scene_id` | 模型推荐的场景 id | 取值指向 `scenes.id`，无法判断为 `NULL`（类型是 **INTEGER**；`scenes.code`（`S1`–`S5`）不是这个字段的值域） |
| `model` | `ARK_VISION_MODEL` 的当前值 | NOT NULL |
| `status` / `error_code` / `error_message` / `created_at` / `started_at` / `finished_at` / `attempt` | 状态机、时间戳与重试记账 | 见 `spec/01-领域模型与数据库.md` §2.4、§3.15 |

采纳路径：前端在**上传页**采纳（`pages/P01-上传与身份确认.md` §4.4），推荐值随会话内存态带进年代与场景选择（`pages/P02-年代与场景选择.md` §7 的初值），用户确认后仍走 `spec/05-Prompt工程.md` §2 的 `buildPrompt` 拼装，再从 `spec/00-总纲.md` §3 的第 ⑤ 步进入链路。

### 5.4 容错解析与校验

按 `modules/M03-身份锚点提取.md` §5.5 的同一顺序执行：`stripFence → JSON.parse → zod 结构校验 → 长度与词表校验`。任一步失败即**按 `spec/04-技术基线与目录结构.md` §4.6 处置**（零产出的瞬时错误先回 `queued` 重试，规则不在本文件复述），词表命中与结构不合法最终都落到 `PROVIDER_ERROR`：

| 步骤 | 判据 | 失败 → 错误码 |
|---|---|---|
| 反序列化 | 剥 ```json 包裹后 `JSON.parse` 成功且为对象 | `PROVIDER_ERROR` |
| 结构校验 | `result_json` 恰含 5 个键且均为非空字符串；`result_prompt` 为非空字符串 | `PROVIDER_ERROR` |
| 推荐值域 | `suggest_era_code ∈ {E1,E2,E3,E4} ∪ {null}`；`suggest_scene_id ∈ scenes.id ∪ {null}` | 越界即置 `null`，**不**判失败（推荐是弱约束） |
| 词表拦截 | 任一字段不得命中减龄 / 美化 / 换脸词表（`spec/05-Prompt工程.md` §4 的黑名单语义） | `PROVIDER_ERROR` |

解析失败的模型原文写入 `logger.warn`，不进 `error_message`（避免把模型原文透给用户）。

## 6. 端到端流程

1. `POST /api/prompt-reverse-jobs` 入队（校验通过后写 `queued` 行，返回 `202`）；
2. worker 领取任务（claim 语义与原子性见 `spec/04-技术基线与目录结构.md` §4.6）；
3. 读图：取 `source_photo_id` 的文件与 `mime`，组装多模态请求（§5.1）；
4. 解析与校验（§5.4）；
5. 落库：写 `result_json` / `result_prompt` / `suggest_era_code` / `suggest_scene_id` / 终态（§3）；
6. `GET /api/prompt-reverse-jobs/:id` 轮询：间隔 1.5s、超时 90s，终止条件 `status ∈ {succeeded, failed}`（`spec/03-接口契约.md` §2.1）；
7. 前端展示与采纳：面板与采纳落在**上传页**（`pages/P01-上传与身份确认.md` §4.4），推荐值带进 `pages/P02-年代与场景选择.md` §7 的初值，用户一键采纳后走 `buildPrompt`（§5.3）。

## 7. 边界与错误

码、HTTP 状态与用户可见文案的唯一事实源是 `spec/03-接口契约.md` §5；本节只记**场景与触发**。

| 场景 | 触发 | 错误码 |
|---|---|---|
| 未登录 | handler 开头 `requireUser()` 失败 | `UNAUTHENTICATED` |
| 照片不存在 / 不属于当前用户 / 已软删除 | 读 `photos` 无行 | `NOT_FOUND`（不返回 403，避免探测） |
| 提交的是生成图 | `photos.kind='generated'` | `INVALID_PARAM`（防链式自举） |
| worker 心跳缺失 | `GET /api/health` 的 `worker.alive=false` | 端点仍返回 `202`，前端按 `spec/04-技术基线与目录结构.md` §4.6 的存活约定提示 `pnpm worker` |
| 上游超时 | 读图请求超过 `ARK_TIMEOUT_SECONDS` | `PROVIDER_TIMEOUT`（可重试） |
| 上游非 2xx / 返回体为空 / 解析失败 | `spec/03-接口契约.md` §5.1 的映射 | `PROVIDER_ERROR`（可重试） |
| 读 `storage_key` 文件失败 | 磁盘读写失败 | `STORAGE_ERROR`（可重试） |
| 源照片被内容审核拒绝 | `content_reviews` 判定拒绝 | `CONTENT_REJECTED` |
| `dataUri` 编码等我方问题 | 无对应上游错误 | `INTERNAL` |

上游错误到本项目错误码的完整映射见 `spec/03-接口契约.md` §5.1 与 `modules/M06-生成编排.md` §5.8（实现于 `src/server/ark/errors.ts`），本文件不重复。
