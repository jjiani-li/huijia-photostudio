用多模态模型读【预处理图】产出 `anchor_text` + 12 键 `features_json`，带状态机与质量快照落 `identity_anchors`；`POST /api/anchors`、`GET /api/anchors/:id`、`POST /api/anchors/:id/retry` 可用。

## 2. 不做（边界）
- 不做确认 / 授权 / 审计（归 `tickets/T07-身份确认、授权确认与审计.md`）：`app/api/anchors/[id]/route.ts` 的 `DELETE` 与 `confirm` 端点由 T07 追加。
- 不做通用 worker（三表拉取、心跳、回收、自动重试归 `tickets/T09`）；本条只在 `src/jobs/worker.ts` 补 `anchorExtract` 所需的最小拉取循环。

## 4. 实现要点
1. 落库与状态机严格按 `modules/M03-身份锚点提取.md` §3、§5.2：`succeeded` 时 `anchor_text` / `features_json` 非空，`failed` 时 `error_code` 非空；重提取 = 插新行，绝不覆盖旧行。
2. 容错解析按 §5.5 六步（剥包裹 → `JSON.parse` → zod 12 键 → 长度 [40,200] → 否定词拦截 → 美化词拦截），任一步失败落 `PROVIDER_ERROR`；prompt 文本只来自 `versions.ts`，业务代码不得内联第二份。
3. 质量前置判定按 §6.1（`usable=false`、无脸、`faceCount>1`、`readability<0.35`）→ `ANCHOR_LOW_QUALITY`，不浪费一次生成；handler 内部捕获全部异常，不得把 `AppError` 抛给 worker。
