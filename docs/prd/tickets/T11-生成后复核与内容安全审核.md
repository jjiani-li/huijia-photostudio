## 4. 实现要点
1. 审核在前、复核在后：内容审核判定（`moderationVerdict`）`reject` 要撤销本次全部产物，越早发现代价越小；复核失败只少一个标注，不得占用撤销路径（`modules/M07-生成后复核与内容审核.md` §5.1）。
2. 审核「失败」与内容审核判定（`moderationVerdict`）不同：审核是合规硬约束，**不放过未审核的结果**——超时 / 上游错误重试 1 次仍失败则任务 `failed`；复核失败留 `NULL` + `warn` 继续，是刻意的不对称。
3. `age_delta` 是有符号整数（负 = 变年轻），**不得取绝对值后上报**；`age_delta < 0` 单独 `warn` 并附 `eraCode` / `sceneId`；落库只保留 `EraCheck` 四键，`estimatedAgeRange` 消费后丢弃。
4. `review` 在三阶段都等同放行、仅留痕；`prompt` 阶段 `target_id` 用占位 `0` 并在 `reason` 前置 `prompt-stage`（见 §6 待定决策 2）。
