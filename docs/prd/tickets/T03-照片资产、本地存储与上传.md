## 1. 目标
用户上传的旧照片安全落本地磁盘并写进 `photos`，再以「只属于当前用户」的方式读回：`POST /api/photos`、`GET /api/photos/:id/file`、`DELETE /api/photos/:id` 三端点可用。

## 2. 不做（边界）
- 不做归一化 / 质量评分（归 `tickets/T04-预处理与质量评分.md`）；不写隐式标识（`src/server/images/mark.ts`）；不做缩略图预生成、对象存储 / CDN、公网 URL。
- 不做物理删除 / purge 与级联计数（归 `tickets/T13-历史记录、再生成与彻底删除.md`）；`DELETE` 只落软删 + 审计。

## 4. 实现要点
1. 上传严格按 `modules/M01-照片资产与存储.md` §6.1：校验 → buffer → sha256 → 去重 → 原子落盘 → 单事务三写；事务失败回滚磁盘并抛 `STORAGE_ERROR`。
2. `?w=` 缩放用 `sharp` 且 `withoutEnlargement: true`（永不放大）；仅 `kind='generated'` 带 `X-AIGC-Generated: true`；不存在 / 他人 / 已软删一律 `404 NOT_FOUND`（**不回 403**，`API-04`）。
3. `file.type` 为空或 heic 解码失败一律 `INVALID_FILE_TYPE`，**不做**转码兜底（保原始字节）。

- [待定决策] `modules/M01-照片资产与存储.md` 的 HEIC 语义自相矛盾——§4.1 说"探测失败写 `NULL`、不阻断上传"，§7 错误表又说"heic 无 heif 解码能力导致探测失败 → `400 INVALID_FILE_TYPE`"。→ 拆成两类失败：容器可解析但读不到宽高 → 写 `NULL` 继续；解码器打不开文件 → `400 INVALID_FILE_TYPE`，并写出 `sharp` 错误码到两个分支的映射。
