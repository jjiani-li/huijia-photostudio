## 1. 目标
空仓变成「`pnpm dev` + `pnpm worker` 两进程可启动、`GET /api/health` 可读、`pnpm check` / `pnpm test` 可跑」的可开发骨架，并落齐错误 / 时间 / 响应 / 校验四个横切层。

## 2. 不做（边界）
- 不建业务表、迁移、种子（归 `tickets/T02-数据层：迁移、schema 与种子数据.md`）；不写任何业务 service。
- 不装 ORM / Redis / axios、不新增环境变量（只用 `spec/08-本地开发指南.md` §4 的清单）；`app/api/**` 只落 `/api/health`。

## 4. 实现要点
1. Next.js 15 App Router + TS strict + Tailwind；Node ≥ 20.11、pnpm ≥ 9（`spec/04-技术基线与目录结构.md` §1）。
2. `withErrorHandling` 捕获顺序：`AppError` → 按 `status`；`ZodError` → `INVALID_PARAM`；其他 → 结构化日志 + `INTERNAL`（不透传原始 message，日志按 §4.7）。
3. `pnpm worker` 先落空转循环（心跳与启动自检归 `tickets/T09-生成编排：任务、worker、轮询、重试、额度.md`）；文档间引用一律写完整路径（`spec/09-施工纪律.md` §6）。
4. `scripts/acceptance.ts` 只落**骨架**：按 `spec/07-验收标准.md` §3 的输出格式（`[ID] ✓/✗`、期望 vs 实际、退出码）建执行器与空的检查项注册表；`PROVIDER=mock` 前置与各 ID 的用例由 `tickets/T10`–`tickets/T20` 追加（它们一律标「修改」）。`package.json` 本条接上 `check:acceptance`（`check:blind` / `smoke` 待 `tickets/T20` 的产物落地再接）。

## 5. 完成判定
```bash
pnpm install && pnpm typecheck && pnpm test
pnpm dev    # 另开终端：curl -s localhost:3000/api/health → ok=true
```
- 通用项：`spec/07-验收标准.md` §5 第 1、3、5 条；`API-01`（端点齐备）随端点补齐、在 `tickets/T20-验收：自动化检查与端到端冒烟.md` 全绿，本条只保证 `/api/health` 与骨架就位。
