## 4. 实现要点
1. `normalizeIdentifier` 的归一化结果是 `login_codes.identifier` 与 `users.phone` / `users.email` 的唯一写入值（手机号恒 11 位纯数字、邮箱恒小写）；码比对用 `crypto.timingSafeEqual`（比较前校验长度均为 6）。
2. 登录校验顺序固定「存在 / 已消费 → 过期 → 码值」；发码同 `identifier` 60 秒内已有未消费记录 → `429 CODE_RATE_LIMITED`，`expiresInSec` 恒 600。
3. `devCode` 仅在 `SMS_PROVIDER=console` 时出现，且须调 `assertDevCodeAllowed()` 做实现层断言（失败抛 `INTERNAL`，不透出 code）；cookie 为 `HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000`，`sessions.token_hash = sha256hex(token)`。
4. `GET /api/me` 的 `phone` / `email` 必须经 `mask.ts`；`quota` 取 `readQuota()`（`users.daily_image_quota` 默认 20）；`getSessionUser()` 的 cookie 缺失或格式非法时**不查库**直接 `null`。
5. **替换 `tickets/T02` 的鉴权桩（出口条件）**：`src/server/auth/session.ts` 在**同一路径**改为真实实现——`getSessionUser()` 读 cookie（缺失/格式非法**不查库**直接 `null`）→ `sessions` 活跃行 → `users.status=1`；`requireUser()` 失败抛 `401 UNAUTHENTICATED`；`createSession` / `destroySession` 按 `modules/M08-账号历史与彻底删除.md` §2.1。**回归项**：替换后 `T03`–`T11` 的受保护端点必须仍全绿，并新增「未登录访问受保护端点 → 401 `UNAUTHENTICATED`」（`API-03`）；桩里「不查 cookie」的行为**不得**残留。额度侧同轮下沉：`readQuota()` / `QuotaView` 归 `tickets/T09`，本条只消费。
