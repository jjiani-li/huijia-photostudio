## 1. 目标
把「锚点提取成功」变成「用户主张这就是他 + 两项授权已落库」，并让未确认或未授权的锚点在接口层彻底不可用于生成；审计写入的唯一入口就位。

## 2. 不做（边界）
- 不做实名 / 人脸比对 / 授权书上传；不做吊销 UI 与吊销端点（`spec/03-接口契约.md` 无此端点，不得发明）；不删改 `consents` 历史行。
- 不在 confirm 里顺带触发提取或生成；不在前端做「可否生成」的权威判断。

## 4. 实现要点
1. confirm 单事务顺序固定：归属 → 可用性（`succeeded` 且 `anchor_text` 非空）→ 两项授权齐全 → 写 `consents` 两行 + `markConfirmed`（仅 0→1）→ 两条审计（`anchor.confirm` / `consent.agree`）；`nowIso()` 只取一次，`agreed_at` 与审计 `created_at` 逐字符相等。
2. `audit()` 必须在调用方已开启的事务内调用，失败不回吞；`app/api/**/route.ts` 不得直接调；`meta` 只放 id / `attempt` / `scope` / 级联计数。
3. 生成前置顺序：`confirmed_by_user != 1` → `409`（先），`photo_usage` 无 `revoked_at IS NULL` 行 → `403`（后）；顺序固定后 `SEC-01` 不依赖测试数据里是否有 `consents` 行。
