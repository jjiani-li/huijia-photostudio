## 1. 目标
`POST` / `GET /api/me/realname` 与生成前硬门槛就位；`users.real_name` / `id_hash` / `verified_at` 三列只经 `IdVerifyProvider` 写入，且列名不泄漏到任何 API 响应。

## 2. 不做（边界）
- 不做真实身份核验、人脸比对、一号多账号拦截、频次风控；不做授权书与亲属关系证明；不做密码 / 找回密码。
- 不新增端点 / 字段 / 表 / 错误码 / 环境变量；`/login` 的两个面板骨架由 `tickets/T14` 交付，本条只接线实名段。

## 4. 实现要点
1. `id_hash = sha256(证件号)`，**只存哈希不存明文**；`verified_at` 非空即已实名；三个列名**不得出现在任何 API 响应**。
2. 生成序列第 1 步硬拒绝且**不产生 `generations` 行**，无降级路径、不自动重试；顺序在 `ANCHOR_NOT_CONFIRMED`（409）与 `CONSENT_REQUIRED`（403）**之前**（`spec/03-接口契约.md` §3.5）。
3. `realName` / `idNumber` 为空或格式非法 → `400 INVALID_PARAM`（`details.fields`）；`id_hash` 已被其他用户占用 → `400 INVALID_PARAM`（`details.fields`）。
4. `REALNAME_REQUIRED` 的 `ErrorNotice` 用 `inline` 形态给「去实名」动作 → `/login`；该动作必须落在 `tickets/T16` 的提交处。
5. 成功路径的 `users` 三列写入与 `audit_logs(action='auth.realname')` **必须同一事务**（`RN-04`，`modules/M08-账号历史与彻底删除.md` §2.2）；`audit()` 的调用点在 `auth/` 或 `domain/` 层，`app/api/me/realname/route.ts` 不直接调（`modules/M04-身份确认与授权.md` §9）。
