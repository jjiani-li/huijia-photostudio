## 1. 目标
把链路 ①–④ 组装成能走完的一条路：上传 1–5 张 → 逐张预处理与质量评分 → 标注哪张更适合作为基准 → 发起锚点提取 → 展示锚点文本与 12 项特征 → 点确认并勾两项授权 → 跳年代场景选择。

## 2. 不做（边界）
- 不新增端点 / 响应字段，不自行拼图片 URL（只用响应里的 `url`）；不做年代场景选择、结果 / 历史 / 下载（`tickets/T16`、`tickets/T17`）；不做登录（`tickets/T14`）。
- 不做修复 / 超分 / 美化 / 人脸裁剪；不做前端「是否可生成」的权威判断。

## 4. 实现要点
1. 上传格式与大小交给服务端判定（前端**不做**大小预判）；错误码文案与呈现形态按 `pages/P01-上传与身份确认.md` §5 与 `pages/P00-设计基准与路由.md` §8。
2. 选文件超过 5 张按 `readability` 降序取前 5；基准图在 `usable = true` 中按 `readability` 降序、同值按 `sharpness` 降序取第一张，`usable = false` 一律排后，用户可手动改选（只改 `preprocessedPhotoId`，不重传）。
3. `quality.warnings[]` 与 `quality.advice` 原样展示、不改写不翻译；`usable = false` 不阻断，展示 `advice` 与 `仍然用这张`。
4. 两项授权**初始未勾选、绝不预勾选、绝不写 URL / localStorage**；文案逐字取自 `modules/M04-身份确认与授权.md` §10；提交按钮文案与未勾满行内提示逐字对齐 `pages/P01-上传与身份确认.md` §4.3。

## 5. 完成判定
```bash
pnpm test && pnpm check:acceptance
```
