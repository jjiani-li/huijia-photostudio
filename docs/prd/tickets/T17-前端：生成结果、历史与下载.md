## 4. 实现要点
1. 结果轮询 2s / 180s，终态 `{succeeded, partial, failed}`；超时**不自动停**并保留 `继续看进度`；终态不再轮询（复用 `tickets/T14` 的 `useJobPolling`，终态由它停止排下一次）。
2. `eraCheck` 三态（年代复核判定 `eraCheckVerdict`）与 `|ageDelta| > 5` 的年龄提示按 `modules/M07-生成后复核与内容审核.md` §5.3 / §5.5；年代复核判定 `eraCheckVerdict` 为 `reject` 的结果图**不隐藏、不阻断下载**；`null` 只显示 `还没检查`，不显示推测性提示。
3. `status === 'queued'` 且 `worker.alive === false` → 立即在进度区上方报错（`后台还没启动，图片处理会卡住` + 一行命令 `pnpm worker`），不得无限转圈，也不得并入 `ErrorNotice`；`/history` 同样在顶部报错。
4. 两级删除统一走 `ConfirmDialog`，确认与成功提示必须写明「删了拿不回来」；成功提示取 `cascaded.results`；已被 `runPurge()` 抹掉的行返回 `404` 时按「已经删掉了」处理，只提示 `删掉了`、不报错。
5. 会话失效：`GET /api/generations/:id` / `/api/history` / `/api/photos` 任一回 `UNAUTHENTICATED` → `router.replace(loginPath(pathname))`（`API-03`）；`404` 走 `page` 形态 `ErrorNotice`（文案取服务端 `error.message`）。
6. 「没走完的照片」区块的游标与链路分页**互不通用**（混用 → `400 INVALID_PARAM`）：链路游标写 URL（`?cursor=`）、区块游标留在组件内，两者各走各自的 loader。
