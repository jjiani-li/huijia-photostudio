## 4. 实现要点
1. 级联解析顺序固定：目标 → 受影响锚点 → 受影响 `generations` → 受影响 generated 照片 → 受影响反推任务，全部在**单个 `db.transaction()`** 内；`cascaded` 键名与 `spec/03-接口契约.md` §3.2 / §3.3 完全一致，**不新增键**。
2. `consents` 只写 `revoked_at`（**不删行**）；`identity_anchors` / `generations` / `prompt_reverse_jobs` 物理 DELETE；`generation_results` 留给 `runPurge()` 按 `photo_id` 清。
3. 幂等：重复删除返回 `200` 且 `cascaded` 全零；已被 `runPurge()` 清理或属于他人 → `404 NOT_FOUND`（不返 403）。
4. `runPurge()`：单行失败只记 `failed` 并保留 `photos` 行（下轮重试），不整批失败；批满 `PURGE_BATCH_SIZE` 立即续批；异常必须捕获、绝不中断 worker。
