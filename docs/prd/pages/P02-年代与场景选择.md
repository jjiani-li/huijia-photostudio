## 1. 目标、范围与依赖

**做**：四个年代卡片（E1–E4）、五个场景卡片（S1–S5）、组合样片预览、低置信组合的温和提示、张数选择、发起生成，以及 F4「用一张旧照片反推」辅助入口。

**不做**：

- ❌ 不新增路由 / 端点 / 响应字段：路径以 `pages/P00-设计基准与路由.md` §5 的路由表为准，数据形状以 `spec/03-接口契约.md` §4 为准；
- ❌ 不在前端拼 prompt、不把 prompt 回传服务端，也不把反推的 `resultPrompt` 提交回去（`spec/03-接口契约.md` §6）；不做「自己描述场景」输入框，不提供 prompt 预览（`spec/00-总纲.md` §6.2）；
- ❌ 不做「是否可生成」的完整判断——服务端是唯一裁判，前端只置灰按钮并给文案；也不在本页重复定义视觉 Token、`useJobPolling`、`ErrorNotice`（`pages/P00-设计基准与路由.md` §3、§7、§8）。

本页之外：上传／评分／身份确认／授权 → `pages/P01-上传与身份确认.md`；结果网格／历史／下载 → `pages/P03-结果历史与下载.md`。

## 2. 页面结构、路由与组件

**路由**：`/choose/[anchorId]` → `app/(pages)/choose/[anchorId]/page.tsx`，Server Component 骨架 + Client Component 选择区（`pages/P00-设计基准与路由.md` §5）；需登录，`GET /api/anchors/:id` 的 `anchor.confirmedByUser !== true` 时重定向 `/confirm/[anchorId]`。未提交的选择写在查询参数上（`pages/P00-设计基准与路由.md` §6.2）：`?era=E2`（年代代号）、`?scene=1`（`scenes.id`，**不是** `S1` 这类代号）、`?count=2`；一律用 `router.replace` 写入，不 `push`。

```
ChoosePage  (app/(pages)/choose/[anchorId]/page.tsx, Server Component)
└── ChoosePanel                     (Client Component，持有选择与提交状态)
    ├── EraSection   → EraCard × 4   props: { era: EraOption; selected; onSelect(code): void }
    ├── SceneSection → SceneCard × 5 props: { scene: SceneOption; selected; onSelect(id): void }
    ├── ComboPreview                 props: { eraName; sceneName; profile: EraSceneProfile | null; confidenceHintThreshold }
    │     └── SampleSlot             props: { src: string | null; caption: string; alt: string }   ← §4 两种状态
    ├── CountPicker                  props: { value: 2 | 3 | 4; onChange }
    └── GenerateCta                  props: { disabled; reason; busy; onGenerate }
```

组件落在 `components/choose/`：`era-card.tsx`、`scene-card.tsx`、`sample-slot.tsx`、`combo-preview.tsx`、`count-picker.tsx`、`generate-cta.tsx`（命名沿用 `pages/P00-设计基准与路由.md` §2 的惯例）。props 类型一律从 `src/shared/types.ts` 引入：`EraOption`、`SceneOption`、`EraSceneProfile`、`EraSceneConfig`（`spec/03-接口契约.md` §4）。

## 3. 接口消费（数据来源与端点）

| 用途 | 端点 | 来源 |
|---|---|---|
| 年代 / 场景 / 组合档案（进页面加载一次并缓存） | `GET /api/config/era-scene` | `spec/03-接口契约.md` §3.4 |
| 登录态与剩余额度；守卫用的锚点 | `GET /api/me`；`GET /api/anchors/:id` | `spec/03-接口契约.md` §3.1、§3.3 |
| 发起生成 | `POST /api/generations`（`{ anchorId, eraCode, sceneId, count }`，202） | `spec/03-接口契约.md` §3.5 |
| F4：复用锚点原图或新传一张 / 建任务 / 轮询 | `POST /api/photos`、`POST /api/prompt-reverse-jobs`、`GET /api/prompt-reverse-jobs/:id` | `spec/03-接口契约.md` §3.2、§3.8 |

配置端点只返回 `version` / `confidenceHintThreshold` / `realismAnchor` / `eras` / `scenes` / `profiles`，**不含** `promptPack` / `spacePack` / `constraintPack` / `promptOverride`（`API-06`）。`eras` 或 `scenes` 为空数组即种子未跑，展示 `年代和场景还没准备好，先跑一次 pnpm seed。`

## 4. 样片的两种状态（本页重点）

`eras[].sampleUrl`（年代）与 `scenes[].coverUrl`（场景）是 `string | null`（`spec/03-接口契约.md` §4），取值来自 `spec/era-scene-seed.json` 的 `samplePhoto`——**前端静态资源路径**，形如 `/samples/era-E2.png`，落地目录 `public/samples/`。字段为 `null` 就是没有样片，没有别的中间态：**本期全部为 `null`**（`docs/output/` 下没有可用的真实留存图，见 `spec/08-本地开发指南.md` §7），因此年代 / 场景 / 组合卡片一律按纯文字渲染并如实标注"暂无示例"，**不得**用占位图或 AI 生成图填充。

| 层级 | 有样片 | 无样片（`null`） |
|---|---|---|
| 年代 `eras[]`（4 个） | **E2、E4** | **E1、E3** |
| 场景 `scenes[]`（5 个） | **S1、S3** | **S2、S4、S5** |
| 组合档案 `profiles[]`（20 组） | **E2×S1、E4×S3** | 其余 **18 组** |

两种状态的呈现与逐字文案（`SampleSlot` 是唯一实现点，年代卡、场景卡、组合预览三处共用）：

| 状态 | 呈现 | 逐字文案 |
|---|---|---|
| 有样片 | 图位渲染 `<img src={src} alt={alt}>`（`rounded-lg`、`bg-surface`、4:3、`object-cover`），图下方一行说明 | 该行即服务端 `caption` 原文，前端不改写。例：E2 `彩色胶卷，颜色有点偏，颗粒明显，照相馆和老院子的年代`；S1 `当年街口那家照相馆，布景布、假花、铁椅子` |
| 无样片（`null`） | **纯文字状态**：不渲染 `<img>`，不渲染灰框图、骨架图或任何占位图；图位换成一个同高区块（`bg-surface` + `rounded-lg`，无图标、无边框、无插画），区块内居中一行文字 | `暂无示例`（`note` 字号、`text-ink-soft`）；区块下方照常显示 `caption` |

`ComboPreview` 同理：命中档案且有样片 → 图 + `visualSignature`；有档案但无样片 → 只显示 `visualSignature`，图位写 `暂无示例`；`profile` 匹配不到 → 整个预览区不渲染。**禁止**用占位图、灰框图、骨架图或用 mock／AI 生成的假图充当样片（`spec/era-scene-seed.json` 的 `note`、`spec/03-接口契约.md` §3.4）：样片是「真实感」的第一印象，用不达标的图比不挂图更糟；有图必有 `caption`，无图必有 `暂无示例`。

## 5. 低置信组合的温和提示

`profile.confidence < config.confidenceHintThreshold`（阈值 `0.6`，取自 `spec/era-scene-seed.json` 顶层 `confidenceHintThreshold`，对齐 `DB-04`）时，在 `ComboPreview` 的 `visualSignature` 下方加一行温和提示，**不禁用**该组合、不拦截生成（`modules/M05-年代场景配置与Prompt拼装.md` §6）。

| 位置 | 逐字文案 |
|---|---|
| 低置信提示（`confidence` 低于阈值） | `这两样配在一起的老照片不多，出来可能不太像那个年代。` |

判据用响应里的 `confidenceHintThreshold`，不写死 `0.6`；等于阈值时不提示；`profile = null` 时不提示也不推断。20 组里低于阈值的是这 5 组：E3×S1（0.55）、E4×S1（0.2）、E3×S2（0.35）、E1×S4（0.5）、E4×S5（0.4）。

## 7. 交互与逐字文案

年代与场景各选一个，两者都选定后按 `(eraCode, sceneId)` 命中 `profiles` 才展示组合区；张数默认 2 张（不传 `count` 时服务端缺省 2，`spec/03-接口契约.md` §3.5）；年代卡片用 API 的 `isMono` 标注黑白年代。禁用条件（任一命中即置灰并给对应文案）：未选年代、未选场景、`quota.remaining < count`、`POST /api/generations` 请求期间（该端点非幂等，`spec/03-接口契约.md` §1.5）。

**接住反推推荐**：本页加载时，若 URL 未带 `era` / `scene`，先把 `pages/P01-上传与身份确认.md` §4.4 存下的内存态推荐值写进 URL（`router.replace`，同 §7 的写 URL 规则）；URL 一旦带上参数，内存态不再参与——用户手选优先，采纳只是初值。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 / 分区标题 | `让他出现在哪个年代、哪个地方` / `先选年代，再选场景。两个都可以随时改。` / `先选年代` `再选场景` `你选的组合` |
| 黑白年代标记 / 张数 | `黑白` / `生成几张`：`2 张` `3 张` `4 张` |
| 未选完 / 主按钮 / 生成中 | `上面先各选一个` / `开始生成` / `正在生成，大概要等一会儿` |
| 额度不足（前端置灰）/ 额度用尽（`QUOTA_EXCEEDED`） | `今天的额度不够了` + `今天还能生成 {remaining} 张` / `今天的生成额度用完了，明天再来吧` |
| 并发冲突（`GENERATION_IN_PROGRESS`）/ 授权缺失（`CONSENT_REQUIRED`）/ 未实名（`REALNAME_REQUIRED`）/ 锚点不可用（`ANCHOR_NOT_CONFIRMED`） | `上一组还在生成，稍等一下` / `需要先确认照片使用授权` / 取服务端 `message` / `需要先确认"这就是他"，才能开始生成` |

## 8. 状态与错误：边界与降级

`caption` 是服务端文案，前端原样展示，不改写、不翻译；`null` 的可选文案不渲染。所有样片为 `null` 时整页仍是完整可用的纯文字选择（`spec/03-接口契约.md` §3.4）。配置未回 → 卡片骨架；请求失败（401 / 网络）→ `ErrorNotice` + `重新加载`，不白屏；401 统一跳登录路由并保留 `next`（`pages/P00-设计基准与路由.md` §5）。文案语气遵守 `pages/P00-设计基准与路由.md` §9：第二人称、平实、不煽情，禁用「复活」「重生」「修复」等措辞。

## 9. 与上游文档的差异

§8.2 的「自己描述」入口与「实时预览组合样片」移除：组合区只展示 `visualSignature` 与已有样片，无样片写 `暂无示例`（`spec/00-总纲.md` §6.2、`spec/03-接口契约.md` §3.4）；「四个大卡片」保留形态，但必须有「有样片 / 无样片」两态（`spec/03-接口契约.md` §3.4）。原 PRD 未规定 F4，本页把它做成辅助入口，产物只用于**填好选择**，仍走 `buildPrompt`（`spec/05-Prompt工程.md` §11）。

## 10. 验收与测试要点（含 ticket 归属）

单元测试（A 层 `pnpm test`，vitest，纯函数优先，不依赖网络）：`isLowConfidence(profile, threshold)` —— `confidence < threshold` 为真、等于阈值不提示、`profile === null` 不提示（对齐 `modules/M05-年代场景配置与Prompt拼装.md` §6）；`disabledReason({ era, scene, quota, count, busy })` —— 未选年代 / 未选场景 / `quota.remaining < count` / 提交中 各返回对应文案，穷尽 switch 无 `default`；`readSelection(searchParams)` / `writeSelection(...)` —— `?era`（年代代号）/ `?scene`（整数 `scenes.id`，**不是** `S1` 代号）/ `?count`（缺省 2）的规范化，非法值回退不抛；`takeReverseSuggestion()` —— URL 未带 `era` / `scene` 时返回内存态推荐做初值、返回后清空，URL 已带参数时不参与，且不触碰 `localStorage` / `sessionStorage`（`pages/P01-上传与身份确认.md` §4.4）。

手工 / 检查项：未确认锚点直接打开 `/choose/[anchorId]` → 重定向回 `/confirm/[anchorId]`（`SEC-01`）；`GET /api/config/era-scene` 进页面只发 1 次（`API-06`）；种子未跑（`eras` / `scenes` 为空数组）时展示 `年代和场景还没准备好，先跑一次 pnpm seed。`；样片为 `null` 时整页仍是完整可用的纯文字选择，无占位图（§4）。
