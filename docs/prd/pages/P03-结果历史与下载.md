## 5. 轮询、超时与 worker 存活

- **生成轮询**：`GET /api/generations/:id`，间隔 **2s**、超时 **180s**，终态 `status ∈ {succeeded, partial, failed}`（`spec/03-接口契约.md` §2.1）。请求**串行**——上一次响应回来再排下一次，不得 `setInterval` 叠加；实现落在 `hooks/use-job-polling.ts`（`pages/P00-设计基准与路由.md` §7）。**超时不自动停**：展示 `还在处理，可以先去别处看看`，保留 `继续看进度` 按钮（`refreshNow()`）；已进入终态的任务不得再轮询（`spec/03-接口契约.md` §6 禁忌 5）。
- **后端侧**：`running` 超过 `WORKER_STALE_MINUTES`（默认 10 分钟）由 worker 启动时回退为 `queued`；任务运行超 `JOB_TIMEOUT_SECONDS`（默认 120s）判失败，仅 `PROVIDER_TIMEOUT` / `PROVIDER_ERROR` / `STORAGE_ERROR` 自动重试 1 次（`spec/03-接口契约.md` §2.2）。
- **worker 存活与明确报错（本页硬要求）**：worker 每 5 秒写心跳文件 `.<DATA_DIR>/worker-heartbeat`，`GET /api/health` 按 mtime 判定，超 15 秒未更新即 `worker.alive === false`（`spec/03-接口契约.md` §2.3）；`dev` 侧在启动时与每次入队前读心跳并明确报错，不允许把"任务不执行"变成静默行为（`spec/08-本地开发指南.md` §3.1）。轮询期间若 `status === 'queued'` 且 `worker.alive === false`，立即在进度区上方报错而不是无限转圈——文案 `后台还没启动，图片处理会卡住` + 一行命令 `pnpm worker`（`micro` 字号、`text-ink-soft`）；该提示**不走 `ErrorNotice`**（它不是 API 错误、没有 `code`，`pages/P00-设计基准与路由.md` §8），对齐检查项 `ERR-04`。`worker.alive === true` 而任务仍无进展时按超时态处理，不并入本条。

## 6. `/result/[generationId]` 生成结果

**守卫**：需登录；`GET /api/generations/:id` 返回 `404` → `这组生成记录找不到了`（`page` 形态 `ErrorNotice`，不给重试）。

**状态**：`queued` / `running` → 进度态 + 已到位候选网格（`results` 可能是空数组，附 `共 {requestedCount} 张`）；`succeeded` → 完整网格；`partial` → 成功结果照常展示 + `这几张只成功了一部分` + `再试一次`；`failed` → `这次没生成出来` + `error.message` + `再试一次`；超时与 worker 报错见 §5。

```
ResultPage
├── SafetyNotice         (首次情感安全提示：每会话一次、模块级内存态，见 `pages/P04-失败与情绪安全路径.md` §4)
├── WorkerNotice         (worker.alive=false 的明确报错，见 §5)
├── AsyncStatus / GenerationHeader  (queued/running + 超时后保留"继续看进度"；eraName × sceneName、requestedCount、status)
├── ResultGrid → ResultCard × n  (Thumbnail / EraCheckBadge / AgeDeltaNotice / FeedbackButtons / DownloadLink)
└── PartialNotice + RetryCta     (partial / failed；"用同样设定再来一组")
```

**交互**：点缩略图打开 `Lightbox`（← → 切换、Esc 或点空白关闭）；`EraCheckBadge` 按 `eraCheck.verdict` 三态渲染，`review` / `reject` 时展开列出 `findings[].item` 与 `findings[].reason`；`AgeDeltaNotice` 仅当 `ageDelta !== null` 且 `Math.abs(ageDelta) > 5` 时出现（阈值同 `modules/M07-生成后复核与内容审核.md` §5.5）；反馈三个值 `1` / `-1` / `-2`（`喜欢` / `不喜欢` / `不像他`），再点同一按钮写 `null` 取消，请求期间该按钮禁用；点 `不像他` 除落库外还给一条 `换一张照片再来` → `/upload`（三条出路的区别见 `pages/P04-失败与情绪安全路径.md` §5）；下载支持单张与 `全部下载`（逐张触发，单张失败不影响其余），文件名 `回家照相馆-{eraName}-{sceneName}-{ordinal + 1}.png`；`用同样设定再来一组` 与 `再试一次` 都调 retry（新行、不覆盖历史）后跳新 id；首次情感安全提示在网格之上展示一次，状态只放模块级内存态（`pages/P04-失败与情绪安全路径.md` §4）。

| 位置 | 逐字文案 |
|---|---|
| 页头 / 进度态 | `{eraName} · {sceneName}` ／ `正在生成，大概要等一会儿` / `共 {requestedCount} 张` |
| 首次情感安全提示（**仅本会话首次进本页**，展示在网格之上） | `我们会尽力还原照片的样子，但这是基于照片的重建，无法替代真实。`（语义以 `spec/06-合规与风控.md` §9.2 为准，措辞可调；触发口径见 `pages/P04-失败与情绪安全路径.md` §4） |
| 轮询超时 | `还在处理，可以先去别处看看` + `继续看进度` |
| worker 未启动 | `后台还没启动，图片处理会卡住` + `pnpm worker` |
| 年代徽标（年代复核判定 `eraCheckVerdict`） | `可能不符合所选年代，仅供参考`（`review`） / `明显不符合所选年代`（`reject`） / `还没检查`（`eraCheck === null`） |
| 年龄偏差提示 | `看起来比原照片年轻了 N 岁` / `看起来比原照片年长 N 岁`（N 取 `ageDelta` 绝对值） |
| 反馈 / 下载 | `喜欢` / `不喜欢` / `不像他`（点它同时给 `换一张照片再来`） ／ `下载这张` / `全部下载` |
| 再来一组 / 部分成功 / 失败 | `用同样设定再来一组` / `再试一次` ／ `这几张只成功了一部分` / `这次没生成出来` |
| `PROVIDER_TIMEOUT` / `PROVIDER_ERROR` | `生成花的时间有点长，请重试一次` / `生成服务暂时不可用，请稍后重试` |
| retry 被拒 | `上一组还在生成，稍等一下`（`GENERATION_IN_PROGRESS`） / `今天的生成额度用完了，明天再来吧`（`QUOTA_EXCEEDED`） |

**边界**：`eraCheck = null` 与 `ageDelta = null` 均按"尚未有结论"处理，不显示推测性提示（`null` 时只显示 `还没检查`）；年代复核判定（`eraCheckVerdict`）为 `reject` 的结果图**不隐藏、不阻断下载**（`modules/M07-生成后复核与内容审核.md` §5.3）；`partial` 时不隐藏成功结果；进度只用定性描述，不出现百分比、剩余张数与倒计时（`pages/P00-设计基准与路由.md` §3.1）。

## 7. `/history` 历史记录

**边界（历史列表的范围）**：只覆盖「原图 → 预处理 → 锚点 → 生成结果」这条链路，`generations` 最多返回该锚点下最近 10 条（`spec/03-接口契约.md` §3.6）。**反推任务（`prompt_reverse_jobs`）不进入历史**——它是看图产提示词的工具，不产生照片资产（`modules/M09-图片反推提示词.md`）。

**守卫与状态**：需登录（401 → 登录路由，带 `next`）；首屏未回 → 链路骨架；`items.length === 0 && nextCursor === null` → `这里还没有记录。先去生成一张试试。`；网络失败 → 错误块 + `重新加载`。

```
HistoryPage
├── WorkerNotice        (worker.alive=false 的明确报错，见 §5)
├── HistoryChain × n    (SourceThumb → AnchorSummary → GenerationRow × m → HistoryActions)
├── ConfirmDialog / LoadMore  (删除二次确认见 §8；"再往下看"，nextCursor === null 时隐藏)
```

**交互**：链路三段顺序连接 `sourcePhoto → preprocessedPhoto` + `anchorText → generations[].results[]`；每条 generation 标注 `eraName` × `sceneName`、`status`（`partial` / `failed` 文案同 §6）与年代徽标（同 §6 口径）；`用同样设定再生成` 对某条 generation 调 retry 后跳 `/result/[新 id]`；`再往下看` 把上次的 `nextCursor` 原样回传（不解析，`spec/03-接口契约.md` §6）。`未确认锚点` 的链路不出现，若服务端返回则按 `这个人还没确认过，不能用来生成` 呈现。标题 / 链路标签为 `生成过的记录` 与 `原照片` → `人物特征` → `生成的照片`。

## 8. 两级删除与不可恢复告知

语义由 `modules/M08-账号历史与彻底删除.md` §5.2 定义，交互归 `tickets/T17`。删除**只有**两个入口，统一走 `ConfirmDialog` 二次确认（`pages/P00-设计基准与路由.md` §8）：

| 级别 | 按钮 / 端点 | 删除范围 | 确认文案（逐字） |
|---|---|---|---|
| 链路级 | `删掉这次记录` → `DELETE /api/photos/:id`（`id` = `sourcePhoto.id`，§3.2） | 软删除该原图 + 其预处理派生图 + 受影响 generations 下的生成图；物理删除受影响锚点与 generations；吊销 `consents` | 标题 `删掉这次记录？`／正文 `照片、人物特征和生成结果都会一起删掉，删了拿不回来。`／按钮 `删掉` `算了` |
| 生成部分级 | `只删生成的这几张` → `DELETE /api/anchors/:id`（`id` = `anchorId`，§3.3） | 物理删除该锚点与 `anchor_id` 指向的 generations 并吊销 `consents`；**原图与预处理图不删** | 标题 `只删掉生成的部分？`／正文 `人物特征和生成的照片会删掉，原照片不动。删了拿不回来。`／按钮 `删掉` `算了` |

- **两阶段、宽限期与幂等**：软删除**立即**生效（该照片随即从 `/api/history` 与 `GET /api/photos/:id/file` 消失，`DEL-01` / `DEL-02`）；磁盘文件、`generation_results` 与 `photos` 行在 `deleted_at` 早于 `PURGE_GRACE_MINUTES`（`modules/M08-账号历史与彻底删除.md` §5.3 的模块常量，10 分钟）后由 `runPurge()` 物理清理（`DEL-03` / `DEL-04`）。`DELETE *` 幂等（`spec/03-接口契约.md` §1.5），重复删除按成功处理；已被 `runPurge()` 抹掉的行返回 `404`，前端按"已经删掉了"处理，不报错（`modules/M08-账号历史与彻底删除.md` §9 待定决策 3）。`GET /api/history` 只返回 `status='succeeded'` 的锚点（同文件 §9 待定决策 10），因此生成部分级删除同样会让整张链路卡消失。
- **不可恢复告知（硬要求）**：确认弹层与成功提示都必须写明**删了拿不回来**，不得出现"可以恢复""回收站""过几天还能找回"之类措辞。成功提示：`删掉了` + `一起删掉了 {cascaded.results} 张生成图`（`cascaded` 四键见 `spec/03-接口契约.md` §3.2）。

## 9. 合规标识的用户可见部分

口径以 `spec/06-合规与风控.md` §4 为准：

- **本期结果页不出现任何"AIGC"字样**：无可见标识开关 UI、无"AI 生成"角标组件（`spec/00-总纲.md` §6.2）；水印默认关闭（`WATERMARK_DEFAULT=false`），前端不提供加水印/去水印选项，只读展示 `generation.params.watermark`（`pages/P00-设计基准与路由.md` §11）。**服务端侧**：`kind='generated'` 的文件响应带 `X-AIGC-Generated: true`，其余 `kind` 不带（`spec/03-接口契约.md` §3.2）；隐式标识写入文件元数据（`AIGC_IMPLICIT_MARKER`，默认 `true`）——两者前端都不解析、不展示。
- **将来补做与分享的定则**：可见标识开关默认值必须是"关闭"、必须保留服务端记录（复用 `audit_logs(action='photo.mark')`，不加表）、开关状态**不得出现在生成结果页的主视区内**；本期无分享功能，因此不存在"分享到外部平台时补平台侧可见标识"的实现口径，新增分享时按上述三条补做（`spec/06-合规与风控.md` §1.2、§4、§10）。

## 10. 测试要点

- `eraCheckBadge(eraCheck)`：`review` / `reject` / `null` 三态文案互不相同且穷尽，`pass` 不渲染标注；`ageDeltaNotice(ageDelta)`：仅 `|x| > 5` 时返回文案，`5` / `0` / `null` 返回 `null`（`modules/M07-生成后复核与内容审核.md` §5.5）；`downloadFileName(eraName, sceneName, ordinal)` → `回家照相馆-{eraName}-{sceneName}-{n}.png`。
- 反馈三态：`喜欢` / `不喜欢` / `不像他` 分别为 `1` / `-1` / `-2`，同值再点传 `null`、请求期间禁用（`ResultCardProps.onFeedback`）；`不像他` 同时给出 `换一张照片再来` → `/upload` 的路（`pages/P04-失败与情绪安全路径.md` §5）。
- 情感安全提示的会话态：模块级内存标志首帧返回「显示」、标记后返回「不显示」、模块重载后重新返回「显示」，且不触碰 `localStorage` / `sessionStorage`（`CMP-06`、`pages/P04-失败与情绪安全路径.md` §4）。
- `useJobPolling` 的生成实例（`pnpm test`）：间隔 2s、上一个响应回来才发下一个、终态停止、超时后自动轮询停止而 `refreshNow()` 可用（`spec/03-接口契约.md` §2.1）；反馈按钮同一按钮再点传 `null`，请求期间禁用。
- 手工 / 检查项：未登录访问 `/result/*`、`/history` → 跳登录并保留 `next`（`API-03`）；用他人的 `generationId` 打开 → `这组生成记录找不到了` 而非 403（`API-04`）；`/history` 响应体不得出现手机号/邮箱明文（`API-05`）；删除链路后该链路立即消失（`DEL-01`）、`GET /api/photos/:id/file` 随即 404（`DEL-02`）；worker 停掉后 `/result` 出现 §5 的明确报错（`ERR-04`）；`partial` / `failed` / 超时三态文案不得出现倒计时、夸张成功提示或 `pages/P00-设计基准与路由.md` §9.3 的禁用词。

## 11. 非目标与待定决策
