## 1. 职责与边界
**做**：把链路 ①–④ 组装成一条能走完的路——上传 1–5 张 → 逐张预处理与质量评分 → 标注哪张更适合作为基准 → 发起锚点提取 → 展示锚点文本与 12 项特征 → 点「这就是他」+ 勾两项授权 → 跳年代场景选择，并给出每个界面状态的逐字文案。

**不做**：

- ❌ 不新增端点、不新增响应字段，不自行拼图片 URL（只用响应里的 `url`）；形状以 `spec/03-接口契约.md` §4 的 `src/shared/types.ts` 为准；不在前端拼 prompt、不把 prompt 回传服务端，不做「是否可生成」的权威判断（`spec/03-接口契约.md` §6.1、§6.2）。
- ❌ 不做年代 × 场景选择（`pages/P02-年代与场景选择.md`）、结果 / 历史 / 下载（`pages/P03-结果历史与下载.md`）、登录（`pages/P00-设计基准与路由.md` §5）。
- ❌ 不做修复、超分、美化、人脸裁剪；预处理只做方向校正、色彩空间统一、EXIF 剥离、尺寸归一（`modules/M02-预处理与质量评分.md` §1.3）。

## 2. 页面清单与路由
| 路径 | 页面文件 | 需要登录 | 本页职责 |
|---|---|---|---|
| `/` | `app/(pages)/page.tsx` | 否 | 一句话说明 + 上传入口，仅此而已 |
| `/upload` | `app/(pages)/upload/page.tsx` | 是 | 上传、逐张质量评分、基准图标注、发起锚点提取 |
| `/confirm/[anchorId]` | `app/(pages)/confirm/[anchorId]/page.tsx` | 是 | 轮询提取、原图 / 预处理图对比、锚点文本与特征、确认与授权 |

## 3. 端点与数据读写
前端不直读数据库。以下端点按 **`spec/03-接口契约.md`** 逐字引用（方法 + 路径）；上传格式与大小限制以 `modules/M01-照片资产与存储.md` §7、§8 为准——接受 `image/jpeg` / `image/png` / `image/webp` / `image/heic`，单文件 ≤ `MAX_UPLOAD_MB`（默认 20），本页**不做**上传前的大小预判，交给服务端返回 `FILE_TOO_LARGE`：

| 页面 | 端点 | 服务端落库 |
|---|---|---|
| `/`、`/upload` | 点按钮时探测 `GET /api/me`（§3.1）；`GET /api/health`（§3.7） | 只读；`worker.alive` 驱动上传页顶部提示，`provider.mode` 驱动标题栏小字 |
| `/upload` | `POST /api/photos`（§3.2；`multipart/form-data`，字段名 `file`；201 `{ photo }`） | 写 `photos(kind='original')` 与 `content_reviews(stage='upload')` |
| `/upload` | `POST /api/photos/:id/preprocess`（§3.2；同步；200 `{ photo, quality }`） | 写 `photos(kind='preprocessed', quality_json)` |
| `/upload` → `/confirm` | `POST /api/anchors`（§3.3；body `{ photoIds, preprocessedPhotoId }`；202 `{ anchor }`） | 写 `identity_anchors(status='queued')` + `audit_logs(action='anchor.extract')` |
| `/confirm` | `GET /api/anchors/:id`（§3.3） | 只读；轮询 1.5s / 90s，终止于 `status ∈ {succeeded, failed}` |
| `/confirm` | `POST /api/anchors/:id/confirm`（§3.3；body `{ confirmed: true, consents: ["photo_usage","family_agreement"] }`） | 写 `confirmed_by_user` / `confirmed_at`、`consents` 两行、两条审计 |
| `/confirm` | `POST /api/anchors/:id/retry`（§3.3；202 返回**新行**） | 插新 `identity_anchors` 行，`attempt = 旧 + 1`，旧行零修改 |

### 4.1 `/` 首页
| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 / 按钮 | `回家照相馆` / `上传一张老照片，让他出现在一张从没拍过的新照片里。` / `上传一张老照片` |

### 4.2 `/upload` 上传与质量评分
- **目标**：多选上传 1–5 张，逐张展示 `quality`，标注哪张更适合作为基准，`usable = false` 时给替代建议。
- **守卫**：需登录；`GET /api/health` 的 `worker.alive === false` 时页面顶部提示，**不禁用**后续操作。
- **状态**：**loading** 逐张上传 / 预处理在途 → 卡片骨架 + `正在上传…` / `正在读取照片…`，按钮禁用；**empty** 未选文件 → 空态文案 + 文件选择按钮；**error** 某张返回 `INVALID_FILE_TYPE` / `FILE_TOO_LARGE` / `STORAGE_ERROR` / `CONTENT_REJECTED` / `INTERNAL` → 该行显示文案 + `重试上传`，其余张不受影响；**成功** 至少 1 张 `usable = true` → 卡片显示质量摘要与基准标记，`开始提取面部特征` 可点。

```
UploadPage
├── WorkerBanner         (alive, mode)
├── FilePicker           (multiple, accept="image/jpeg,image/png,image/webp,image/heic", maxCount=5, onPick)
├── PhotoQualityCard × n (photo, quality, isBaseline, onRemove, onSetBaseline, onRetry)
│                        └─ Thumbnail / QualityBadge / WarningList / AdviceBlock / BaselineTag
├── UploadErrorList      (rows: { fileName, code, message }[], onRetry)
└── ExtractCta (disabled, busy, onClick) ／ FooterNote（情感安全提示一行小字）
```

- **交互与按钮**：选文件超过 5 张按 `readability` 降序取前 5，其余忽略并提示；基准图在 `usable = true` 中按 `readability` 降序、同值按 `sharpness` 降序取第一张，`usable = false` 一律排后，用户可手动改选（只改 `preprocessedPhotoId`，不重传）；`photoIds` = 全部上传成功的 `original` 图 id（≤5）；禁用条件：无 `usable = true` 的图、仍有上传或预处理在途、`POST /api/anchors` 请求期间（非幂等，`spec/03-接口契约.md` §1.5）。

`quality.warnings[]` 与 `quality.advice` 是服务端产出，前端**原样展示、不改写不翻译**，`advice = null` 时不渲染该块；取值集合见 `modules/M02-预处理与质量评分.md` §6.1、§6.2。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 | `选几张他的照片` / `清楚一点的、正脸的最好。选 1 到 5 张。` |
| 空态 / 上传中 / 预处理中 | `还没选照片。点上面的按钮，从相册里挑几张。` / `正在上传…` / `正在读取照片…` |
| 基准标记 / 质量摘要 | `这张最适合当基准` / `清晰度 {sharpness} · 可读性 {readability}` |
| 不可用替代建议 / 次级按钮 | 逐字取 `quality.advice`（`modules/M02-预处理与质量评分.md` §6.1），前端不另写 / `仍然用这张` |
| 超过 5 张 / 全部不可用 | `一次最多 5 张，先按前 5 张处理。` / `这几张都不太适合提取特征。换一张清楚的正面照试试。` |
| 文件类型错误 / 文件过大 | `暂时只支持 jpg、png、webp、heic` / `这张照片太大了，换一张小一点的` |
| worker 未启动 / 主按钮 | `后台还没启动，图片处理会卡住` + 命令行 `pnpm worker` / `开始提取面部特征` |

### 4.3 `/confirm/[anchorId]` 身份确认
- **目标**：左右对比原图与预处理图，展示 `anchorText` 与 `features`（可折叠），点 `这就是他，开始生成` 并勾两项授权；覆盖提取中、失败重试、已确认三种进入情形。
- **守卫**：需登录；`GET /api/anchors/:id` 返回 `404 ANCHOR_NOT_FOUND` → 页面级 `ErrorNotice` 文案 `这次的人物特征记录找不到了`，不给重试入口（避免对他人资源探测）。
- **状态**：**loading** `status ∈ {queued, running}` → `AsyncStatus` + 三步步骤提示，90s 后转超时态；**empty** 首个响应未回（`anchor === null`）→ 骨架屏；**error** `status = 'failed'` → `error.message` + `重新提取一次`（404 不给重试）；**成功** `status = 'succeeded'` → 对比区 + `anchorText` + 折叠 `features` + 确认区；**已确认** `confirmedByUser === true` → 展示 `anchorText` 与 `这个人物特征已经确认过了`，主按钮改为 `去选年代和场景`。

```
ConfirmPage
├── AsyncStatus  (phase, steps=["正在读取照片","正在辨认脸部特征","正在整理成文字"])
├── CompareView  (before: sourcePhotos[0], after: preprocessedPhoto)
├── AnchorText (text) ／ FeatureList (features: AnchorFeatures | null, defaultCollapsed)
├── ConsentPanel (checked: { photo_usage, family_agreement }, onChange)
└── ConfirmButton (disabled, busy, onClick) ／ ErrorNotice (error, variant, onRetry)
```

- **交互与按钮**：`features` 默认折叠；两项勾选都勾上后确认按钮才可点（服务端仍是唯一裁判，缺任一项 → `400 INVALID_PARAM`，前端按 `details.fields.consents` 高亮对应复选框）；确认成功跳 `/choose/[anchorId]`；`重新提取一次` 触发 retry，202 返回新 id，用 `router.replace` 到新 id，旧锚点保留在历史；授权勾选**绝不写入 URL / localStorage**（`pages/P00-设计基准与路由.md` §6.3）。
- **对比区约束**：左侧标签 `你上传的那张`，右侧标签 `我们读取用的那张`；两侧都只展示服务端 `url`，不构造路径，**不得**出现任何暗示"变清楚了 / 被修过"的标签或说明（`spec/06-合规与风控.md` §9.1）。授权文案的权威来源是 `modules/M04-身份确认与授权.md` §12，逐字引用，不得改写、不得预勾选、不得合并成一个"全部同意"框。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 | `这是照片里的那个人吗` / `下面是系统从照片里读到的外貌特征。先确认一下，是不是他。` |
| 提取中步骤 1 / 2 / 3 | `正在读取照片` / `正在辨认脸部特征` / `正在整理成文字` |
| 轮询超时 | `还在处理，可以先去别处看看` + `继续看进度` |
| 对比区标签 / 折叠标题（收起 / 展开） | `你上传的那张` / `我们读取用的那张`；`他长这样（12 项特征）` / `收起` |
| 特征标签（依次对应 `gender` `ageRange` `hair` `faceShape` `forehead` `eyebrows` `eyes` `nose` `mouth` `skin` `distinctive` `build`） | `性别` `年龄段` `发型` `脸型` `额头` `眉毛` `眼睛` `鼻子` `嘴部` `皮肤` `显著特征` `体型` |
| 确认按钮 / 未勾满 / 已确认 / 重试 | `这就是他，开始生成` / 未勾满 `需要两项都勾上才能开始` / 已确认后主按钮 `去选年代和场景` / `重新提取一次` |
| 勾选 1（`photo_usage`） | `我确认我手上有这张照片的使用权，也确认照片里的人是我认识的人。` |
| 勾选 2（`family_agreement`） | `我已经和家里其他亲属说过这件事，他们同意我用这张照片来做。` |
| 勾选区下方小字（默认可见、不可折叠） | `如果家里有不同意见，请先沟通好再来做。` |

**边界与降级**：`preprocessedPhoto = null` 时右侧占位显示 `照片还在处理`；`features = null` 而 `status = 'succeeded'` 时只渲染 `anchorText` 并隐藏折叠区；`anchorText` 为空时不渲染确认按钮；三步步骤提示只是文案分段，不与服务端进度绑定（服务端只给 `status`）。`status !== 'succeeded'` 时确认区整体不渲染，因此 `409 ANCHOR_NOT_CONFIRMED` 在本页不可达——该码只属于生成路径（`POST /api/generations`，`pages/P02-年代与场景选择.md`）：用户必须先完成本页确认。

## 5. 错误码与触发位置

前端只做一处映射：`ApiError.error.code` → 呈现形态；**文案一律取服务端 `error.message` 原样展示**（`spec/03-接口契约.md` §1.3）。码、HTTP 状态与用户可见文案的唯一事实源是 `spec/03-接口契约.md` §5，形态与附加动作（「换一张」/「去确认」/ 重试按钮）以 `pages/P00-设计基准与路由.md` §8 为准——**本页只记触发位置**，不复述文案与动作。跨页规则：受保护端点 401 统一触发登录跳转并记录 `next`；网络层失败按 `INTERNAL` 呈现 + `重试`，不得白屏；轮询失败**不终止**轮询，页内显示一行错误后继续。

| code | 触发位置 |
|---|---|
| `UNAUTHENTICATED` | 三个受保护端点 |
| `INVALID_FILE_TYPE` / `FILE_TOO_LARGE` | `POST /api/photos` |
| `INVALID_PARAM` | `preprocess`（`kind != 'original'`）、`POST /api/anchors`（`photoIds` 为空或 > 5 张）、`confirm`（授权缺项，按 `details.fields.consents` 高亮复选框） |
| `NOT_FOUND` / `ANCHOR_NOT_FOUND` | `preprocess`（照片不存在 / 属他人 / 已软删）；`GET /api/anchors/:id`、`confirm`、`retry`（不给重试） |
| `ANCHOR_LOW_QUALITY` / `CONTENT_REJECTED` | 锚点提取；上传或提取 |
| `STORAGE_ERROR` / `INTERNAL` / `PROVIDER_ERROR` / `PROVIDER_TIMEOUT` | 上传、预处理、确认；锚点提取失败（`status='failed'` 的 `error.message`） |
| `ANCHOR_NOT_CONFIRMED` | **本路径不出现**——该码只属生成路径（`spec/03-接口契约.md` §3.5）；本页的职责正是让用户先确认 |

## 6. 本期降级项
1. **heic 已知限制**：`POST /api/photos` 声明接受 `image/heic`，但 `sharp` 是否可解码取决于本机构建（`modules/M01-照片资产与存储.md` §7、`spec/08-本地开发指南.md` §8）。文件选择器仍允许 heic；收到 `INVALID_FILE_TYPE` 时展示 `暂时只支持 jpg、png、webp、heic` 并建议改用 jpg，**不阻断**其他已选文件。
2. **`usable = false` 不阻断流程**：服务端仍返回 `200`，前端展示 `quality.advice` 原文与 `仍然用这张` 次级按钮（`modules/M02-预处理与质量评分.md` §6.1），点了就继续走 `POST /api/anchors`；`usable = false` 的图不作默认基准图。

## 7. 测试要点与 ticket 归属
单元测试（`vitest`，纯函数优先，不依赖网络）：`pickBaseline(cards)` —— `readability` 降序、同值按 `sharpness` 降序、`usable = false` 排最后、全不可用返回 `null`（对齐 `E2E-01` 前端段）；`apiErrorMessage(code)` —— 对 `src/shared/types.ts` 的全部 `ErrorCode` 有映射且与 `spec/03-接口契约.md` §5 逐字一致（穷尽 switch，无 `default`，对齐 `API-02`）；`useJobPolling` 锚点段 —— 间隔 1.5s / 90s、上一个响应回来才发下一个、终态停止、超时后不自动停（对齐 `E2E-01` 前端段）。

端到端与守卫（手工或检查项覆盖）：未登录访问 `/upload`、`/confirm/*` → 跳登录路由并保留 `next`（`API-03`）；用他人的 `anchorId` 打开 → "找不到"文案而非 403（`API-04`）；只勾一个授权项点确认 → `400 INVALID_PARAM` 且 `identity_anchors.confirmed_by_user` 仍为 0（`SEC-02`）；未确认锚点直接打开 `/choose/[anchorId]` → 重定向回 `/confirm/[anchorId]`（`SEC-01`）；worker 未启动时 `/upload` 顶部出现 `后台还没启动，图片处理会卡住` 与 `pnpm worker`（`ERR-04`）；`E2E-01` 的**前端段**要求上传 → 预处理 → 建锚点 → 轮询至 `succeeded` → confirm 界面对同一链路可用。

ticket 归属：本文件全部页面与组件属 `tickets/T15-前端：上传 → 预处理 → 身份确认.md`，视觉 Token、`SiteHeader`、`ErrorNotice`、`useJobPolling` 等基础件属 `tickets/T14-前端基础：设计基调、布局与通用组件.md`；完成判定见 `spec/07-验收标准.md` §5。
