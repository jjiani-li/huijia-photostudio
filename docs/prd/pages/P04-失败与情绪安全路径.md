# P04 · 失败与情绪安全路径

> **层级**：实现规格层 · 前端页面
> **上游**：`spec/06-合规与风控.md` §9 ／ `spec/07-验收标准.md` §2.8 ／ `spec/03-接口契约.md` §5 ／ `pages/P00-设计基准与路由.md` §8、§9 ／ `pages/P01-上传与身份确认.md`、`pages/P02-年代与场景选择.md`、`pages/P03-结果历史与下载.md`
> **下游**：`tickets/T15-前端：上传 → 预处理 → 身份确认.md`、`tickets/T16-前端：年代 × 场景选择.md`、`tickets/T17-前端：生成结果、历史与下载.md`

> 本文件是**负路径与情绪安全**的汇总处：九类失败情形各写清「触发 → 界面 → 下一步」，并固定首次情感安全提示的唯一触发口径。**文案与形态不在本文件定义**——`ErrorNotice` 的形态与附加动作以 `pages/P00-设计基准与路由.md` §8 为准，用户可见文案的唯一事实源是 `spec/03-接口契约.md` §5（前端原样展示服务端 `error.message`）；本文件只记**界面构件与下一步动作**，以及它们之间的分界。

## 1. 目标、范围与依赖

**目标**：让每条失败路径都有归宿——用户看得懂发生了什么、知道下一步做什么，且不会被夸张的成功提示或倒计时掩盖。

**范围**：九类负路径的界面与下一步（§3）、首次情感安全提示的触发口径（§4）、结果页「不像他」与反馈 / 重新生成 / 换一张照片的分界（§5）。

**不做**：不新增端点 / 字段 / 错误码 / 组件 / 路由；不复述 `ErrorNotice` 的形态表与文案表；不引入「回收站 / 可以恢复」这类措辞（`pages/P03-结果历史与下载.md` §8）；不做分享、导出、评论。

**依赖**：本页的界面全部长在 `pages/P01` / `pages/P02` / `pages/P03` 已有的页面与组件上，本文件**不新增路由、不新增组件**。ticket 归属随宿主页：`/`、`/upload`、`/confirm/[anchorId]` 归 `tickets/T15-前端：上传 → 预处理 → 身份确认.md`；`/choose/[anchorId]` 归 `tickets/T16-前端：年代 × 场景选择.md`；`/result/[generationId]`、`/history` 归 `tickets/T17-前端：生成结果、历史与下载.md`。

## 2. 接口消费

本文件**不消费任何端点**——它描述的是既有页面对既有端点**失败返回**的处理。错误码、HTTP 状态与用户可见文案的唯一事实源是 `spec/03-接口契约.md` §5；前端只做一处映射（`code` → 呈现形态），主文案一律取服务端 `error.message`（`pages/P01-上传与身份确认.md` §5）。

## 3. 状态与错误：九类负路径（触发 → 界面 → 下一步）

| # | 情形 | 触发 | 界面（构件 + 落点） | 下一步 |
|---|---|---|---|---|
| 1 | 锚点提取失败 | `GET /api/anchors/:id` 的 `status='failed'`（`ANCHOR_LOW_QUALITY` / `PROVIDER_ERROR` / `PROVIDER_TIMEOUT` / `STORAGE_ERROR` / `INTERNAL`） | `/confirm/[anchorId]`：`AsyncStatus` 三步提示转入失败态 + 页面级 `ErrorNotice` 取服务端 `error.message`；`404` 不给重试（`pages/P01-上传与身份确认.md` §4.3） | `重新提取一次`（retry 新行、旧行留在历史）／回 `/upload` 换一张 |
| 2 | 质量不可用 | `POST /api/photos/:id/preprocess` 返回 `usable=false`（仍 `200`） | `/upload`：`QualityBadge` + `quality.advice` 原文（`WarningList` / `AdviceBlock`）+ `仍然用这张`；`usable=false` 的图不作默认基准（`pages/P01-上传与身份确认.md` §4.2） | 换一张（重选文件）／`仍然用这张` 继续提取 |
| 3 | 生成失败 | `GET /api/generations/:id` 的 `status='failed'`（`CONTENT_REJECTED` / `PROVIDER_ERROR` / `STORAGE_ERROR` / `INTERNAL`） | `/result/[generationId]`：`AsyncStatus` 失败态 + `ErrorNotice` + `再试一次`；`partial` 只加 `这几张只成功了一部分`、成功的张照常展示（`pages/P03-结果历史与下载.md` §6） | `再试一次` = retry（新行、不覆盖历史） |
| 4 | 结果不像他 | 用户在 `/result/[generationId]` 点 `不像他` | 结果卡第三个反馈按钮：写 `generation_results.user_feedback = -2`，并在同处给一条 `换一张照片再来` → `/upload`（见 §5） | 回 `/upload` 重新上传 → 提取 → 确认 → 生成（新链路）；该值只落库留痕、**不做聚合** |
| 5 | 超时 | 前端轮询 `elapsedMs >= timeoutMs`（锚点 90s / 生成 180s，`pages/P00-设计基准与路由.md` §7）；或服务端 `PROVIDER_TIMEOUT` | 锚点页 / 结果页：`还在处理，可以先去别处看看` + `继续看进度`（**自动轮询停、能力保留**）；服务端超时自动重试 1 次后仍失败 → 按「生成失败」呈现（`spec/03-接口契约.md` §2.2） | `继续看进度`（`refreshNow()`）／`再试一次` |
| 6 | 额度用尽 | `POST /api/generations` 或 retry 返回 `QUOTA_EXCEEDED` | `/choose/[anchorId]` 提交处与 `/result` retry 处：`ErrorNotice` + `quota.remaining` / `quota.limit`；`quota.remaining < count` 时提交按钮置灰（`pages/P02-年代与场景选择.md` §7） | 降 `count`（2 张）／明天再来（额度按 UTC 日重置，`modules/M08-账号历史与彻底删除.md` §3.1） |
| 7 | worker 未启动 | `GET /api/health` 的 `worker.alive === false`（心跳超 15s 未更新） | `/upload`、`/result`、`/history` 顶部**明确报错**：`后台还没启动，图片处理会卡住` + 一行命令 `pnpm worker`；**不走 `ErrorNotice`**（没有 `code`，不是 API 错误） | 另开一个终端跑 `pnpm worker`（`spec/08-本地开发指南.md` §3.1）；`alive=true` 而任务仍无进展时按超时态处理 |
| 8 | 未实名 | `POST /api/generations` 返回 `REALNAME_REQUIRED` | `/choose/[anchorId]` 提交处：`ErrorNotice` + 「去实名」动作（`pages/P00-设计基准与路由.md` §5.2） | 「去实名」→ `/login`；与 `ANCHOR_NOT_CONFIRMED` 同属硬拒绝，**无降级路径、不自动重试** |
| 9 | 未确认锚点 | `POST /api/generations` 返回 `ANCHOR_NOT_CONFIRMED`；或直接打开 `/choose/[anchorId]` 而 `confirmedByUser !== true` | `/choose` 守卫：重定向回 `/confirm/[anchorId]`（`SEC-01`）；提交处 `ErrorNotice` + 「去确认」 | 「去确认」→ `/confirm/[anchorId]`，勾两项授权后重走生成 |

**共同约定**：① 任何负路径都不得白屏，也不得用「夸张成功提示 / 倒计时 / 百分比」掩盖（`pages/P00-设计基准与路由.md` §3.1、§9.1）；② 未登录统一跳登录并保留 `next`，他人资源统一「找不到」而非 403（`API-03` / `API-04`）；③ worker 未启动与 API 错误**分开呈现**（`pages/P00-设计基准与路由.md` §8）；④ 措辞不得出现 `pages/P00-设计基准与路由.md` §9.3 的禁用词，尤其不得暗示「修复」；⑤ 删除类负路径（已被 `runPurge()` 抹掉的 404）按「已经删掉了」处理，不报错（`pages/P03-结果历史与下载.md` §8）。

## 4. 首次情感安全提示（唯一触发口径）

**语义与措辞**以 `spec/06-合规与风控.md` §9.2 为准（语义固定、措辞可调、不得指涉 `逝者` / `离开的人`）。

**触发口径（唯一）**：**每会话一次、状态放模块级内存态**。

- 首次进入 `/result/[generationId]` 时，在**网格之上、页面主视区**展示一次温和说明；用户确认即标记本次会话已展示。
- 状态**只**放模块级内存变量（Client 组件模块作用域），**不写** `localStorage` / `sessionStorage`，**不引入**「已读」这类持久状态——这是页面规范的硬约束（`pages/P00-设计基准与路由.md` §6），内存态是唯一可行解。刷新页面即新会话，会再展示一次，这是**有意**的。
- 该提示**不是** API 错误，不并入 `ErrorNotice`；也不是进度态，不并入 `AsyncStatus`。首页 `/` 只在页脚常驻同义一行小字，不参与计数（`pages/P01-上传与身份确认.md` §4.1）。
- 落点：`pages/P03-结果历史与下载.md` §6；检查项 `CMP-06`（`spec/07-验收标准.md` §2.8）。

## 5. 「结果不像他」与反馈 / 重新生成 / 换一张照片的分界

结果页对「不满意」有四条彼此不同、**不得混为一谈**的出路：

| 出路 | 落点 | 语义 | 是否产生新记录 |
|---|---|---|---|
| 反馈 `不喜欢` | `generation_results.user_feedback = -1` | 对**这一张**的评价，只落库留痕 | 否 |
| 反馈 `不像他` | `generation_results.user_feedback = -2`，并给一条回 `/upload` 的路 | 对**这一张**最重要的失败信号（不像本人）+ 引导换输入 | 否 |
| `用同样设定再来一组` / `再试一次` | `POST /api/generations/:id/retry` | 同一组设定**重跑**，新行、不覆盖历史 | 是（新 `generations` 行） |
| `换一张照片再来` | 回 `/upload` 重新上传 | 换**输入**重来：新照片 → 新锚点 → 重新确认 → 生成 | 是（新照片、新锚点、新生成） |

约定：① 三个反馈值 `1` / `-1` / `-2` 互斥，再点同一按钮传 `null` 取消（`spec/03-接口契约.md` §3.5）；② `-2` **本期只落库留痕、不做聚合**——不新增看板、不新增指标消费方（避免再造一个没有 owner 的指标）；③ 「换一张照片」**不删除**已有记录，历史里那组仍在，要删走 `pages/P03-结果历史与下载.md` §8 的两级删除。

## 6. 验收与测试要点

- 检查项：`CMP-06`（情感安全提示的语义句存在、触发状态为内存态——`spec/07-验收标准.md` §2.8）；`ERR-04`（worker 未启动的明确报错）；`SEC-01`（未确认锚点的守卫重定向）；`API-03` / `API-04`（未登录 / 他人资源）。
- A 层纯函数（`pnpm test`）：反馈三态按钮语义（同值再点传 `null`）；情感安全提示的会话态（首帧返回真、看过一次后为假、模块重载后为真，且不触碰 `localStorage` / `sessionStorage`）。
- 手工：§3 的九类情形逐条走一遍，确认界面与「下一步」一致、无白屏、无 `pages/P00-设计基准与路由.md` §9.3 的禁用词。

## 7. 非目标与待定决策

**非目标**：分享、导出、评论、结果图编辑；情绪安全的自动化干预（本期只有一次提示与措辞禁令）；九类路径之外的运维态（如数据库损坏、进程崩溃）不在产品界面的范围内。

**待定决策**：无——本文件是既有行为的汇总与交叉引用，不引入新的开放问题；各宿主页自己的开放问题留在它们的「非目标与待定决策」一节（如 `pages/P03-结果历史与下载.md` §11）。
