## 3. 设计基调与 Token
### 3.1 设计基调（继承 `docs/raw/AIGC_PRD.md` §8.1）
暖白 / 米杏 / 浅木色打底，主色用柔和暖棕，**忌高饱和、忌冷科技蓝紫**；标题用中文衬线（信笺感），正文无衬线、字重偏细；大留白、**一屏一重点**；动效极克制，以淡入为主。硬性推论：**全站不得以 `#000000` / `#FFFFFF` 作区块背景**（纯黑仅允许图标描边级别小面积）；任何进度**不得出现数字倒计时**，只用不定进度条 + 一句平实说明；结果页不得出现 `太棒了` / `奇迹` / `成功生成 N 张`；动效统一 `animate-fade-in`（180ms `ease-out`），不做跨页转场；措辞禁令见 §9.3。
### 3.2 语义色（`theme.extend.colors`）

| 语义名 | hex | Tailwind 键 | 用途 |
|---|---|---|---|
| `background` | `#FBF7F1` | `colors.background` | 全站底色（暖白） |
| `surface` | `#F3EBDD` | `colors.surface` | 卡片 / 输入框 / 图卡底（米杏） |
| `wood` | `#D8C3A2` | `colors.wood` | 分隔线、年代卡片装饰（浅木色） |
| `primary` | `#A9704A` | `colors.primary.DEFAULT` | 主按钮、选中态描边（柔和暖棕） |
| `primary-soft` | `#E8D6C3` | `colors.primary.soft` | 主色悬停 / 禁用底、选中卡片底 |
| `ink` | `#3B2F28` | `colors.ink.DEFAULT` | 正文与标题（深暖褐，非纯黑） |
| `ink-soft` | `#7A6A5C` | `colors.ink.soft` | 说明、时间戳、卡片 caption |
| `border` | `#E3D8C8` | `colors.border` | 全部分割线与输入框描边 |
| `danger` | `#B4553F` | `colors.danger` | 错误文案与错误框（暖调砖红，不用正红） |
命名硬约束：正文色与说明色就是 `text-ink` / `text-ink-soft`，**不要写 `text-primary`**——`colors.primary` 会生成同名工具类，撞名后正文变「主色文字」。`primary` 作背景时文字用 `#FBF7F1`（对比度 ≈ 4.9:1）；`danger` 只用于文字与 1px 描边。
### 3.3 字号阶梯（6 档，`theme.extend.fontSize`）
`display` 32/1.35·500（首页唯一主标题，每屏最多一处） · `title` 24/1.4·500（页面标题） · `heading` 19/1.5·500（区块 / 卡片主标题） · `body` 16/1.7·400（正文、按钮、表单标签） · `note` 14/1.6·400（卡片说明、表单提示） · `micro` 12/1.5·400（顶部导航小字、时间戳、`provider.mode`）。
### 3.4 间距 / 圆角 / 阴影 / 动效
- `spacing`：`xs 4` · `sm 8` · `md 12` · `lg 16` · `xl 24` · `2xl 32` · `3xl 48` · `4xl 64`（px）；`maxWidth.content = 720px`（一屏一重点内容栏，统一由 `app/(pages)/layout.tsx` 约束）。
- `borderRadius`：`sm 6px` · `md 10px`（卡片） · `lg 16px`（图片容器） · `pill 999px`（主按钮）；`boxShadow`：`soft 0 1px 2px rgba(59,47,40,.06)`（默认卡片） · `card 0 2px 10px rgba(59,47,40,.08)`（悬停 / 图卡）；`animation`：`fade-in: fadeIn 180ms ease-out both` + `@keyframes fadeIn { from { opacity: 0 } to { opacity: 1 } }`；`theme.extend` 键名清单：`colors`、`fontFamily`、`fontSize`、`spacing`、`maxWidth`、`borderRadius`、`boxShadow`、`keyframes`、`animation`。
### 3.5 样片的两种状态（`samplePhoto` 可空）
年代卡片、场景卡片、组合卡片各有一个样片位，取值来自 `spec/era-scene-seed.json` 的 `samplePhoto`（可空，映射到端点的 `EraOption.sampleUrl` / `SceneOption.coverUrl`，`spec/03-接口契约.md` §3.4）；`seed-v1` 下只有 E2、E4、S1、S3、E2×S1、E4×S3 有样片，其余为 `null`。
- **有样片**：固定 4:3 比例容器承载 `<img>`（`unoptimized`），`rounded-lg` + `shadow-soft`，`alt` 用卡片名；下方两行文字——卡片主标题（`heading`）+ 一行说明（`note` / `text-ink-soft`，取 `caption`）。
- **无样片**：不渲染 `<img>`；同等 4:3 容器用 `bg-surface` + 1px `border-border` 占位，居中 `note` 字号 `text-ink-soft` 写「暂无示例」；卡片其余文字与有样片态逐字一致。**禁止**用占位图、mock 生成图或 AI 生成图充当样片；逐页交互细节见 `pages/P02-年代与场景选择.md`。
## 4. 字体栈与全局布局
### 4.1 字体栈（`theme.extend.fontFamily`）
```ts
fontFamily: {
  serif: ['"Source Han Serif SC"', '"Noto Serif SC"', '"Songti SC"', '"STSong"', 'serif'],
  sans:  ['"PingFang SC"', '"Source Han Sans SC"', '"Noto Sans SC"', '"Microsoft YaHei"', 'system-ui', 'sans-serif'],
}
```
标题（`display` / `title` / `heading`）用 `font-serif`，正文与控件用 `font-sans`；**不下载 webfont**，只用系统已装字体（`spec/08-本地开发指南.md` §1）。Windows 上缺 `Source Han Serif SC` / `Noto Serif SC` 时回退 `Songti SC` → `serif`（宋体），属可接受降级。全局 `letter-spacing: 0.01em`、`-webkit-font-smoothing: antialiased` 写在 `app/globals.css`；禁止用 `Inter` / `Roboto` 等冷感几何无衬线作中文主字体。
### 4.2 全局布局与顶部导航
`app/layout.tsx` → `<body class="bg-background text-ink font-sans">` → `app/(pages)/layout.tsx` → `<SiteHeader />`（固定 56px、底边 1px `border-border`）+ `<main class="mx-auto max-w-content px-xl py-2xl">`。
`SiteHeader` 从左到右：站点名（`font-serif` / `heading`，常量）· 「历史」链接 → `/history` · 用户昵称 + 剩余额度（`额度 14/20`，取 `GET /api/me` 的 `user.nickname` / `quota.remaining` / `quota.limit`）· 右上小字 `真实模式`（`PROVIDER=real`）/ `本地模式`（`mock`），取 `GET /api/health` 的 `provider.mode`（`spec/08-本地开发指南.md` §5.2）。
worker 未存活提示只落在**上传页顶部**（不是全站）：`GET /api/health` 的 `worker.alive === false` 时显示 `后台还没启动，图片处理会卡住`，紧跟一行 `pnpm worker`（`micro` / `text-ink-soft`），对齐 `ERR-04`。
## 5. 路由表
### 5.1 路由表

| 路径 | 页面名 | 规格文档 |
|---|---|---|
| `/login` | 登录 + 实名（两段式同路由，见 §5.2） | `pages/P00-设计基准与路由.md` §5.2 |
| `/` | 首页（一句话说明 + 上传入口） | `pages/P01-上传与身份确认.md` |
| `/upload` | 上传 → 预处理 | `pages/P01-上传与身份确认.md` |
| `/confirm/[anchorId]` | 身份确认 | `pages/P01-上传与身份确认.md` |
| `/choose/[anchorId]` | 年代 × 场景选择 | `pages/P02-年代与场景选择.md` |
| `/result/[generationId]` | 生成结果（含首次情感安全提示） | `pages/P03-结果历史与下载.md` |
| `/history` | 历史与下载 | `pages/P03-结果历史与下载.md` |
App Router 页面目录 `app/(pages)/`（`spec/04-技术基线与目录结构.md` §2）。规则：① **页面组件一律 Server Component**，只做静态骨架与「cookie 存在性」软校验，真实数据一律在 Client Component 里经 `src/shared/api-client.ts` 取（`spec/03-接口契约.md` §6）。② `[anchorId]` / `[generationId]` 用 zod 在页面入口解析为整数，非法值直接 `notFound()`（不发请求）。③ 上表除 `/login` 外均需登录，在 `app/(pages)/layout.tsx` 统一软重定向：`cookies().has('sid')` 为假 → `redirect('/login?next=<本页>')`；服务端仍是唯一裁判（`UNAUTHENTICATED` → 页面级 `ErrorNotice`，§8）。④ 站内跳转用 `next/link`；图片用 `<img>` 或 `next/image` 的 `unoptimized`（`url` 由服务端给且带 `?w=`）。
### 5.2 登录与实名页（`/login`）
两段式同路由：验证码登录段 → 实名段。已登录且已实名访问 `/login` → `redirect(next)`（`next` 缺省 `/upload`）；已登录未实名 → 直接展示实名段。端点与字段以 `spec/03-接口契约.md` §3.1 为准：`POST /api/auth/code`（`identifier`、可选 `channel`）→ `POST /api/auth/login`（`identifier`、`code`）→ `GET /api/me` / `GET /api/me/realname`（`realNameStatus`）→ `POST /api/me/realname`（`realName`、`idNumber`）。
- **登录段** `<LoginPanel />`（Client）：`<input inputMode="tel" />` 手机号或邮箱 + 「获取验证码」；发码后追加 `<input inputMode="numeric" maxLength={6} />` 验证码 + 「登录」；重发按钮文字固定 `稍等一下`、禁用 60 秒、**不显示倒计时秒数**（§3.1）。逐字文案：标题 `回家照相馆`；说明 `用手机号或邮箱登录，我们会发一个六位数的验证码给你。`；底部小字 `我们不会把你的照片用在别的地方。`；identifier 只做去空格与非空校验。`SMS_PROVIDER=console` 时响应带 `devCode`，**仅当响应含该字段**才在发码后显示一行 `开发模式：验证码是 {devCode}。`（`micro` / `text-ink-soft`），生产不返回（对齐 `SEC-07`）；`DEV_LOGIN_CODE` 前端不写死、不提示。
- **实名段** `<RealNamePanel />`（Client）：`realName`（真实姓名）、`idNumber`（证件号）两个文本输入 + 提交按钮；未实名时展示，提交成功后展示已实名态（`realNameStatus.verified`），**不回显证件号明文**（服务端只存哈希）。不做「记住我」「忘记密码」「第三方登录」「一键登录」。
- **错误码**：`CODE_INVALID` / `CODE_EXPIRED` 在验证码输入框下方一行 `text-danger`，取服务端 `message`；`CODE_RATE_LIMITED` 同上且「重新获取」保持禁用（文案 `刚刚已经发过了，稍等一下`）；实名格式 / 唯一性失败 → `INVALID_PARAM`（`details.fields` 仅用于高亮控件）；`PROVIDER_ERROR` / `INTERNAL` → `ErrorNotice`（§8）。
- **未实名时生成的引导**：`POST /api/generations` 未实名返回 `409 REALNAME_REQUIRED`（文案 `需要先完成实名认证，才能开始生成`），与 `ANCHOR_NOT_CONFIRMED` 同一硬拒绝处理——无降级路径、不自动重试（`spec/06-合规与风控.md` §5.2）。`ErrorNotice` 以 `inline` 形态给「去实名」动作 → `/login`；`pages/P02-年代与场景选择.md` 的提交处必须落这个动作。
## 6. 状态管理方案
不引入 redux / zustand / jotai / react-query：全站没有真正的跨页共享状态，全部查询是「进页面取一次 + 轮询一个任务」，`useJobPolling` + `useEffect` 已足够；Next Server Actions 会绕开冻结的 HTTP 契约。手段：**RSC 页骨架 + 少量客户端 `useState`/`useRef` + URL 参数（流程事实源）**。

| URL 参数 | 载体 | 理由 |
|---|---|---|
| `anchorId` | `/confirm/[anchorId]`、`/choose/[anchorId]` 路径段 | 流程事实，刷新 / 回退 / 分享都必须成立 |
| `generationId` | `/result/[generationId]` 路径段 | 同上；历史页可直接链到结果 |
| `era` / `scene` | `/choose/[anchorId]?era=E4&scene=3` | 未提交的选择，刷新不丢、不落库（`scene` 是 `scenes.id`，非 `code`） |
| `count` | `/choose/[anchorId]?count=2` | 与 `POST /api/generations` 的 `count` 同名同义；缺省不写，服务端默认 2 |
| `cursor` | `/history?cursor=<opaque>` | 不透明游标，前端**只回传不解析**（`spec/03-接口契约.md` §6 禁忌 4） |
写 URL 一律 `router.replace(...)`，**不用 `push`**（选年代 / 场景不是导航，不该污染历史栈）。local state：上传中的 `File[]` 与进度、各提交按钮的「请求进行中」禁用标志（`POST /api/anchors`、`POST /api/generations` 非幂等，请求期间必须禁用按钮）、`useJobPolling` 内部状态、两个授权勾选（`photo_usage` / `family_agreement`，初始未勾选，**绝不写 URL / localStorage**）、结果页当前放大图、当前 `ErrorNotice` 消息。**禁止**把 `prompt`、`anchorText`、授权勾选、上传中文件放进 `localStorage` / `sessionStorage`。唯一允许的会话级内存态是**情感安全提示的「本次会话已展示」标志**（模块作用域变量，不落任何存储；每会话一次，触发口径见 `pages/P04-失败与情绪安全路径.md` §4）。
## 7. 轮询 Hook：`useJobPolling`

```ts
export const ANCHOR_POLL_INTERVAL_MS = 1500;      export const ANCHOR_POLL_TIMEOUT_MS = 90_000;
export const GENERATION_POLL_INTERVAL_MS = 2000;  export const GENERATION_POLL_TIMEOUT_MS = 180_000;
export type PollPhase = 'idle' | 'polling' | 'done' | 'timedOut' | 'error';
export interface JobPollingOptions<T> { fetchJob: () => Promise<T>; getStatus: (job: T) => string; terminalStatuses: readonly string[]; intervalMs: number; timeoutMs: number; enabled: boolean; }
export interface JobPollingState<T> { job: T | null; phase: PollPhase; jobStatus: string | null; elapsedMs: number; error: { code: string; message: string } | null; refreshNow: () => void; }
export function useJobPolling<T>(options: JobPollingOptions<T>): JobPollingState<T>;
```
实现在 `hooks/use-job-polling.ts`，对齐 `spec/03-接口契约.md` §2.1。实现要点（每条对应一个可测断言）：① **只排下一次、不叠加**：`setTimeout` 递归、不用 `setInterval`，下一次调度在本次响应（或失败）回来之后；`enabled` 为真时**首帧立即请求一次**。② **并发护栏**：`useRef<boolean>('inFlight')`，请求前置 `true`、`finally` 置 `false`，已在飞行中则跳过本轮调度。③ **终止即停**：`getStatus(job) ∈ terminalStatuses`（锚点 `['succeeded','failed']`，生成 `['succeeded','partial','failed']`）→ `phase='done'`；`enabled=false` 或组件卸载时清 `setTimeout` 并复位 `inFlight`。④ **超时不取消能力**：`elapsedMs >= timeoutMs` → `phase='timedOut'`（文案 `还在处理，可以先去别处看看`），自动轮询停止但 `refreshNow()` 保留，调用后恢复间隔轮询。⑤ **错误不吞**：`ApiClientError` → `error={code,message}`、`phase='error'`，停止自动轮询交给 `ErrorNotice`；`PROVIDER_TIMEOUT` / `PROVIDER_ERROR` 由用户点重试（后端最多自动重试 1 次）。⑥ **不轮询终态**：已进入终态的 `anchorId` / `generationId` 不得再次发起轮询（`spec/03-接口契约.md` §6 禁忌 5）。调用方各传一组常量：`/confirm/[anchorId]` 用 `ANCHOR_*`；`/result/[generationId]`、`/choose/[anchorId]`（提交后跳转）用 `GENERATION_*`。
## 8. 错误呈现：`ErrorNotice`

```ts
export interface ErrorNoticeProps {
  error: { code: string; message: string } | null;
  variant?: 'inline' | 'page';   // 'page' 占满内容区（该页无法继续）；'inline' 贴触发控件下方
  onRetry?: () => void;          // 不传则不显示重试按钮
  action?: ReactNode;            // 附加动作插槽：「换一张」「去确认」「去看那一组」「去实名」
}
export function ErrorNotice(props: ErrorNoticeProps): ReactElement | null;
```

实现在 `components/error-notice.tsx`，是 `spec/03-接口契约.md` §5 错误码在前端的**唯一落点**。主文案**直接用服务端 `error.message`**（`spec/03-接口契约.md` §1.3，前端不重写、不改写、不二次加工）；未知 `code` → 按 `INTERNAL` 渲染，仍显示服务端 `message`。视觉：`bg-surface` + 1px `border-danger` + `text-danger` 标题行 + `text-ink` 正文，`note` 字号；无图标、无大面积红填充、无感叹号堆叠。

| code | 形态 | 附加动作（除末行外均**不**显示重试按钮） |
|---|---|---|
| `UNAUTHENTICATED` | page | 「去登录」→ `/login` |
| `FORBIDDEN` / `NOT_FOUND` / `ANCHOR_NOT_FOUND` | page | 「回历史」→ `/history` |
| `INVALID_PARAM` / `INVALID_FILE_TYPE` / `FILE_TOO_LARGE` | inline | 高亮对应控件（`details.fields`，不展示原文）／「换一张」唤起文件选择 |
| `CODE_INVALID` / `CODE_EXPIRED` / `CODE_RATE_LIMITED` | inline | 聚焦验证码输入框；`CODE_RATE_LIMITED` 禁用「发送」60 秒（按钮可用性，非任务倒计时） |
| `CONSENT_REQUIRED` | inline | 滚动并聚焦授权勾选区 |
| `ANCHOR_NOT_CONFIRMED` / `REALNAME_REQUIRED` | inline | 「去确认」→ `/confirm/{anchorId}` ／ 「去实名」→ `/login`（§5.2） |
| `ANCHOR_LOW_QUALITY` / `GENERATION_IN_PROGRESS` / `QUOTA_EXCEEDED` / `CONTENT_REJECTED` | inline | 展示 `details.quality.warnings[]` 原文 + 「换一张」／「去看那一组」→ `/history` ／ 显示 `quota.remaining`、`quota.limit` ／ 无动作、不回显审核原因 |
| `PROVIDER_ERROR` / `PROVIDER_TIMEOUT` / `STORAGE_ERROR` / `INTERNAL` | inline | — → **是**（`onRetry`） |
worker 未存活提示**不走 `ErrorNotice`**（它不是 API 错误、没有 `code`），由 `useHealth()` 驱动，落点与文案见 §4.2——这样「错误红」只留给真正的错误。
## 9. 文案语气规范
### 9.1 规则
第二人称「你」，不说「您」、「用户」；平实陈述事实与下一步动作，不抒情、不承诺效果、不安慰式收尾；不说教，不出现「请珍惜」「思念」「逝去」这类情绪引导；一句话最多一个动作，且每句都能推出下一步（换一张 / 勾选 / 点确认 / 等一会儿 / 下载）；不出现技术词 `prompt` / `锚点` / `token` / `API` / `候选`（对外统一说「这几张」）；进度只用定性描述，不用数字倒计时、不用「最后 30 秒」。
### 9.2 示例文案（每类一句，完整文案见 `pages/P01-上传与身份确认.md`–`pages/P03-结果历史与下载.md`）
首页主标题 `把旧照片交给我们，让他出现在没拍过的地方。` ／ 身份确认页主问句 `这是他吗？` ／ 年代选择页问句 `想让他出现在哪个年代？` ／ 生成中 `正在生成，一般要一分钟左右。可以先去做点别的。` ／ 超时 `还在处理，可以先去别处看看。` ／ 历史页空态 `还没有记录。上传一张旧照片就能开始。` ／ 删除确认 `删掉之后就找不回来了，包括已经生成的这几张。`
### 9.3 禁用措辞（出现即返工）
`复活` · `重生` · `重获新生` · `让ta回来` · `ta` · `一键还原青春` · `年轻时的样子` · `完美的全家福` · `太棒了` · `奇迹` · `惊喜` · `修复`（本链路没有修复步骤，`README.md` §0.2；`docs/raw/AIGC_PRD.md` §8.1 的示例句「我们先把这张照片修清楚一点。」在前端不得使用）· `逝者` / `离开的人` / 任何殡葬语境词。
情感安全提示：首次进入生成结果页前必须展示一次温和说明，语义固定为 **「我们会尽力还原照片的样子，但这是基于照片的重建，无法替代真实。」**（措辞可调、语义不可改，且不得指涉 `逝者` / `离开的人`）；权威定义见 `spec/06-合规与风控.md` §9，触发口径为**每会话一次、模块级内存态**（`pages/P04-失败与情绪安全路径.md` §4）。
## 10. 对外接口与数据读写
前端只调用 `spec/03-接口契约.md` §3 列出的端点（与 §5.1 路由表逐一对应），不新增端点、不新增字段；响应类型全部从 `src/shared/types.ts` 引入，对齐 `API-02`。**前端不直读数据库**，不读 `promptPack` / `spacePack` / `constraintPack` / `promptOverride`（`API-06`）。数据流：`src/shared/api-client.ts` → 页面 Client 组件 `useState`，无全局缓存层；唯一例外是 `useEraSceneConfig()` 的模块级 memory 缓存（`Map<string, EraSceneConfig>`，key 为响应的 `version`，不做 `localStorage` 持久化）。写操作 `POST /api/anchors`、`POST /api/anchors/:id/retry`、`POST /api/generations`、`POST /api/generations/:id/retry` 均非幂等：`await` 期间禁用按钮、不自动重投。`POST /api/generations` 预扣张数，成功后重拉 `GET /api/me` 刷新 `SiteHeader` 额度。
## 11. 配置与环境变量
前端**不新增任何环境变量，也不使用 `NEXT_PUBLIC_*`**（唯一清单见 `spec/08-本地开发指南.md` §4）。接触方式：`PROVIDER` 间接——只经 `GET /api/health` 的 `provider.mode` 显示小字（§4.2）；`SMS_PROVIDER` 间接——只判断 `POST /api/auth/code` 响应是否含 `devCode` 字段（§5.2）；`DEV_LOGIN_CODE`、`GENERATION_DEFAULT_COUNT`、`MAX_UPLOAD_MB`、`WATERMARK_DEFAULT`、`AIGC_IMPLICIT_MARKER`、`ID_VERIFY_PROVIDER`、`DATABASE_PATH`、`STORAGE_DIR`、`ARK_*`、`WORKER_*`、`JOB_TIMEOUT_SECONDS` 前端**均不读取**（前端不传 `count`，大小校验交给服务端返回 `FILE_TOO_LARGE`，结果页只读展示 `generation.params.watermark`）。
## 12. 测试要点
单元测试（A 层 `pnpm test`，vitest，fake timers；`hooks/__tests__/`、`components/__tests__/`）覆盖：`useJobPolling` 首帧立即请求、慢响应不叠加、终止态停排、超时后自动停但 `refreshNow()` 可续（`E2E-01` 前端段）；`ErrorNotice` 对全部错误码可渲染、未知 `code` 走 `INTERNAL`、`UNAUTHENTICATED` 为 `page` 形态 + 「去登录」（`API-01`、`API-03`）；`useHealth` 在 `worker.alive === false` 时产出上传页提示所需状态（`ERR-04`）；`useEraSceneConfig` 只发 1 次请求（`API-06`）；`/choose` 未选年代或场景时提交按钮置灰且不发起 `POST /api/generations`（`SEC-01`）；`tailwind.config.ts` 存在 §3.2 的 9 个语义色键与 §3.3 的 6 档字号键（Token 契约测试，防样式漂移）。手工：`pnpm check`（类型 + lint）零错误；`pnpm smoke` 后人工过 `/` → `/upload` → `/confirm` → `/choose` → `/result` → `/history`。检查项 ID 的权威定义见 `spec/07-验收标准.md`。

非目标另见 §1：不做响应式断点细化（本期只保证 375px 与 1280px 两个宽可用）、不做骨架屏动画（`animate-fade-in` 淡入即可）、不做无障碍专项（保留语义标签与轮询状态区 `aria-live="polite"`）；界面上的「AI 生成」角标与可见标识开关**本期不做**（无全局开关 UI、无角标组件，`spec/06-合规与风控.md` §4）。待定决策（结论记入对应 ticket 的 `## Comments` 后再实现）：`CODE_RATE_LIMITED` 按钮是否显示剩余秒数（本文件按「按钮可用性 ≠ 任务倒计时」允许，评审若认为仍属压迫感则改为只显示「稍等一下」）；结果图用 `<img>` 还是 `next/image` + `unoptimized`；是否补 Playwright（本期前端交互正确性靠 vitest + 人工过流程）。
