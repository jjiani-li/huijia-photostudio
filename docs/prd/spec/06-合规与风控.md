## 1. 职责与边界
### 1.1 做什么
把"生成真人影像"的五类义务固定到**表、列、端点、文件**上（§2 总表）：① 隐式标识（§3）② 授权声明与留痕（§5.1）③ 实名门槛（§5.2）④ 彻底删除与不用于训练（§6）⑤ 内容审核（§7）；另有两条贯穿性约束：**额度与限流**（§8）、**措辞禁令**（§9）。

### 1.2 明确不做什么
- ❌ **不做真实身份核验**：不接身份证联网核验、不做人脸比对、不做手机号实名核验；本期的"实名"只是本地门槛（§5.2），不得描述成"真实身份核验"，也不得把验证码登录（`SMS_PROVIDER=console`）称作实名。
- ❌ **不做投诉受理与下架通道**（§10 说明留了什么）、**不做人工审核后台**（`verdict='review'` 等同放行并留痕，`modules/M07-生成后复核与内容审核.md` §1.2）、**不做金额计费**（只有 `usage_counters` 计数，`spec/01-领域模型与数据库.md` §6）。
- ❌ **不做可见标识开关 UI**（§4）、**不做分享功能**（因此不存在"分享到目标平台时补充平台侧可见标识"的实现）。
- ❌ 不新增表；除 §5.2 实名所需的 `users` 三列外不加列，其余落点复用既有结构（唯一其他例外是 `audit_logs.action` 增加一个取值，见 §3.3）。

## 3. 隐式标识（必须落代码）
### 3.1 唯一产物：`mark.ts`
依据《人工智能生成合成内容标识办法》，生成合成内容须写入**隐式标识**（文件元数据中的生成合成内容属性信息），**必须写入**，不是可选项。唯一产物：

```ts
// src/server/images/mark.ts
export const AIGC_MARKER = 'AIGC:service=home-photo-studio;model=doubao-seedream-5-0-lite-260128;v=1';
/** 只在 kind='generated' 的输出上调用；失败判定见 §3.4。 */
export async function markGeneratedImage(buf: Buffer, format: 'png' | 'jpeg'): Promise<{ marked: Buffer; implicit: boolean }>;
```

`AIGC_MARKER` 是**纯 ASCII**（含中文会让 PNG `tEXt` 与 EXIF `UserComment` 的字节串语义产生歧义，`CMP-01` 也无法逐字符比对），必须含 `AIGC` 字面量与 `service=`；模型名与 `spec/08-本地开发指南.md` 的 `ARK_IMAGE_MODEL` 默认值必须一致，换模型时同批更新（`CMP-01` 断言这一致性）。

### 3.2 按格式的写入位置
| 格式 | 写入位置 | 实现 |
|---|---|---|
| `png`（本期固定） | 新增 `tEXt` 块，关键字 `AIGC`，值 `AIGC_MARKER` | 手工插入 chunk：`length(4) + "tEXt"(4) + keyword\0text + CRC32(4)`，插在 IHDR 之后、IDAT 之前 |
| `jpeg` | `EXIF IFD0.ImageDescription` 与 `IFD3.UserComment` | `sharp(buf).withMetadata({ exif: { IFD0: { ImageDescription: AIGC_MARKER }, IFD3: { UserComment: AIGC_MARKER } } })` |

插入 PNG chunk 需 CRC-32（PNG 规范 §5.5，多项式 `0xEDB88320`）：`zlib.crc32` 可用则直接用，否则查表实现。**这是本文件唯一需要手写二进制处理的点，必须配单元测试**（§12.1）。

> **与 `modules/M02-预处理与质量评分.md` §5 的禁令不冲突**：M02 禁 `.withMetadata()` / `.keepMetadata()` 针对的是**输入归一化**路径（源图必须剥离 EXIF，见总表第 12 项）；`mark.ts` 只作用于 `kind='generated'` 的输出，方向相反、对象不同。**不得因本条而放开 M02 的禁令。**

### 3.3 调用点与服务端标识记录
调用点唯一：**生成结果转存时**（`modules/M06-生成编排.md` §5 第 3 步），顺序固定：

```
上游 data[].url → 下载 → 探宽高（`probeImage()`；失败分支见 `modules/M01-照片资产与存储.md` §6.4）→ markGeneratedImage() → LocalStorageProvider 写 .tmp → rename
  → INSERT photos(kind='generated', bytes=marked.length)
  → INSERT audit_logs(action='photo.mark', target='photo:<id>')
```

- `photos.bytes` 必须取**标识写入之后**的长度，否则 `E2E-06`（磁盘字节数与 `bytes` 一致）会失败。
- `audit_logs(action='photo.mark')` 是"服务端标识记录"，**无论是否真的写入了元数据都要写**：成功 `{ implicit: true, format: "png", marker: "<AIGC_MARKER>" }`；按配置不写 `{ implicit: false, mode: "off", format: "png" }`；写入失败 `{ implicit: false, mode: "failed", format: "png", reason: "<错误摘要>" }`。`mode` 三态不可合并，否则无法区分"合规地关掉了"与"写挂了"。
- 需在 `spec/01-领域模型与数据库.md` §3.14 的必记 `action` 清单中增加 `photo.mark`。

### 3.4 写失败不阻断交付
标识写入失败**不**把任务置为失败：记 `mode: "failed"` 的审计行 + `logger.warn`，照常交付并落盘**未标记**的文件——元数据写入失败不应让用户拿不到图，但必须留痕，由 `CMP-03` 在验收中要求 `mode='failed'` 为零。

### 3.5 开关
| 变量 | 默认 | 语义 |
|---|---|---|
| `AIGC_IMPLICIT_MARKER` | `true` | 是否为生成图写入隐式标识元数据 |

**生产环境必须为 `true`**；允许本地设为 `false` 做"看起来像不像真照片"的对比。该开关**只控制元数据写入**，不影响审计行（§3.3）。

## 5. 授权、留痕与实名
### 5.1 授权与留痕
口径与字段细节以 `modules/M04-身份确认与授权.md` 与 `spec/01-领域模型与数据库.md` §3.11 为准；本文件只固定四条不可动摇的规则：

1. **两项 scope 缺一不可**：`photo_usage`（对照片中人物拥有合法使用权）与 `family_agreement`（已获其他近亲属同意）；`spec/03-接口契约.md` §3.3 的 `consents` 数组必须同时含两项，否则 `400 INVALID_PARAM`。
2. **确认在生成之前，且是硬前置**：未确认 → `409 ANCHOR_NOT_CONFIRMED`；已确认但授权被吊销 → `403 CONSENT_REQUIRED`。判定顺序固定为"先确认、后授权"（`modules/M04-身份确认与授权.md` §5.3）。
3. **consents 行永不物理删除、`agreed_at` 永不改写，失效只有 `revoked_at` 一个来源**：显式吊销入口（`modules/M04-身份确认与授权.md` §5.5）与删除级联（§6.2、`modules/M08-账号历史与彻底删除.md` §3.3）**都写 `revoked_at`、都不删行**——吊销是法律事件，删除是清理，两者都不删 `consents` 行；"同意 → 吊销 → 再同意"必须留下完整轨迹。删除动作本身另写 `audit_logs`（`photo.delete` / `anchor.delete`），据此与吊销在审计上可区分。
4. **`consents` 历史行永不删改**：`agreed_at` 不可改写，重新确认插入新行；授权留痕依附的锚点记录（`consents.anchor_id`）因此必须保持当时的样子——这是"重新提取锚点 = 插入新行、不覆盖"的合规理由之一。

### 5.2 实名（生成前门槛）
字段与端点细节以 `modules/M08-账号历史与彻底删除.md` §2 与 `tickets/T19-实名、用户资料与生成门槛.md` 为准；本文件固定三条规则：

1. **三个字段（列名）**：`users.real_name`、`users.id_hash`（**只存哈希，不存明文**）、`users.verified_at`；`verified_at` 非空即视为已实名。本节规定的是**数据库列名**；实名的对外状态字段由 `spec/03-接口契约.md` 以 camelCase 定义，**列名不得泄漏到任何 API 响应**。
2. **生成是硬前置**：`POST /api/generations` 在发起任何生成动作之前校验已实名，未实名返回 `REALNAME_REQUIRED`（与 `ANCHOR_NOT_CONFIRMED` 同一处理方式：硬拒绝，无降级路径、不自动重试）。
3. **核验走 `IdVerifyProvider` 抽象**（与既有 Storage / SMS / Ark 三个 Provider 抽象一致）：**本地实现 = 格式校验 + 唯一性校验**，生产实现留空位。检查项 `RN-01`–`RN-04`（归属 `modules/M08-账号历史与彻底删除.md`），端点检查项 `API-09`。

**「本地实现 / 生产必须补」对照表** —— 本地实名 ≠ 真实身份核验：

| 能力 | 本地实现（本期交付） | 生产必须补（上线前） |
|---|---|---|
| 姓名 | 非空 + 长度与字符格式校验 | 与核验服务返回的姓名一致 |
| 证件号 | 格式校验（长度、校验位）+ 唯一性校验（`id_hash` 唯一） | 联网核验真实性；失效证件号的拒登处理 |
| 真实性一致性 | **不做**：本地不接触任何权威数据源 | 对接核验服务（`IdVerifyProvider` 的生产实现） |
| 一号多账号 | **不拦**：唯一性校验只保证同一 `id_hash` 不重复入库 | 按平台规则处理同一证件的多账号 |
| 绕过、频次与审计 | 无防护：本地接口可直接调用；落 `users.verified_at` 并在同一事务写 `audit_logs(action='auth.realname')`（`RN-04`） | 频次限制、风控与人工复核通道；核验流水（请求方、时间、结论）纳入审计 |

## 6. 彻底删除与隐私
### 6.1 两级删除
| 级 | 触发 | 效果 |
|---|---|---|
| 软删 | `DELETE /api/photos/:id` / `/api/anchors/:id` | 写 `deleted_at`，立刻从 `/api/history` 与文件端点消失；写 `audit_logs(action='photo.delete')` |
| 物理清理 | purge worker 定时执行 | 删磁盘文件 → 删 `generation_results` → 物理 `DELETE photos` 行；写 `audit_logs(action='photo.purge')` |

阈值与批处理常数（`PURGE_GRACE_MINUTES=10`、`PURGE_BATCH_SIZE=200`、`PURGE_INTERVAL_MS`）见 `modules/M08-账号历史与彻底删除.md` §5.3，**本文件不重复数值**。

### 6.2 删除的完备性
删除一张 `original` 图时，必须连带处理：`preprocessed` 派生图、引用该派生图的 `identity_anchors`、这些锚点下的 `generations` 与 `generation_results`、这些生成任务产出的 `photos(kind='generated')` 及其磁盘文件；命中被删锚点的 `consents` 行**写 `revoked_at`（不删行）**。完整规则表见 `modules/M08-账号历史与彻底删除.md` §3.3，验收为 `DEL-01`–`DEL-04`。**"彻底"的判定标准**：删除后 `storage/` 下不存在任何未被 `photos` 行引用的残留文件，且 `photos` 行本身也不再存在；仅软删不算彻底。

### 6.3 最小权限与不落公网
- 源图与生成图只存本地 `./storage/`，库里只存 `storage_key`；**任何表、任何响应都不含公网图片地址**（`spec/00-总纲.md` §6.2）；文件读取走受控端点 `GET /api/photos/:id/file`，先校验 `user_id` 归属，越权返回 `404`（不返回 `403`，避免资源探测；`API-04`）。
- 上游返回的签名临时 URL（86400s 有效期）只在上游响应中存在，**必须立即转存并丢弃**，不得写入数据库。
- 登录标识符在响应中脱敏（含 `*`，`API-05`）。

### 6.4 不用于模型训练
**承诺：用户上传的照片与生成结果不用于训练任何模型。** 该承诺落在两处：① 本项目不实现任何"数据回流/样本导出"通道，代码中不存在把 `./storage/` 内容上传到训练侧或标注侧的路径；② 该承诺出现在用户可见的使用说明中。**诚实边界**：上游方舟侧是否将请求用于训练，由平台条款决定，不受本项目控制，因此对外表述只能是"我们不会用你的照片训练模型"，**不得**表述为"你的照片不会被用于任何训练"；此点须在实现注释与用户可见说明中同时体现。

## 7. 内容审核
三阶段的触发点、判定对象、落库行、reject 路径与失败语义，**全部以 `modules/M07-生成后复核与内容审核.md` §5.6 为准**。本文件固定三条不可动摇的规则：

1. **审核是硬约束，不放过未审核的结果**：审核调用超时/报错时按 `spec/03-接口契约.md` §2.2 自动重试 1 次，仍失败则任务 `failed` 并写对应 `error_code`——**不得**把"没拿到结论"当作"通过"（这与年代复核"失败就留空"是刻意的不对称）。
2. **内容审核判定（`moderationVerdict`）为 `reject` 时必须留痕**：额外写 `audit_logs(action='moderation.reject')`，`meta_json` 记 `{stage, targetId, reason}`；三个阶段的 `reject` 都适用。
3. **`review` 等同放行**：三个阶段一致，仅留痕，无人工处置通道。

**诚实说明**（必须写进实现注释）：本期用户输入面极小，`prompt` 阶段真正能拦到的只有"模型从照片里读到的违规文字"，**是防线不是主力**；主力是 `upload` 与 `result` 两个对着真实图像的阶段。

## 8. 风控与额度
| 手段 | 规格 | 落点 |
|---|---|---|
| 单次生成张数上限 | `count ∈ {2,3,4}`，超出 `400 INVALID_PARAM` | `spec/03-接口契约.md` §3.5 |
| 每日额度与预扣回滚 | 判断读 `users.daily_image_quota`、计数写 `usage_counters(user_id, day)`，超出 `429 QUOTA_EXCEEDED`；入队时预扣 `count`，worker 内未产出的张数回滚 | `security/`、`modules/M06-生成编排.md` §5 |
| 限流、并发与实名门槛 | 同 `identifier` 60 秒内二次发码 → `429 CODE_RATE_LIMITED`；已有非终态生成时再次发起 → `409 GENERATION_IN_PROGRESS`；未实名 → 见 §5.2 | `modules/M08-账号历史与彻底删除.md` §5.1、`modules/M06-生成编排.md` §5 |
| 异常调用发现 | **本期无自动风控**：不做行为分析、不做黑名单、不做频率熔断 | 留审计行（`generation.create` / `auth.login`），由人工查库 |

**明确不做**：不基于 IP 或设备指纹做风控，不做自动封禁。本期风控的全部产出是**可事后审计的记录**，不是自动拦截。

## 9. 措辞与情感安全
### 9.1 禁用措辞（出现即返工）
以 `pages/P00-设计基准与路由.md` §9.3 为唯一清单：`复活` · `重生` · `重获新生` · `让ta回来` · `ta` · `一键还原青春` · `年轻时的样子` · `完美的全家福` · `太棒了` · `奇迹` · `惊喜` · `修复` · `逝者` / `离开的人` / 任何殡葬语境词。

本文件补充一条口径：**`修复` 是禁用词，因为在产品语境里它是虚假承诺**——本链路没有修复步骤（`README.md` §0.2），任何"修复""变清晰""还原清晰度"的表述都在承诺一件系统不做的事；同理禁止对修复能力的任何暗示性描述。

### 9.2 首次使用的情感安全提示
首次进入生成结果页前，必须展示一次温和说明，语义固定为：**"我们会尽力还原照片的样子，但这是基于照片的重建，无法替代真实。"** 措辞可调，语义不可改，且不得使用 `逝者` / `离开的人` 这类指涉。

### 9.3 与"不做"清单的呼应
不做视频生成、不做语音合成、不做数字人对话、不做"让照片动起来"（`spec/00-总纲.md` §6.2）。这不只是范围问题：上述形态会显著放大心理伤害与合规风险，是**合规决定**，不是排期决定。

## 12. 测试要点
### 12.1 单元测试（A 层：`pnpm test`，vitest）
以下 7 项是 **A 层单元测试（`pnpm test`／vitest）**，不是 `pnpm check:acceptance` 检查项；ID 族为 `MARK-`（`mark.ts` 是本项目隐式标识的唯一产物），归属 `docs/prd/spec/06-合规与风控.md`，由 `docs/prd/spec/07-验收标准.md` 登记。

- `MARK-01`：`markGeneratedImage(pngBuffer, 'png')` 后用 PNG 解析读回，存在关键字 `AIGC` 且值**逐字符等于** `AIGC_MARKER`
- `MARK-02`：输出的 IHDR / IDAT 数据**未被修改**——`sharp(out)` 的宽高与 `sharp(in)` 一致，且像素 sha256 相等
- `MARK-03`：`markGeneratedImage(jpegBuffer, 'jpeg')` 后 `sharp(out).metadata().exif` 可解析出 `ImageDescription === AIGC_MARKER`
- `MARK-04`：tEXt chunk 的 CRC-32 正确——篡改任意数据字节后读回校验失败（证明 CRC 真的被计算，而不是填零）
- `MARK-05`：传入已含 `tEXt` 块的 PNG，输出仍只有**一个** `AIGC` 关键字块（幂等，不重复插入）
- `MARK-06`：`AIGC_MARKER` 为纯 ASCII（`/^[\x20-\x7E]+$/`）且包含 `AIGC` 与 `service=`
- `MARK-07`：`AIGC_MARKER` 中的模型名与 `ARK_IMAGE_MODEL` 默认值一致

### 12.2 契约与链路检查（B 层：`pnpm check:acceptance`）
| ID | 断言 |
|---|---|
| `CMP-01` | `E2E-01` 产出的每张 `kind='generated'` 文件，都能读回 `AIGC` 标识且值等于 `AIGC_MARKER`；同批的 `kind='original'` / `'preprocessed'` 文件**读不到**该标识 |
| `CMP-02` | 扫描 `app/`、`components/`、`src/` 的全部字符串字面量与 JSX 文本，§9.1 的禁用词**0 命中**（`修复` 一并命中即失败） |
| `CMP-03` | 本次运行产生的 `audit_logs(action='photo.mark')` 行数 == 生成的图片张数，且**没有** `meta_json.mode='failed'` 的行 |

与既有检查项的分工：`SEC-01`–`SEC-08` 管授权与额度，`DEL-01`–`DEL-04` 管删除，`RN-01`–`RN-04` 管实名（归属 `modules/M08-账号历史与彻底删除.md`），`CMP-01`–`CMP-05` 只管标识与措辞，不重复覆盖。
