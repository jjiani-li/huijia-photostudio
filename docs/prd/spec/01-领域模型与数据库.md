> **层级**：规范层 · 全局约束（不可违背）
> **上游**：`docs/raw/AIGC_PRD.md` §5、§9、§10 ／ `spec/00-总纲.md` §3、§5、§6
> **下游**：`spec/02-schema.sql`、`modules/M01-照片资产与存储.md`–`modules/M09-图片反推提示词.md`、`pages/P01-上传与身份确认.md`–`pages/P03-结果历史与下载.md`、`tickets/T02`

> 本文件是**数据层唯一权威**；`spec/02-schema.sql` 是其机器可读落地（首个迁移），冲突时以本文件为准并修 `spec/02-schema.sql`。技术选择为 SQLite + `better-sqlite3` + 手写 SQL 迁移、不用 ORM。

## 1. 实体关系

```
users ─┬─< sessions ／ login_codes ／ consents ／ usage_counters ／ content_reviews ／ audit_logs
       ├─< photos ──< photos(source_photo_id: preprocessed → original)
       ├─< identity_anchors >── photos(input_photo_ids / preprocessed_photo_id)
       ├─< generations ──< generation_results >── photos(kind=generated)
       └─< prompt_reverse_jobs >── photos(source_photo_id)

eras ──< era_scene_profiles >── scenes ；eras ／ scenes ／ era_scene_profiles ──< generations >── identity_anchors
```

## 2. 状态机

### 2.1 `identity_anchors.status`（F1 提取任务）
| 状态 | 含义 / 迁移条件 |
|---|---|
| `queued` | 初始态；`running` 的 `started_at` 超时（worker 崩溃）→ 回退到这里 |
| `running` | worker 取任务后写 `started_at` |
| `succeeded` | `anchor_text` / `features_json` 必须非空 |
| `failed` | `error_code` 必须非空 |
迁移：重新提取 / 重试(retry) = **插入新行**且 `attempt = 旧 + 1`，旧行保留不覆盖；**只有 `succeeded AND confirmed_by_user = 1` 才能用于生成**。
### 2.2 `generations.status`（F2 生成任务）
| 状态 | 含义 / 迁移条件 |
|---|---|
| `queued` | 初始态；`running` 的 `started_at` 超时（worker 崩溃）→ 回退到这里 |
| `running` | worker 取任务后写 `started_at` |
| `succeeded` | `requested_count` 张全部成功 |
| `partial` | 至少 1 张成功、至少 1 张失败 |
| `failed` | 0 张成功 |
迁移：`succeeded` / `partial` 至少有 1 行 `generation_results`；`attempt` 支持"失败自动重试 1 次"，超过 1 次则交用户"再来一组" = 新建 `generations` 行继承上一层全部设定，**绝不覆盖旧任务**。
### 2.3 `photos` 生命周期
| 状态 | 含义 / 迁移条件 |
|---|---|
| active（`deleted_at IS NULL`） | 默认态；用户删除 → `deleted_at = now`，立即从所有读取路径消失 |
| 已软删 | 清理 worker：`deleted_at` 早于 N 分钟 → 删磁盘文件 + 物理删除行 |
迁移：级联语义在 repository 层实现，不启用 SQLite 外键级联。删 `original` 图时，其 `preprocessed` 派生图、引用该派生图的 `identity_anchors`、这些锚点下的 `generations` / `generation_results`、及其产出的 `photos(kind='generated')` 全部处理；`consents` 中 `anchor_id` 命中的行写 `revoked_at`；删锚点**不动**原图与预处理图。
各表删除方式：`photos` 软删除 + 延迟物理清理（磁盘删除不可逆）；`identity_anchors` / `generations` / `generation_results` 立即物理删除（无 `deleted_at`，`anchor_text` / `prompt` 不宜长期留存）；`consents` 吊销不删行（授权留痕）。完整规则见 `modules/M08-账号历史与彻底删除.md` §3.3。
### 2.4 `prompt_reverse_jobs.status`（F4 图片反推任务）
| 状态 | 含义 / 迁移条件 |
|---|---|
| `queued` | 初始态；`running` 的 `started_at` 超时（worker 崩溃）→ 回退到这里，`attempt` 不变 |
| `running` | worker 取任务后写 `started_at` |
| `succeeded` | `result_json` / `result_prompt` 必须非空 |
| `failed` | `error_code` / `error_message` 必须非空 |
迁移：本表只做一次性反推，不写入 `identity_anchors`。超时判定、回收与"仅对瞬时错误自动重试 1 次"的规则与 `identity_anchors` / `generations` 一致，见 `spec/03-接口契约.md` §2.2（依赖本表的 `started_at` 与 `attempt` 两列）。

## 3. 表字典

> 约定：主键统一 `INTEGER PRIMARY KEY AUTOINCREMENT`（除 `eras.code` 用业务主键）；**所有时间戳为 `TEXT`，UTC ISO-8601**（如 `2026-09-17T15:07:42.000Z`）；**所有 JSON 列名为 `*_json`，类型 `TEXT`**（写入前用 zod 校验）；布尔用 `INTEGER` 0/1；`storage_key` 一律是**相对存储根的相对路径**，绝不存公网 URL。

## 4. 设计决策

- `identity_anchors` 单表兼作提取任务，不拆 `anchor_jobs`：任务与锚点 1:1，拆表只多一次 join。
- `generations` 兼作生成任务，不引入通用 `jobs` 表：本期只有提取、生成两种异步操作。
- `storage_key` 指向本地文件、无对象存储：本地可跑优先，`StorageProvider` 抽象保留替换能力（`modules/M01-照片资产与存储.md`）。
- 时间戳存 TEXT/ISO-8601，不用 INTEGER 毫秒：可直接用字符串比较与 `date()`。
- 配置资产（`eras` / `scenes` / `era_scene_profiles`）落库而非代码常量：上游要求"新增年代或场景无需发版"，且 prompt 需版本化与 A/B。
- 不启用 SQLite 外键级联删除：会绕过"软删除 + 延迟物理清理"。
- 重新提取 / 再来一组 = 插入新行而非更新原行：可复现、可追溯，旧结果不可被覆盖。

## 5. 迁移与种子策略

### 5.1 迁移
- 目录 `migrations/`：`001-init.sql`（内容即 `spec/02-schema.sql`）、`002-xxx.sql`…
- `migrate.ts`：建 `schema_migrations(version TEXT PRIMARY KEY, applied_at TEXT)`，按文件名顺序执行未应用迁移，**每个文件单事务**；只前进不后退，重置即删库重跑。
### 5.2 种子
