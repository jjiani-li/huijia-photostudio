## 1. 产品定义

### 1.1 一句话

> 上传一张（模糊的）旧照片，提取人物的**身份锚点**，再按用户选择的【年代 × 场景】生成该人物在**全新场景**下的真实感照片。

### 1.2 这是一个什么产品，不是什么产品

| 是 | 不是 |
|---|---|
| **特征保真**的面孔复用：同一个人，出现在他从未拍过的新场景里 | ❌ 老照片修复/超分/去划痕（那是 F1 以前的错误定位） |
| **年代质感重建**：生成结果要"像是那个年代拍出来的" | ❌ AI 换脸、数字复活、让照片动起来 |
| 照片层面的"补拍"：把缺失的那张照片补上 | ❌ 视频生成、语音合成、数字人对话 |

### 1.3 为什么"修复"不是这个产品

旧照片的价值在于它是这个人的唯一证据：若第一步是"用 AI 把照片重画清楚"，后续所有生成图锚定的都是一张 **AI 想象的脸**，身份保真从根上断掉——所以第二步做的是**读**（提取特征），不是**画**（重建图像）。

### 1.4 三个不可让步的属性

1. **像他**——生成图必须逼近**旧照片里那个人**，不能被理想化、年轻化、美化；
2. **像那个年代**——色调、颗粒、光比、道具、服饰必须属于所选年代或更早；
3. **像拍出来的**——第一反应必须是"这是一张照片"，而不是"这是一张 AI 图"。

## 2. 目标用户

| 用户 | 特征 | 核心诉求 | 主要风险 |
|---|---|---|---|
| 主要用户 · 中青年子女（30–55 岁） | 替父母/自己整理旧照片，手机操作，不懂 AI | 让逝去的父亲重新出现在一张像样的照片里 | 生成结果"一眼 AI"→ 二次伤害 |
| 次要用户 · 年长亲属（55 岁+） | 由子女引导使用，对"假"极度敏感 | 全家福/生活照要"看着是真的" | 面部失真 → 直接否定整个产品 |
| 边界用户 · 影像修复从业者 | 批量处理 | 效果稳定、可控、可复现 | 无 |

**本期只为「主要用户」做设计**，其余两类不做专门适配。

## 3. 核心链路（权威版）

| # | 步骤 | 产出（落库载体） |
|---|---|---|
| ① | 上传旧图（1–5 张，jpg/png/heic） | `photos(kind=original)` |
| ② | 预处理与质量评分（归一化、方向/格式/尺寸统一、可读性评分；**不修复、不美化**） | `photos(kind=preprocessed)` + `quality_json`；不可用时告知"建议换一张"，不硬走 |
| ③ | 特征锚点提取（F1′）：多模态读图，显式防美化（写出皱纹深度/老年斑/皮肤松弛） | `identity_anchors(status=succeeded)` 的 `anchor_text` + `features_json` |
| ④ | 身份确认 + 授权（★ **强制节点**：用户必须点"这就是他"，并勾选授权确认） | `identity_anchors(confirmed_by_user=1)`、`consents` |
| ⑤ | 选择年代 × 场景（E1–E4 × S1–S5，低置信组合给温和提示） | `eras` / `scenes` / `era_scene_profiles` |
| ⑥ | Prompt 拼装：身份锚点 + 年代质感包 + 场景空间包 + 写实锚定 + 正向化年代约束 | `generations.prompt`（带版本号与 hash） |
| ⑦ | 生成（异步）：Seedream lite，参考图 = 预处理图，2–4 张候选 | `generations` + `generation_results` + `photos(kind=generated)` |
| ⑧ | 生成后复核：年代穿帮复核 + 年龄偏差估计 + 内容安全审核 | `generation_results.era_check_json` / `age_delta` |
| ⑨ | 挑选 / 再生成 / 下载：历史记录按链路展示，可"用同样设定再生成" | `generations.status`、`photos.deleted_at` |

**旁路（F4 · 图片反推提示词）**：任意旧照片 → 多模态读图 → 结构化描述 + 自然语言 prompt + **推荐的年代代号与场景 id**，用户可直接采纳，从链路第 ⑤ 步进入。它复用 ③ 的读图通路，但**不写入 `identity_anchors`**（见 `modules/M09-图片反推提示词.md`）。

**链路铁律**：

- ③④ 之间是**强制确认节点**。未确认的锚点不得用于生成（接口层直接拒绝，见 `spec/03-接口契约.md` 错误码 `ANCHOR_NOT_CONFIRMED`）。
- 生成前**必须已实名**，未实名直接拒绝（错误码 `REALNAME_REQUIRED`）。
- ⑥ 的 prompt 必须由 `spec/05-Prompt工程.md` 的模板拼装，**不得在业务代码里内联 prompt 字符串**。
- ⑦ 的每一次调用都必须把 prompt、参考图 id、锚点 id、年代、场景、模型、size **全部落库**。这是**"可重新提交复现"**的依据，**不承诺逐位相同的出图**：`generation_results.seed` 只在**上游回传时**记录、不作为复现依据，"`seed` 是否被上游接受并回传"属未验证能力（与另外两条一起登记在 `spec/07-验收标准.md` §6，挂起处见 `tickets/T10-Seedream生图调用与结果转存.md` 的 `## Comments`）。

## 4. 真实感定义（最高优先级约束）

> 与 `docs/raw/AIGC_PRD.md` §2 一致，**任何功能与之冲突时以本节为准**。

### 4.1 三类目标质感

| 年代 | 参考样态 |
|---|---|
| E1 · 50–70 | 黑白/极轻泛黄胶片扫描：颗粒、划痕灰点、四角暗角、高反差 |
| E2 · 80–90 | 彩色胶卷：偏青或偏暖红、明显彩色颗粒、闪光灯直打 |
| E3 · 00 | 早期数码：略灰、偏冷/偏绿、数码噪点、低动态范围、闪光灯压脸 |
| E4 · 10–20 | 智能手机：通透、白平衡基本准确、构图随意、轻微算法痕迹 |

### 4.2 必须保留（Preserve）

- 面部身份特征：五官比例、痣、疤、牙齿形态、发型、脸型轮廓、**年龄痕迹**；
- 皮肤真实纹理：毛孔、细纹、法令纹、老年斑、肤色不均；
- 年代感：色调偏移、颗粒/噪点、轻微对焦不实、镜头畸变、闪光灯痕迹。

### 4.3 严禁出现（红线）

| 类别 | 禁止项 |
|---|---|
| 皮肤 | 塑料感、蜡像感、过度磨皮、零毛孔 |
| 质感 | 3D 渲染感、CG、插画风、HDR 过度、锐化过度 |
| 面部 | 五官完美对称、AI 高光、牙齿过白过齐 |
| **年龄** | **把老人磨年轻**（皱纹、老年斑、皮肤松弛被抹平） |
| 背景 | 过饱和、与年代不符的现代物件、虚化逻辑错误 |
| 整体 | "一眼 AI"的精致感、影楼摆拍感 |

### 4.4 可度量目标

| 指标 | 定义 | 目标 |
|---|---|---|
| 面部相似度 | 生成图与源照片人脸特征向量余弦相似度 | ≥ 0.55 |
| 年龄保真度 | 自动估计的年龄偏差 \|age_delta\| | ≤ 5 岁 |
| 年代一致性 | 评审判断"像那个年代拍的"通过率 | ≥ 70% |
| 年代穿帮率 | 生成图出现该年代之后物件的比例 | ≤ 3% |
| 盲测真实率 | 生成图被误判为真实老照片的比例 | ≥ 60% |
| AI 感投诉率 | 用户主动反馈"太假/塑料感"占比 | ≤ 5% |

前两项与年代穿帮在 MVP 内**自动化检查**（见 `spec/07-验收标准.md`）；后三项依赖人工评审样本集，MVP 只交付检查工具与流程（`pnpm check:blind`）。

## 7. 成功判据

MVP 交付时，必须能在本地跑通 `pnpm dev`（前端 + 后端）与 `pnpm worker`（异步任务 worker，另一个终端，缺一不可），并且：

1. 用 `docs/老照片/` 下的照片作为输入走到生成出图（`PROVIDER=mock` 离线可复现；`PROVIDER=real` 真实出图需人工确认）；
2. 数据库里能查到完整链路记录：`photos → identity_anchors → generations → generation_results`；
3. `pnpm check:acceptance` 全绿（`PROVIDER=mock`，见 `spec/07-验收标准.md`）；
4. 未实名或未确认锚点调用生成端点分别被拒绝（`REALNAME_REQUIRED`、`ANCHOR_NOT_CONFIRMED`）。
