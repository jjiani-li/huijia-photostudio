# 03 · 接口契约

> **层级**：规范层 · 全局约束（不可违背）
> **上游**：`docs/raw/AIGC_PRD.md` §3、§4、§9 ／ `spec/00-总纲.md`、`spec/01-领域模型与数据库.md`
> **下游**：`modules/M01-照片资产与存储.md`–`modules/M09-图片反推提示词.md`、`pages/P00-设计基准与路由.md`–`pages/P03-结果历史与下载.md`、`tickets/`

> 前后端唯一约定，冻结后两端可并行开发。后端实现为 Next.js App Router Route Handlers（`app/api/**/route.ts`）；前端只通过本文件列出的端点取数据，**不得直接读数据库**。

## 1. 通用约定

### 1.1 传输

| 项 | 约定 |
|---|---|
| Base | 同源 `/api`，无跨域配置 |
| 编码 | 请求与响应均为 `application/json; charset=utf-8`（上传与取图为例外） |
| 字段命名 | **`camelCase`**；数据库的 `snake_case` 只在 repository 层出现，不得泄漏到 API |
| 时间 | ISO-8601 UTC 字符串，如 `2026-09-17T15:07:42.000Z` |
| 未知字段 | 服务端忽略；前端必须容忍响应中出现未声明字段 |

### 1.2 鉴权

- 登录成功后服务端下发 cookie：`sid=<base64url(32B)>`，属性 `HttpOnly; SameSite=Lax; Path=/; Max-Age=2592000`；服务端只存 `sha256(token)`（`sessions.token_hash`），明文不落库。
- 受保护端点在 handler 开头调用 `requireUser()`，失败返回 `401 UNAUTHENTICATED`；免登录端点仅 `POST /api/auth/code`、`POST /api/auth/login`、`GET /api/health`。
- 登出：`POST /api/auth/logout` 写 `sessions.revoked_at` 并清 cookie。

### 1.3 错误响应（统一 envelope）

```json
{ "error": { "code": "QUOTA_EXCEEDED", "message": "今天的生成额度用完了，明天再来吧", "details": {} } }
```

- HTTP 状态码语义与 `code` 对应（见 §5 错误码总表）。
- `message` 是**可直接展示给用户的中文文案**，语气遵循 `pages/P00-设计基准与路由.md` §9。
- `details` 仅用于开发调试，前端不应依赖（例外：`INVALID_PARAM` 的 `details.fields` 与 `ANCHOR_LOW_QUALITY` 的 `details.quality`）。

### 1.4 成功响应

**不使用 envelope**，直接返回业务对象（如 `{ "photo": {...} }`）；列表端点统一使用 `{ items, nextCursor }` 形状。

### 1.5 幂等与并发

| 端点 | 语义 |
|---|---|
| `POST /api/auth/code` | 非幂等；同 `identifier` 60 秒节流 |
| `POST /api/photos` | 非幂等；同用户同内容 `sha256` 复用已存在行（不重复落盘） |
| `POST /api/anchors` | **非幂等**：每次调用创建新行。前端必须在请求期间禁用按钮 |
| `POST /api/anchors/:id/retry` | **非幂等**：创建新行，`attempt = 旧 + 1` |
| `POST /api/generations` | 非幂等。同一用户同时只允许 1 个非终态生成任务，否则 `409 GENERATION_IN_PROGRESS` |
| `POST /api/generations/:id/retry` | 非幂等：创建新行并继承全部设定 |
| `DELETE *` | **幂等**：重复删除返回 200 |

## 2. 异步任务与轮询协议

异步操作共三个，共用同一套协议：**锚点提取**（§3.3）、**生成**（§3.5）、**反推提示词**（§3.8）——`status: queued → running → succeeded | failed`（生成另有 `partial`）。

### 2.1 轮询规则（前端）

| 任务 | 端点 | 间隔 | 超时 | 终止条件 |
|---|---|---|---|---|
| 锚点提取 | `GET /api/anchors/:id` | 1.5s | 90s | `status ∈ {succeeded, failed}` |
| 生成 | `GET /api/generations/:id` | 2s | 180s | `status ∈ {succeeded, partial, failed}` |
| 反推提示词 | `GET /api/prompt-reverse-jobs/:id` | 1.5s | 90s | `status ∈ {succeeded, failed}` |

超时后前端展示"还在处理，可以先去别处看看"，**继续保留轮询按钮**；不得用 `setInterval` 叠加请求，必须等上一次响应回来再排下一次。

### 2.2 超时与回收（后端）

回收阈值、超时与自动重试次数的**唯一事实源**是 `spec/04-技术基线与目录结构.md` §4.6，本节不复述数字与规则，只记调用方可见的后果：

- 任务被回收后回到 `queued` 会被再次执行，`attempt` 不变，因此**同一个 `id` 可能被发现过两次 `running`**；
- `running` 超过超时阈值视为失败；仅瞬时错误（`PROVIDER_TIMEOUT`、`PROVIDER_ERROR`、`STORAGE_ERROR`）自动重试一次，之后不再自动重试，用户须走新建行重试；
- 用户侧"再来一组"/"重新提取"永远走**新建行**，不覆盖历史。

### 2.3 worker 存活探测

心跳文件的写法与存活阈值（写频率、判死窗口）的**唯一事实源**是 `spec/04-技术基线与目录结构.md` §4.6。本节的接口侧约定：`GET /api/health` 读心跳文件 mtime 并返回 `worker.alive` / `worker.lastSeenAt`；前端据此在上传页顶部显示提示"后台还没启动，图片处理会卡住"，并给出命令 `pnpm worker`。

## 3. 端点详表

> 各端点的请求/响应字段名以下列为准；字段类型见 §4。

### 3.1 账号与会话

**`POST /api/auth/code`** — 请求 `{ identifier, channel? }`（`channel` 取 `phone` | `email`，缺省时按 `identifier` 是否含 `@` 自动判定）；响应 `200` `{ sent, expiresInSec, devCode? }`。`devCode` **仅在 `SMS_PROVIDER=console` 时出现**，生产实现必须不返回。同 `identifier` 60 秒内已有未消费记录 → `429 CODE_RATE_LIMITED`。

**`POST /api/auth/login`** — 请求 `{ identifier, code }`；响应 `200` `{ user: User }` + `Set-Cookie: sid=...`。码不存在或已用 → `400 CODE_INVALID`；已过期 → `400 CODE_EXPIRED`；成功则写 `consumed_at`、`users.last_login_at`，首次登录自动建用户（`nickname` 默认 `用户{id 后 4 位}`）。

**`POST /api/auth/logout`** — 响应 `200` `{ ok: true }`。

**`GET /api/me`** — 响应 `200` `{ user: User, quota: Quota }`（`quota = { day, images, limit, remaining }`）；手机号/邮箱在响应中**必须脱敏**（`138****8000`）。

**`POST /api/me/realname`**（实名门槛，走 `IdVerifyProvider`）— 请求 `{ realName, idNumber }`；响应 `200` `{ realNameStatus: RealNameStatus }`。

- 写入 `users.real_name`、`users.id_hash`（`sha256(证件号)`，**只存哈希、不存明文**）、`users.verified_at`。
- 本地实现 = **格式校验 + 唯一性校验**；生产换真实核验通道（见 `spec/06-合规与风控.md` §5 的「本地实现 / 生产必须补」对照表）。
- `realName` / `idNumber` 为空或格式非法 → `400 INVALID_PARAM`（`details.fields`）；`id_hash` 已被其他用户占用 → `400 INVALID_PARAM`（`details.fields`）。

**`GET /api/me/realname`** — 响应 `200` `{ realNameStatus: RealNameStatus }`；未实名时 `verified=false`、`verifiedAt=null`、`realName=null`。

> 检查项：`API-09`、`RN-01`–`RN-03`（归属 `modules/M08-账号历史与彻底删除.md`，见 `tickets/T19`）。

### 3.2 照片资产

**`POST /api/photos`** — `multipart/form-data`，字段名 `file`；接受 `image/jpeg`、`image/png`、`image/webp`、`image/heic`；单文件 ≤ `MAX_UPLOAD_MB`（默认 20）。响应 `201` `{ photo: Photo }`。规则：写入 `storage/u<userId>/<uuid>.<ext>`；同用户内 `sha256` 命中未删除行则直接返回已有行（不重复落盘）；同一次请求调用**上传阶段内容审核**（唯一入口 `moderateUpload()`，见 `modules/M07-生成后复核与内容审核.md` §5.6）：

- **内容审核是阻断式的**。内容审核判定（`moderationVerdict`）为 `reject` → 该 `photos` 行**立即软删**（写 `deleted_at`，磁盘文件由 `runPurge()` 清理，用户侧不可见）、写 `content_reviews(stage='upload', verdict='reject')` 与 `audit_logs(action='moderation.reject')`，并返回 `422 CONTENT_REJECTED`；
- 内容审核判定为 `pass` / `review` 一律放行（`review` 等同放行只留痕）；
- **无论内容审核判定取何值，都写一行 `content_reviews(stage='upload')`**——只写 `reject` 会让被放行的判定没有记录。

**`POST /api/photos/:id/preprocess`** — 同步执行（`sharp`，预期 < 2s）；响应 `200` `{ photo: Photo, quality: Quality }`。规则：**不修复、不美化**，只做方向校正、色彩空间统一、尺寸归一（长边 ≥ 1600px，不足则不做放大）、EXIF 剥离；`usable = false` 仍返回 `200`，由前端决定是否放行（见 `modules/M02-预处理与质量评分.md`）。重复调用：同一 `sourcePhotoId` 已存在 `preprocessed` 行则**直接返回该行**（幂等）。

**`GET /api/photos/:id/file`** — 查询参数 `w`（可选，整数，目标宽度；服务端按比例缩放并转 jpeg），不带 `w` 时返回原文件。**`w` 的取值域是 `[16, 2048]`**：越界或非整数 → `400 INVALID_PARAM`（不 clamp——静默改参数会让前端拿到与请求不符的图）；`w` 大于原图宽度时按 `withoutEnlargement` 返回原尺寸（服务端不放大，`spec/00-总纲.md` §4 红线）。响应为二进制，`Content-Type` 取 `photos.mime`（`w` 生效时为 `image/jpeg`）；响应头 `Cache-Control: private, max-age=3600`，`kind='generated'` 额外带 `X-AIGC-Generated: true`。照片不属于当前用户或已软删除 → `404 NOT_FOUND`（不返回 403，避免探测）。

**`DELETE /api/photos/:id`** — 响应 `200` `{ ok: true, cascaded: { preprocessed, anchors, generations, results } }`。规则：软删除（`deleted_at`）并级联标记所有派生行（见 `modules/M08-账号历史与彻底删除.md`），物理文件由清理任务延迟删除。

### 3.3 身份锚点（F1′）

**`POST /api/anchors`** — 请求 `{ photoIds, preprocessedPhotoId? }`；响应 `202` `{ anchor: Anchor }`（`status="queued"`）。校验顺序（任一失败即返回对应错误）：

| 条件 | 错误 |
|---|---|
| `photoIds` 为空或 > 5 张 | `400 INVALID_PARAM` |
| 任一 photo 不属于当前用户或已删除 | `404 NOT_FOUND` |
| 提交的照片 `kind='generated'` | `400 INVALID_PARAM`（防链式自举） |

`preprocessedPhotoId` 缺省时服务端自动对 `photoIds[0]` 执行预处理并落库。副作用：写 `audit_logs(action='anchor.extract')`，创建非终态 `identity_anchors` 行。

**`GET /api/anchors/:id`** — 响应 `200` `{ anchor: Anchor }`；`Anchor` 字段含 `id`、`status`、`attempt`、`anchorText`、`features`（`gender` / `ageRange` / `hair` / `faceShape` / `forehead` / `eyebrows` / `eyes` / `nose` / `mouth` / `skin` / `distinctive` / `build`）、`model`、`promptVersion`、`quality`（同 preprocess 的 `Quality`）、`confirmedByUser`、`confirmedAt`、`error`、`sourcePhotos`、`preprocessedPhoto`、`createdAt`、`finishedAt`。`status='failed'` 时 `error = { code, message }`（如 `PROVIDER_TIMEOUT`）。

**`POST /api/anchors/:id/confirm`** — 请求 `{ confirmed: true, consents: ["photo_usage", "family_agreement"] }`；响应 `200` `{ anchor: Anchor, consents: string[] }`。仅 `status='succeeded'` 可确认，否则 `409 ANCHOR_NOT_CONFIRMED`（复用同一码，语义为"锚点不可用"）；`consents` **必须同时包含两项**，缺任意一项 → `400 INVALID_PARAM`；服务端写 `consents` 两行（幂等：同 `anchorId` + `scope` 未吊销则复用）与 `audit_logs(action='anchor.confirm' / 'consent.agree')`。

**`POST /api/anchors/:id/retry`** — 响应 `202` `{ anchor: Anchor }`（**新行**，`attempt = 旧 + 1`，`inputPhotoIds` / `preprocessedPhotoId` 继承）。

**`DELETE /api/anchors/:id`** — 响应 `200` `{ ok: true, cascaded: { generations, results } }`。

### 3.4 配置资产

**`GET /api/config/era-scene`**（需要登录；前端在登录后于年代选择页加载一次并缓存）— 响应 `200` `{ version, confidenceHintThreshold, realismAnchor, eras: EraOption[], scenes: SceneOption[], profiles: EraSceneProfile[] }`。

- **不返回** `promptPack` / `spacePack` / `constraintPack` / `promptOverride`（prompt 是服务端资产，不下发）。
- `EraOption.sampleUrl` / `SceneOption.coverUrl` / `EraSceneProfile.sampleUrl` 取前端静态资源路径（对应 `spec/era-scene-seed.json` 的 `samplePhoto` 字段），**可为 `null`**；为 `null` 时卡片 / 组合预览降级为纯文字并如实写明"暂无示例"，禁止用占位图凑数。
- `realismAnchor` 为写实锚定原文；`confidenceHintThreshold` 为低置信组合的提示阈值。

### 3.5 生成（F2）

**`POST /api/generations`** — 请求 `{ anchorId, eraCode, sceneId, count }`（`count` 可为 2 / 3 / 4，缺省 2）；响应 `202` `{ generation: Generation }`。校验顺序：

| 条件 | 错误 |
|---|---|
| 当前用户 `users.verified_at IS NULL`（未实名） | `409 REALNAME_REQUIRED` |
| `count` 不在 {2,3,4} | `400 INVALID_PARAM` |
| `eraCode` / `sceneId` 不存在或 `is_active=0` | `400 INVALID_PARAM` |
| 锚点不属于当前用户 | `404 ANCHOR_NOT_FOUND` |
| 锚点 `status != 'succeeded'` 或 `confirmed_by_user != 1` | `409 ANCHOR_NOT_CONFIRMED` |
| `consents` 中 `photo_usage` 不存在或已吊销 | `403 CONSENT_REQUIRED` |
| 今日 `usage_counters.images + count > users.daily_image_quota` | `429 QUOTA_EXCEEDED` |
| 该用户已有非终态 `generations` | `409 GENERATION_IN_PROGRESS` |

副作用：拼装 prompt 并**全文落库**；`reference_photo_ids = [preprocessedPhotoId]`；`params_json` 记录 `size`（取 `eras.default_size`）、`outputFormat`、`watermark`、`provider`；`usage_counters` 预扣 `count` 张（失败时在 worker 里回滚未产出的张数）。

**`GET /api/generations/:id`** — 响应 `200` `{ generation: Generation }`。`Generation` 含 `id`、`status`、`eraCode`、`eraName`、`sceneId`、`sceneName`、`requestedCount`、`attempt`、`prompt`、`templateVersion`、`params`（`size` / `outputFormat` / `watermark` / `provider`）、`error`、`createdAt`、`finishedAt`、`results`；`GenerationResult` 含 `id`、`photoId`、`url`、`width`、`height`、`seed`、`eraCheck`（`passed` / `verdict` / `findings` / `model`）、`ageDelta`、`realismScore`、`userFeedback`。`status` 非终态时 `results` 为已有部分（可能为空数组）；`prompt` 在**所有状态**都返回。

**`POST /api/generations/:id/retry`** — 响应 `202` `{ generation: Generation }`（**新行**，继承 `anchorId` / `eraCode` / `sceneId` / `count` / `params`，`attempt = 0`）。允许的原任务状态：`succeeded` / `partial` / `failed`；非终态 → `409 GENERATION_IN_PROGRESS`。因为复用 `createGeneration` 的校验序列（`modules/M06-生成编排.md` §5.1），下列错误同样可能出现，按同一顺序判定：`409 REALNAME_REQUIRED`（未实名）、`409 ANCHOR_NOT_CONFIRMED`（锚点不可用）、`403 CONSENT_REQUIRED`（授权缺失或已吊销）、`429 QUOTA_EXCEEDED`（额度不足）。

**`POST /api/results/:id/feedback`** — 请求 `{ feedback: 1 | -1 | null }`；响应 `200` `{ result: GenerationResult }`。

### 3.6 历史

**`GET /api/history?cursor=<opaque>&limit=20`** — 响应 `200` `{ items: HistoryItem[], nextCursor }`。`HistoryItem` 含 `anchorId`、`anchorText`、`confirmedAt`、`sourcePhoto`、`preprocessedPhoto`、`generations: Generation[]`。

- 排序：按 `identity_anchors.created_at DESC`；`cursor` 为不透明字符串（实现为 `base64(createdAt|id)`），前端只回传、不解析。
- 只返回**未软删除**的照片；`generations` 最多返回该锚点下最近 10 条。

### 3.7 健康检查

**`GET /api/health`**（无需登录）— 响应 `200` `{ ok, db: { ok, eras, scenes, profiles }, provider: { mode, arkConfigured }, worker: { alive, lastSeenAt } }`。`db.eras/scenes/profiles` 数量不符预期时 `ok=false`（用于发现 seed 未执行）。

### 3.8 图片反推提示词（F4）

**`POST /api/prompt-reverse-jobs`** — 请求 `{ photoId }`（照片可为 `original` 或 `preprocessed`）；响应 `202` `{ job: PromptReverseJob }`（`status="queued"`）。

- 写入 `prompt_reverse_jobs(user_id, source_photo_id, model, status, result_json, result_prompt, suggest_era_code, suggest_scene_id, created_at)`（`model` 取 `ARK_VISION_MODEL` 的当前值，不由语句内联）；复用 `modules/M03-身份锚点提取.md` 的多模态读图通路（`POST {ARK_BASE_URL}/chat/completions` + `image_url`），但**不写入 `identity_anchors`**（见 `modules/M09-图片反推提示词.md`）。
- 照片不属于当前用户或已删除 → `404 NOT_FOUND`；照片 `kind='generated'` → `400 INVALID_PARAM`（防链式自举）。
- 不占 `usage_counters.images` 额度。

**`GET /api/prompt-reverse-jobs/:id`** — 响应 `200` `{ job: PromptReverseJob }`。

- 字段：`resultJson`（结构化场景描述：场景 / 光线 / 年代 / 服饰 / 构图）、`resultPrompt`（自然语言提示词）、`suggestEraCode`（推荐的**年代代号**，`E1`–`E4` 字符串）/ `suggestSceneId`（推荐的**场景 id**，INTEGER，指向 `scenes.id`）（用户可直接采纳，再从链路第 ⑤ 步进入）、`status`、`model`、`photoId`、`error`、`createdAt`、`finishedAt`。
- 状态机：`queued → running → succeeded | failed`；超时与回收规则同 §2.2。非终态时 `resultJson` / `resultPrompt` / `suggestEraCode` / `suggestSceneId` 为 `null`；`status='failed'` 时 `error = { code, message }`。
- 任务不存在或不属于当前用户 → `404 NOT_FOUND`；上游失败 → `PROVIDER_TIMEOUT` / `PROVIDER_ERROR`，签名图转存失败 → `STORAGE_ERROR`（三者可自动重试 1 次）；源照片被内容审核拒绝 → `422 CONTENT_REJECTED`。

> 检查项：`API-08`、`REV-01`–`REV-03`（归属 `modules/M09-图片反推提示词.md`，见 `tickets/T18`）。

## 4. TypeScript 形状（前后端共享）

> 放在 `src/shared/types.ts`，**前后端唯一共用文件**；字段名与 §3 严格一致。

```ts
export type Iso = string;
export interface User { id: number; phone: string | null; email: string | null; nickname: string; status: number; createdAt: Iso; }
export interface Quota { day: string; images: number; limit: number; remaining: number; }
export interface RealNameStatus { verified: boolean; verifiedAt: Iso | null; realName: string | null; }
export interface Photo { id: number; kind: 'original' | 'preprocessed' | 'generated'; url: string; mime: string; bytes: number; width: number | null; height: number | null; sha256: string; createdAt: Iso; }
export interface Quality { usable: boolean; faceDetected: boolean; faceCount: number; sharpness: number; readability: number; damageLevel: number; warnings: string[]; advice: string | null; }
export interface AnchorFeatures { gender: string; ageRange: string; hair: string; faceShape: string; forehead: string; eyebrows: string; eyes: string; nose: string; mouth: string; skin: string; distinctive: string; build: string; }
```

| code | HTTP | 触发场景 | 用户可见文案（示例） |
|---|---|---|---|

| `INVALID_FILE_TYPE` | 400 | 非 jpg/png/webp/heic；**或**白名单内的文件本机解码器打不开（`sharp` 无法识别/无法解码——容器可解析但读不到宽高**不算**这一类，见 `modules/M01-照片资产与存储.md` §6.4 的失败分类表） | 暂时只支持 jpg、png、webp、heic |

### 5.1 上游错误码 → 本项目错误码的映射

完整映射见 `modules/M06-生成编排.md` §5.8（统一在 worker 层映射，实现于 `src/server/ark/errors.ts`）。摘要：

| 上游 | 映射 |
|---|---|
| `InvalidParameter`（size 不合法） | `INTERNAL`（属于我方拼装 bug，不打给用户） |
| `ModelNotOpen` | `PROVIDER_ERROR` |
| `InvalidEndpointOrModel.NotFound` | `PROVIDER_ERROR` |
| HTTP 429 / 限流 | `PROVIDER_ERROR`（可重试） |
| 网络超时 / fetch abort | `PROVIDER_TIMEOUT`（可重试） |
| `InternalServiceError` | `PROVIDER_ERROR`（可重试） |
| 图片下载失败（签名 URL 过期） | `STORAGE_ERROR`（可重试） |
| SQLite `SQLITE_BUSY` / `SQLITE_BUSY_SNAPSHOT`（两进程共写同一库） | `STORAGE_ERROR`（可重试；连接侧已设 `busy_timeout=5000`，见 `spec/04-技术基线与目录结构.md` §4.3） |

## 6. 前端调用禁忌

1. **不要**在前端拼 prompt，也不要把 prompt 回传给服务端；
2. **不要**在前端做"是否可生成"的全部判断——服务端是唯一裁判，前端只做体验优化（按钮置灰）；
3. **不要**直接构造图片 URL 路径，一律使用响应中的 `url` 字段；
4. **不要**解析 `cursor`；
5. **不要**轮询 `succeeded`/`failed` 之后的任务（浪费额度与日志）。
