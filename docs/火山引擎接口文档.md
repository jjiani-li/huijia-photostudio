## 0. 重要校正（务必先读）

编写本文档时对原始需求中的若干说法做了**基于实测的校正**，以免把错误的地址/参数带进工程实现：

| 需求中的说法 | 实测校正 |
|---|---|
| 把 `console.volcengine.com/.../experience/gen_image` 当作「接口地址」 | 该链接是**控制台体验页（Web UI）**，不是可编程调用的 API 端点。真正的数据面 API 是 `POST https://ark.cn-beijing.volces.com/api/v3/images/generations`，见 §1。 |
| 把 `console.volcengine.com/.../experience/gen_chat` 当作「接口地址」 | 同上，是控制台体验页。文本生成的真实端点是 `POST https://ark.cn-beijing.volces.com/api/v3/chat/completions`，见 §2。 |
| 文本模型参数 `model=doubao-seed-evolving-latest-version` | 这是**控制台页面上的别名/占位符**，不是可调用的 Model ID。可调用的真实 ID 是 `doubao-seed-2-1-turbo-260628`。 |
| 「PRD §6 强调尺寸 1920×1920」 | §6.1 的表述是：**总像素不得低于 3,686,400**（1920×1920 = 3,686,400 恰好是下限），**推荐尺寸是 2048×2048**；§6.3 参数基线用的也是 `2048x2048`。见 §1.3。 |
| 正向提示词「保留毛孔、细纹、年代感」 | 这是对 PRD §7.1 / §7.2 的**意译**。原文锚定词是「自然皮肤纹理，可见毛孔与细纹，真实肤色不均」；「年代感」以年代包 + 反 AI 感对照表实现。见 §1.4。 |
| 「文本生成接口报 HTTP 500」 | 500 `InternalServiceError` 实际发生在**直连 Responses API（`/api/v3/responses`）**时；而 Chat Completions（`/api/v3/chat/completions`）文本生成是**正常的**。两者不能混为一谈。见 §2.4。 |

## 1. 图片生成接口（doubao-seedream-5.0-lite）

### 1.1 入口地址

| 类型 | 地址 | 说明 |
|---|---|---|
| **真实 API 端点 ✅** | `POST https://ark.cn-beijing.volces.com/api/v3/images/generations` | 工程集成使用的地址 |
| 控制台体验页 | `https://console.volcengine.com/ark/region:cn-beijing/experience/gen_image?model=doubao-seedream-5-0-260128` | 仅用于人工试玩，**不可作为接口调用** |

- 可调用 Model ID：`doubao-seedream-5-0-lite-260128`（基础模型名 `doubao-seedream-5-0`，version `260128`）。
- 认证：`Authorization: Bearer $ARK_API_KEY`，`Content-Type: application/json`（UTF-8）。

### 1.2 请求参数

| 参数 | 类型 | 必填 | 说明 | 实测结论 |
|---|---|---|---|---|
| `model` | string | 是 | 模型 ID 或 Endpoint ID | platform profile 下必须 `ep-...`，见 §5 |
| `prompt` | string | 是 | 正向提示词 | **lite 无负向通道**，所有约束须写进正向 |
| `image` | string \| array | 否 | 参考图 URL 或 Base64 data URI；**最多 14 张**；单图 ≤ 30MB；总像素 ≤ 6000×6000 | ✅ 多图可用，是身份一致性的主要承载方式 |
| `size` | string | 否 | `2K`/`3K`/`4K` 预设，或 `WxH` | ✅ 总像素区间 **[3,686,400, 16,777,216]** |
| `output_format` | string | 否 | `png` / `jpeg` | ⚠️ **仅 lite 可设置**，5.0 完整版固定 jpeg |
| `response_format` | string | 否 | `url`（默认）/ `b64_json` | ✅ 有效 |
| `watermark` | bool | 否 | 是否加可见水印 | ✅ 有效（本次 `false`） |
| `sequential_image_generation` | enum | 否 | `auto`（连贯多图）/ `disabled`（单图） | ✅ 有效 |
| `sequential_image_generation_options` | object | 否 | `{ "max_images": n }` | ✅ 有效 |
| `optimize_prompt_options` | object | 否 | `{ "mode": "standard" }` | ⚠️ `fast` 仅 5.0 完整版支持 |
| `stream` | bool | 否 | 流式返回 NDJSON | — |
| `guidance_scale` | number | 否 | 引导系数 | ❌ **lite 不支持** |
| `negative_prompt` | string | 否 | 负向提示词 | ❌ **lite 不支持** |

### 1.3 尺寸要求（PRD §6.1 实测约束）

由于 lite 不支持 `negative_prompt`，「反 AI 感 + 防减龄 + 防年代穿帮」全部靠正向 prompt 承载，同时尺寸也有硬约束：

| 项 | 值 |
|---|---|
| 尺寸下限 | 总像素 **≥ 3,686,400**（如 1920×1920）；低于此值接口直接报 `InvalidParameter` |
| 尺寸区间 | **[3,686,400, 16,777,216]**，宽高比 ∈ [1/16, 16] |
| 推荐尺寸 | **2048×2048**（4,194,304 px）；1920×1920 为下限边界值 |
| 本次实测 | 请求 `2048x2048`，实际返回 `"size": "1920x1920"`（见 §1.5） |

> 注意区分：**1920×1920 是「允许的最小值/示例值」，不是推荐值**；PRD §6.1 明确推荐 2048×2048，§6.3 参数基线也用 `2048x2048`。

### 1.4 正向提示词写法（PRD §7）

**核心策略**（§7 开篇）：lite 无负向词，采用「正向写实锚定 + 反向特征的正面化表达」——把「不要塑料感 / 不要磨皮 / 不要减龄」改写成「保留毛孔与细纹、保留深皱纹与老年斑」。

**① 写实锚定词库（§7.1，务必注入每条 prompt）**——即需求里「保留毛孔、细纹、年代感」的原文出处：

```
真实照片，随手拍的生活照，摄影质感，
自然皮肤纹理，可见毛孔与细纹，真实肤色不均，
自然光/室内暖光，[年代专属颗粒与画质描述]，
轻微的对焦不实，构图自然不刻意，[年代]年的影像质感
```

> 定稿版（`spec/era-scene-seed.json` 的 `realismAnchor`）为：
> 「真实照片，随手拍的生活照，自然皮肤纹理，可见毛孔与细纹，真实肤色不均，柔和的对比度，构图自然不刻意」。
> 注意「胶片」字样**不能无脑注入所有年代**——E3/E4 属数码/手机年代，写「胶片质感」会与年代包冲突。

**② 反 AI 感对照表（§7.2，节选）**

| 想禁止（AI 感） | 改写为正向描述 |
|---|---|
| 过度磨皮 | 保留皮肤真实纹理、**毛孔、细纹**、法令纹 |
| 塑料感 / 蜡像感 | 自然的皮肤光泽、轻微油光、真实的肤色过渡 |
| 3D 渲染感 | 写真摄影质感、纪实摄影 |
| 过度锐化 / HDR | 柔和的对比度、略低的动态范围、轻微失焦 |
| **把老人磨年轻** | 保留已有的深皱纹、老年斑与皮肤松弛，不做美化与减龄 |
| 现代感穿帮 | 与照片年代一致的服饰与陈设、老式家具 |

**③ Prompt 模板（§7.3）**

```
【身份锚点】严格保持参考图中人物的面部特征与身份一致，不同场景之间必须是同一个人：<特征描述>
【年代】<年代质感包 · §5.2>
【场景】<场景空间包 · §5.3>
【质感】真实照片，随手拍的生活照，自然皮肤纹理，可见毛孔与细纹，
        真实肤色不均，柔和的对比度，构图自然不刻意
【年代一致】画面中的服饰、发型、建筑、陈设与道具必须属于 <年代> 或更早
```

变量只有三段：`身份锚点`、`年代质感包`、`场景空间包`，便于版本化与 A/B。

**④ 本次实测使用的六段式 prompt 实例**（`.scratch/step2_prompt.md`，节选）：

```
【主体】东亚中年男性，年龄35-45岁……自然皮肤纹理、可见毛孔与细纹、真实肤色不均
【穿着】身着浅灰色宽松款老式日常长袖翻领衬衫……
【场景陈设】背景分为上下两部分，上半部分是垂挂的深蓝色拍照背景布……
【光线】室内人工正面顺光，光源位置略高于人物头部……
【画质与年代】1990年代国内民用肖像照风格，使用民用135胶卷相机拍摄……显著胶片颗粒感……
【构图】中近景坐姿上半身肖像构图，人物居于画面主体位置，平视视角
```

### 2.4 ⚠️ 已知问题：HTTP 500 InternalServiceError（待排查）

**发生位置**：直连 **Responses API**（`POST https://ark.cn-beijing.volces.com/api/v3/responses`）时，三种 payload 形态均返回：

```json
{
  "error": {
    "code": "InternalServiceError",
    "message": "The service encountered an unexpected internal error. Request id: 0217896292616429c5625d6f49ce94e6eea0041d172c51c19222b",
    "param": "",
    "type": "InternalServerError"
  }
}
```

**事实澄清**：该 500 属于 **Responses API 直连通道**的已知问题，**不是** Chat Completions 文本生成的问题——§2.3 的 `/api/v3/chat/completions` 调用是**正常返回**的。

**当前结论与建议**：
- arkcli 的 `+chat` / `+understand` 底层走 Responses API（返回体带 `"object": "response"` 与 `resp_` 前缀 ID），该通道本次**未能直连复现**，具体 payload 格式未确认。
- **工程建议**：业务系统集成优先使用 §2.3 的 Chat Completions 通道（已验证可用）；如需 Responses API 的多轮/工具能力，先参考官方示例完成 payload 验证。
- 排查时务必保留 `Request id`，工单与日志检索都依赖它。**本问题记为待排查项。**

## 3. 图片理解接口（Image Understanding）

用于「老照片解析」场景：读入一张老照片，输出人物特征 / 背景陈设 / 光线 / 画质 / 年代等结构化描述，作为后续生文优化与生图的输入。

### 3.1 方式 A：多模态 Chat Completions（✅ 已验证可用）

复用 §2.3 的端点，把 `content` 换成多模态数组：

```bash
curl https://ark.cn-beijing.volces.com/api/v3/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $ARK_API_KEY" \
  -d '{
    "model": "doubao-seed-2-1-turbo-260628",
    "messages": [
      {
        "role": "user",
        "content": [
          { "type": "image_url",
            "image_url": { "url": "https://<your-bucket>/old-photo.jpg" } },
          { "type": "text", "text": "请描述这张照片的人物、场景、光线与年代特征。" }
        ]
      }
    ],
    "max_tokens": 2000
  }'
```

> `image_url.url` 支持**公网 URL** 或 **Base64 data URI**（`data:image/jpeg;base64,...`）。

### 3.2 方式 B：arkcli `+understand`（⚙️ 本次实际使用）

```bash
arkcli +understand \
  --input "docs/output/era-scene-E2-S1-old-studio.png" \
  --model ep-20260917150742-vrndp \
  --no-progress \
  "请详细描述这张图片，用作后续图像生成的参考。需要覆盖：
   1) 人物性别年龄、穿着、外貌与表情；
   2) 背景环境与陈设细节；
   3) 光线方向与性质；
   4) 色调、颗粒、画质等技术特征；
   5) 能体现拍摄年代的特征。用中文，分段输出。"
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `<prompt>` | string | 是 | 位置参数，图片理解指令 |
| `--input` | stringArray | 否 | 输入资产，`@file` 或路径，可重复；本地图片/视频/文档自动上传 |
| `--model` | string | 否 | 模型名或 Endpoint ID |
| `--max-output-tokens` | int | 否 | 回复 token 上限 |
| `--reasoning-effort` | string | 否 | `minimal\|low\|medium\|high` |
| `--thinking` | string | 否 | `auto\|enabled\|disabled` |
| `--no-progress` | flag | 否 | 关闭 stderr 心跳 |

```json
  "usage": { "prompt_tokens": 1474, "completion_tokens": 3987, "total_tokens": 5461 }
}
```

> 返回体带 `"object": "response"`，说明 arkcli 的 `+understand` 走的是 **Responses API**（即 §2.4 中直连遇到 500 的那条通道）。

### 3.4 在「老照片重现」中的用途

1. **F4 图片反推提示词**：多模态读图 → 结构化场景描述 + 推荐年代/场景代号；
2. **面部特征提取（身份锚点）**：读参考照片，输出结构化 `features` 与一句话 `anchor`，注入生图 prompt 的【身份锚点】段（PRD §6.2）；
3. **年代穿帮复核**：读生成图，判定是否出现该年代之后的物件；
4. 内容安全辅助判定与情感化文案生成。

## 5. 错误码速查（均为本次实际遇到）

| # | 场景 | 错误 | 处理 |
|---|---|---|---|
| 5.1 | 模型未开通 | `ModelNotOpen`：「Your account … has not activated the model …」 | 控制台 `openManagement` 开通 |
| 5.2 | 尺寸低于下限 | `InvalidParameter`：「image size must be at least 3686400 pixels」 | `size` 总像素 ≥ 3,686,400（1920×1920 或 2048×2048） |
| 5.3 | platform profile 用了模型名 | `platform data plane requires an endpoint id (ep-...), not a plan model name` | `arkcli +deploy` 建 Endpoint，传 `ep-...`；或直连 HTTP + 模型名 |
| 5.4 | Endpoint 模型未开通 | `model_activation_required` | 控制台开通，或在真实终端交互执行 |
| 5.5 | Model ID 不存在 | `InvalidEndpointOrModel.NotFound` | 核对 Model ID 写法（控制台别名不可用） |
| 5.6 | 未登录 / 未配置 | `not configured, run arkcli config init …` | `arkcli auth login volc-sso --no-browser` |
| 5.7 | 请求体非 UTF-8 | `InvalidParameter.NonUTF8Body` | 中文不要内联在 shell `-d`，改用 `--data-binary @file.json` |

## 7. 安全与计费注意事项

1. **Endpoint 是计费资源**：本次测试创建的 2 个 Endpoint 已全部 Stop + Delete（`ListEndpoints` 复核 `TotalCount: 0`）。生产使用后务必同样清理。
2. **API Key 是账号级凭证**：不要写入仓库，用环境变量 `ARK_API_KEY` 注入。
3. **生图 / 生文均按量计费**：`usage.output_tokens` 随图片尺寸上升（本次 2K 图约 14,400 tokens）。
4. **签名图片 URL 会过期**（`X-Tos-Expires=86400`，24h），需及时转存。
5. **生成的真人影像涉及肖像权与合规**：生产环境必须做隐式标识、授权确认与风控（PRD §8.3）。
