# 01: 闸门上线

**What to build:** 一个能证明文档树自洽的机器闸门。跑 `pnpm check:docs` 会校验检查项注册表与整棵文档树的一致性，并且让**当前文档树第一次全绿**——为此本条同时修掉闸门一开就会报红的四类既有缺陷：索引列与工单表头漂移、指向不存在的章节或文件的引用、"新建"被重复声明、检查项计数口径不一致。交付后，任何人或代理改完文档都能用一条命令知道自己有没有破坏一致性。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-human

- [x] `spec/check-registry.json` 存在，每个检查项一条记录，含 ID、层级、owner、断言位置与认领工单
- [x] `pnpm check:docs` 可独立运行，不依赖外部凭证、不依赖产品进程
- [x] 八条断言全部生效：ID 唯一、恰有一个 owner、无孤儿、工单声明的 ID 存在、"新建"全仓唯一、声明的文件与章节存在、索引列 ≡ 工单表头、文档写出的总数 ≡ 注册表条数
- [x] 文档树跑出全绿；失败时的输出直接指出是哪条 ID、哪份文件，可当诊断工具用
- [x] 工单索引的检查项列改为从各工单表头派生，不再人工维护
- [x] 四处破损引用已处理（指向真实章节，或改为指向拥有该决策的文档），且闸门能拦住新出现的破损引用
- [x] 检查项总数由注册表派生，B 层与 A 层的口径在文档各处一致
