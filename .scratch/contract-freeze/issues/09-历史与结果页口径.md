# 09: 历史与结果页口径

**What to build:** 用户能看到并彻底删除自己上传的任何照片（包括上传了但没走完流程的），能表达"不像本人"，下载得到的文件与真实格式一致，上传多选时的取数不再依赖此时拿不到的值，反向提示词这个旁路能力不再必须先走完全链路。

**Blocked by:** 01 闸门上线

**Status:** ready-for-human

- [x] 未走完流程的照片在界面上可见，并能用同一套删除确认彻底删除
- [x] 对应的读取路径在接口契约里有定义，且不与按锚点分页的历史查询混用同一次分页
- [x] 反馈取值域含"不像他"，并给出换一张照片的路径；本期该值只落库留痕、不做聚合
- [x] 下载文件扩展名从生成参数里的输出格式派生
- [x] 上传多选时的取数规则不依赖此时尚未产生的值
- [x] 反向提示词的入口落在"照片已存在即可用"的位置，依赖边与归属一致

## Comments

- **「没走完的照片」**（清单第 1、2 条）：新增 `GET /api/photos?cursor=<opaque>&limit=20`（`spec/03-接口契约.md` §3.2 + §4 的 `PhotoList`）——当前用户**未软删、且没有被 `/api/history` 呈现**的照片。**呈现集**是：每个 `status='succeeded'` 锚点的**第一个未软删 `input_photo_ids` 行**、它的 `preprocessed_photo_id` 行、以及该锚点 generations 下 `generation_results.photo_id` 指向的 generated 行；本端点返回这个集合的**补集**——所以「上传后停在半路的」与「同一次上传里非基准的那几张原图」都落在这里，**没有照片会两边都不出现**（`/api/history` 每个锚点只呈现第一个输入原图，这是评审抓出来的关键点）。**游标互不通用**：本端点的游标自带前缀 `base64url('ph|' + createdAt + '|' + id)`，把一边的 `cursor` 传给另一边 → `400 INVALID_PARAM`。前端在 `/history` 加「没走完的照片」区块（`pages/P03` §7/§8），复用同一个 `ConfirmDialog` 与 `DELETE /api/photos/:id`，空态不渲染。`spec/04` §3.1 的「简单查询可直连 repository」白名单补上 `/api/photos`；`modules/M08` §3.2 给出互补查询、`tickets/T13` §1/§4/§5 同步。
