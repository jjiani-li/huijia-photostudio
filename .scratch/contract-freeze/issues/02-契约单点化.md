# 02: 契约单点化

**What to build:** 每一类契约从此只有一处定义。错误码只在接口契约里定义，各模块文档只引用；prompt 的长度阈值与正文各只剩一处；worker 的任务来源、claim、心跳与回收只在技术基线里定义。改完之后，任何人再复制一份契约，闸门都会拦下来——治的是"同一件事写了很多遍，于是互相打架"这个病根。

**Blocked by:** 01 闸门上线

**Status:** ready-for-human

- [x] 各模块文档里自行复述的错误码表体已删除，全部改为引用接口契约
- [x] 错误码的唯一事实源之外不再出现错误码表，且闸门有对应断言
- [x] prompt 长度只有一处阈值声明，其余位置改为引用
- [x] prompt 正文以代码为唯一事实源，文档只写结构与约束，并有"文档与代码等值"的断言
- [x] worker 的任务来源、claim 原子性、心跳与回收只有一处定义，模块文档不再复述
- [x] 任务来源"几张表"在全部文档中只有一个说法
- [x] 施工纪律里写明"不许复制契约，只许引用"，并规定契约级分歧不得记成工单的待定决策

## Comments

- **错误码单点化**：`M01`–`M08` 各自复述的「错误码 | HTTP | 触发条件 | 用户可见文案」表体全部删除，换成「`错误码 | 触发条件`」两列表 + 一句指向 `spec/03-接口契约.md` §5 的说明；`M09` §7 是同类的「场景 | 触发 | 错误码」表，把每格里的 `401` / `404` / `504` 等状态码前缀一并去掉（只留码）；`M06` §5.1 的校验顺序表把「错误码 / HTTP」列收敛为「错误码」（顺序才是那张表的契约）。同一手术也落在 `pages/P01-上传与身份确认.md` §5（它的 `code | 触发位置 | 用户可见文案` 表是同一类复述），现在只留触发位置——这一步同时是 `10-页面形态与文案清单` 想要的「另一处只保留触发位置」，`tickets/T15` 的对应待定决策已标为已收口。
- **一处有意识地丢信息**：`M02` 的 `INVALID_PARAM` 文案「这张照片不能再做这个处理，换一张原图试试」与 `M03` 的 `PROVIDER_TIMEOUT` / `PROVIDER_ERROR` 文案（「照片特征读取花的时间有点长，请重试一次」/「照片特征读取失败，请重试一次」）随表删除——「一个码一份文案」是单点化的直接推论，服务端 `ERROR_MESSAGE` 与 `spec/03-接口契约.md` §5 的通用文案胜出。若产品侧更想要这两处的特化措辞，正确做法是改 `spec/03` §5 那一份（并同步代码常量），而不是让模块文档再写一遍。
