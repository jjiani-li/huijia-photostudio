# 03: 术语收敛

**What to build:** 判定与术语不再一号两义。年代复核的"不通过"与内容审核的"不通过"从此是两个词面可区分的概念，两者相反的后果不会再被同一个词表达；锚点长度只有一个区间与单位；推荐场景只有一个类型；术语的规范形式统一。

按 expand–contract 推进：新术语的定义已经在术语表里（expand 已完成），本条迁移全部文档措辞，最后才加"禁止裸写旧词"的断言（contract）——因此迁移过程中每一步文档树都保持自洽，不存在必须等集成才能变绿的时刻。

**Blocked by:** 01 闸门上线

**Status:** ready-for-human

- [x] 年代复核判定与内容审核判定在文档、类型名与检查项措辞里是两个不同的词
- [x] 取值域与列名保持不变，本条只改概念与类型的命名，不引入结构变更
- [x] 迁移完成后，闸门新增"禁止裸写旧词"的断言，全库无命中
- [x] 锚点长度在列说明与检查项里是同一个区间、同一个单位
- [x] 推荐场景的类型与取值域在文档、表字典与检查项里一致（是场景 id，不是代号）
- [x] 术语的规范形式统一，别名只出现在术语表的 `_Avoid_` 行里
- [x] 术语表成为定义的唯一事实源，另一处只保留"术语 → 落点"的映射并指向它

## Comments

- **两个判定分家**：`M07` 的「两个 `reject` 的措辞区分」改成「两个判定的命名」，全文按 canonical 术语写**年代复核判定（`eraCheckVerdict`，只标注、不阻断交付）** 与**内容审核判定（`moderationVerdict`，不通过即终止该张及后续）**；`M01` / `M06` 的审核侧措辞、`spec/01` §3.10（`era_check_json`）与 §3.13（`content_reviews.verdict`）的说明列、`spec/07` 的 `SEC-08`、`pages/P03` 的年代徽标与边界、`tickets/T11` / `T17` 同步。**取值域与列名字段名一律未动**：`EraCheck.verdict` 与 `content_reviews.verdict` 还是原来的名字，取值还是 `pass` / `review` / `reject`；`spec/03-接口契约.md` §4 只新增两个具名类型 `EraCheckVerdict` / `ModerationVerdict`（前者成为 `EraCheck.verdict` 的类型），没有改任何字段形状。
- **类型名的落点在代码里**：`src/shared/types.ts` 目前只有 T01 的错误码与 `ApiError`，两个 `*Verdict` 类型随 `tickets/T07`（`EraCheck` 写入）与 `tickets/T11`（审核判定）落地——本 spec 的范围不含产品代码，所以这里交付的是被冻结的类型名（`spec/03` §4）与文档措辞；闸门的 `retired-terms` 断言要求这两个名字在定义处（`spec/03` §4）与归属模块（`M07`）里都被点名，防止哪天又被合并回一个词。
- **锚点长度**：统一为 **60–120 字符**，区间与单位在 `spec/01-领域模型与数据库.md` §3.5 的列说明、`spec/07` 的 `E2E-02`、`modules/M03` 的 prompt 填写要求/长度窗口测试/§8 用例（边界样本 59 与 121）与 `tickets/T06` 的完成判定里逐处对齐；`M03` 原先「prompt 里要求 60–120 字、窗口放宽到 40–200」的双口径取消，窗口就是同一个区间（不再给模型留放宽余量）。
- **推荐场景**：`suggestSceneId` 的唯一语义是**场景 id（INTEGER，指向 `scenes.id`）**，`suggestEraCode` 仍是年代代号字符串——`spec/03` §3.8 的字段说明、`spec/07` 的 `REV-01` / `REV-02`（后者原先断言 `{S1..S5}`，那是 `scenes.code` 的值域，已改为断言落在 `scenes.id` 的取值域）、`modules/M09` §4.1 与 §9.1 的对应待定决策（标为已收口）、`spec/00` §3 与 §6.1 同步。
- **术语定义与落点分权**：`spec/00-总纲.md` §5 由「术语表（含含义列）」改为**术语落点表**——定义以仓库根 `CONTEXT.md` 的 Language 一节为唯一事实源，表里只剩「术语 → 定义所在小节 / 代码落点」，并补上本条新分的两个判定与三阶段审核；`CONTEXT.md` 的 `反推提示词` 条款补记 `_Avoid_`: 推荐场景代号、场景代号（指 `suggestSceneId` 时）。规范形式统一：`docs/prd/README.md` §0 与 `spec/00` §3 的「面部特征锚点」改为「身份锚点」。
- **闸门**：新增第 12 条断言 `retired-terms`——`面部特征锚点` / `场景代号` / `anchor_text` 的旧区间（`[40, 200]`、`40 ≤ anchor.length ≤ 200`）在 `docs/prd/` 全库零命中（`CONTEXT.md` 的 `_Avoid_` 行在文档树之外，天然豁免），并检查两个判定分别在 `spec/03` §4 与 `M07` 里被点名；`spec/08-本地开发指南.md` §3.3 的表同步，夹具用例 37 全绿。
- **一处口径需要说明**：清单第 6 条「别名只出现在术语表的 `_Avoid_` 行里」在本条只对**本轮在用的术语别名**成立（面部特征锚点 / 场景代号 / 旧区间）。`CONTEXT.md` 的 `_Avoid_` 一共 88 条，其中多数是普通词（删除 222 处、审核 149 处、图片 103 处、`request`/`job`…），把它们在全库禁掉等于禁掉日常用词——所以退役词表是**逐个登记**的（`scripts/check-docs.mjs` 的 `RETIRED_TERMS`），不按 `_Avoid_` 行整体推导。要扩大禁用面，就往 `RETIRED_TERMS` 里加一条。
