# 05: 生成与转存契约

**What to build:** 生成链路的调度与判据不再互相打架。三张任务表公平轮转、并发排他检查与事务语义正确、审核拒绝与任务终态的关系唯一、结果图尺寸取实测值、"可复现"的说法与真实能力对齐、未验证的上游能力带着标记而不是被当作事实。

**Blocked by:** 01 闸门上线

**Status:** ready-for-human

- [x] 三张任务表按轮转拉取，任何一张都不会被更长的队列饿死
- [x] 排他性检查在插入之前执行，字面实现不会把用户的第一次生成拒掉
- [x] 事务语义与繁忙错误的处理写明，繁忙错误归入可重试集合
- [x] 被内容审核拒绝的结果张不写结果行、不计入张数，任务终态由张数决定
- [x] 结果图与照片记录的宽高取转存后实测值，不写请求参数
- [x] "可复现"的表述在全部文档中统一为"可重新提交复现"，且不为该能力预留无证据的字段语义
- [x] 未验证的上游能力集中登记在诚实边界处，并逐条标注"未验证"

## Comments

- **调度改轮转**：`spec/04-技术基线与目录结构.md` §4.6（worker 契约的唯一事实源）把「固定顺序 `identity_anchors` → `prompt_reverse_jobs` → `generations`」改成**轮转**——worker 记住上一轮结束时的表，下一轮从它的下一张开始，每轮每表至多取一行；并写明理由（固定顺序会让排在最后的 `generations` 在锚点队列变长时永远排不上）。`tickets/T09` 的饿死待定决策已收口；`modules/M06` §5.4 本来就只指向 §4.6，无须再改。
- **排他检查、事务语义与繁忙错误**（清单第 2、3 条）：这两条在本轮之前已经收口，本轮只做核对——`modules/M06-生成编排.md` §5.2 第 8 步明确「排他检查在事务**内、`INSERT` 之前**执行（否则刚插入的 `status='queued'` 行会被自己数进去，首次生成必误报 `409 GENERATION_IN_PROGRESS`）」，事务用 `db.transaction(...).immediate()` 的 `BEGIN IMMEDIATE` 语义（`spec/04` §4.3 也写了 `busy_timeout=5000`），`SQLITE_BUSY` / `SQLITE_BUSY_SNAPSHOT` 映射为 `STORAGE_ERROR` 而它本就在 §4.6 的瞬时错误集合里。清单里的两条因此不再需要新裁定。
- **审核拒绝与终态**（清单第 4 条）：同样已收口，本轮核对过三处口径一致——`modules/M06` §5.3 的终态判据（`status = n === requestedCount ? 'succeeded' : n > 0 ? 'partial' : 'failed'`）、§5.9 第 ④ 步（内容审核判定为 `reject` → 中止该张及后续张的转存并写 `content_reviews` 与审计，**被拒的该张不计入 `n`**）、`spec/07` 的 `SEC-08`（`n === 0` 时 `failed` + `CONTENT_REJECTED`）。
- **宽高取实测值**（清单第 5 条）：`modules/M06` §5.9 ③ 写明「用 `sharp.metadata()` 探**转存后**的实际像素，**不得**写请求的 `size`」，`spec/01-领域模型与数据库.md` §3.4 的 `photos.width` / `height` 按 `kind='generated'` 同口径声明（DTO 的 `GenerationResult.width` / `height` 由 `photos` 透出）。顺带修掉一条笔误引用：`tickets/T10` 原先写「`spec/08-本地开发指南.md` §1.5 实测」，那条记录其实在 `docs/火山引擎接口文档.md` §1.3、§1.5（请求 `2048x2048`、实际回 `1920x1920`）。
- **"可复现"的口径统一**（清单第 6 条）：`README.md` §4.3、`spec/00-总纲.md` §3 的 ⑦、`spec/05-Prompt工程.md` §7.2 第 3 条一律写成**「可重新提交复现」**并保留「**不承诺逐位相同的出图**」；`generation_results.seed` 的字段语义改成「**仅上游回传时记录，不作为复现依据**」（`spec/01` §3.10），不再给它任何复现承诺。三处原先各自写的一句「`seed` 是否回传尚待真机验证」全部删掉，改为引用 §6 的登记表。注意口径边界：`离线可复现`（`spec/07` §1、`spec/08` §5 讲 `PROVIDER=mock`）与「确定性可复现」（`M02` §4.2 的退化人脸检测路径）是**另外两个意思**，不动它们。
