## 3. 设计基调与设计 Token

### 3.1 设计基调

继承 `docs/raw/AIGC_PRD.md` §8.1（`README.md` §0.4 声明其完整继承）：

| 维度 | 规范 |
|---|---|
| 色彩 | 暖白、米杏、浅木色打底；主色用柔和的暖棕 / 暖橙；**忌高饱和、忌冷科技蓝紫** |
| 字体 | 中文衬线 / 类衬线做标题（信笺感），无衬线做正文，字重偏细 |
| 留白 | 大留白，**一屏一重点**，不做信息堆叠 |
| 动效 | 极克制，以淡入为主；不做视差、不做弹跳、不做 3D 翻转 |
| 禁忌 | ✗ 殡葬色系（大面积黑 / 白）✗ 「复活」「重生」「让ta回来」措辞 ✗ 倒计时压迫感 ✗ 夸张的成功提示 |

落到代码上的硬性推论：

1. **全站不得出现 `#000000`、`#FFFFFF` 作为区块背景**（纯黑仅允许用于图标描边级别的小面积）；
2. 任何进度表达**不得出现数字倒计时**（`还有 43 秒`）；进度只用不定进度条 + 一句平实说明；
3. 结果页**不得出现** `太棒了` / `奇迹` / `成功生成 N 张` 这类庆祝语，改用 §9 的中性陈述；
4. 动效统一用 `animate-fade-in`（180ms `ease-out`），不做跨页转场。

### 3.2 语义色（可直接写进 `theme.extend.colors`）

| 语义名 | hex | Tailwind 键 | 典型 class | 用途 |
|---|---|---|---|---|
| `background` | `#FBF7F1` | `colors.background` | `bg-background` | 全站底色（暖白） |
| `surface` | `#F3EBDD` | `colors.surface` | `bg-surface` | 卡片 / 输入框 / 图卡底（米杏） |
| `wood` | `#D8C3A2` | `colors.wood` | `bg-wood`、`border-wood` | 分隔线、年代卡片装饰（浅木色） |
| `primary` | `#A9704A` | `colors.primary.DEFAULT` | `bg-primary`、`border-primary` | 主按钮、选中态描边（柔和暖棕） |
| `primary-soft` | `#E8D6C3` | `colors.primary.soft` | `bg-primary-soft` | 主色悬停 / 禁用底、选中卡片底 |
| `ink` | `#3B2F28` | `colors.ink.DEFAULT` | `text-ink` | 正文与标题（深暖褐，非纯黑） |
| `ink-soft` | `#7A6A5C` | `colors.ink.soft` | `text-ink-soft` | 说明、时间戳、卡片 caption |
| `border` | `#E3D8C8` | `colors.border` | `border-border` | 全部分割线与输入框描边 |
| `danger` | `#B4553F` | `colors.danger` | `text-danger`、`border-danger` | 错误文案与错误框（暖调砖红，不用正红） |

> **命名说明（硬约束）**：正文色与说明色的语义名就是 `ink` / `ink-soft`，**不要**用 `text-primary` / `text-secondary`。原因是 `colors.primary`（主色）会生成 `text-primary` 这个工具类，若正文色也叫 `text-primary` 就会**撞名**，同一个类名会变成"主色文字"而不是"正文色"。`16-前端-页面规格.md` 一律使用 `text-ink` / `text-ink-soft`。
> 例外底色：`primary` 作为背景时文字必须用 `#FBF7F1`（对比度 ≈ 4.9:1）；`danger` 只用于文字与 1px 描边，不做大面积填充。

### 3.3 字号阶梯（6 档，`theme.extend.fontSize`）

| 键 | px / 行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 32px / 1.35 | 500 | 首页唯一主标题（每屏最多一处） |
| `title` | 24px / 1.4 | 500 | 页面标题（`/upload`、`/choose` …） |
| `heading` | 19px / 1.5 | 500 | 区块标题、卡片主标题 |
| `body` | 16px / 1.7 | 400 | 正文、按钮、表单标签 |
| `note` | 14px / 1.6 | 400 | 卡片说明（`eras.caption` / `scenes.caption`）、表单提示 |
| `micro` | 12px / 1.5 | 400 | 顶部导航小字、时间戳、`provider.mode` 提示 |

### 3.4 间距、圆角、阴影、动效

| 类别 | 键 → 值 |
|---|---|
| `spacing` | `xs 4` · `sm 8` · `md 12` · `lg 16` · `xl 24` · `2xl 32` · `3xl 48` · `4xl 64`（px） |
| `maxWidth` | `content: 720px`（一屏一重点的内容栏宽，统一由 `app/(pages)/layout.tsx` 约束） |
| `borderRadius` | `sm 6px` · `md 10px`（卡片） · `lg 16px`（图片容器） · `pill 999px`（主按钮） |
| `boxShadow` | `soft: 0 1px 2px rgba(59,47,40,.06)`（默认卡片）· `card: 0 2px 10px rgba(59,47,40,.08)`（悬停 / 图卡） |
| `animation` | `fade-in: fadeIn 180ms ease-out both`；`@keyframes fadeIn { from { opacity: 0 } to { opacity: 1 } }` |

`tailwind.config.ts` 需要的 `theme.extend` 键名清单：`colors`、`fontFamily`、`fontSize`、`spacing`、`maxWidth`、`borderRadius`、`boxShadow`、`keyframes`、`animation`。

## 4. 字体栈与全局布局

### 4.1 字体栈（`theme.extend.fontFamily`）

```ts
fontFamily: {
  serif: ['"Source Han Serif SC"', '"Noto Serif SC"', '"Songti SC"', '"STSong"', 'serif'],
  sans:  ['"PingFang SC"', '"Source Han Sans SC"', '"Noto Sans SC"',
          '"Microsoft YaHei"', 'system-ui', 'sans-serif'],
}
```

- 标题（`display` / `title` / `heading`）用 `font-serif`，正文与控件用 `font-sans`；**不下载 webfont**，只用系统已装字体（本地零外部依赖，见 `18-本地开发指南.md` §1）；
- Windows 上 `Source Han Serif SC` / `Noto Serif SC` 常缺失，回退到 `Songti SC`（macOS）或最终 `serif`（Windows 落在宋体），这是**可接受降级**：仍保持衬线信笺感；
- 全局 `letter-spacing: 0.01em`、`-webkit-font-smoothing: antialiased`，写在 `app/globals.css`；
- 禁止使用 `Inter` / `Roboto` 等冷感几何无衬线作为中文主字体。

### 4.2 全局布局与顶部导航

```
app/layout.tsx                (Server Component)
  └─ <body class="bg-background text-ink font-sans">
       └─ app/(pages)/layout.tsx   (Server Component)
            ├─ <SiteHeader />      固定高度 56px，底边 1px border-border
            └─ <main class="mx-auto max-w-content px-xl py-2xl">
```

`SiteHeader` 内容与落点（从左到右）：

| 位置 | 内容 | 数据来源 |
|---|---|---|
| 左 | 站点名（`font-serif`，`heading`） | 常量 |
| 中 右 | 「历史」链接 → `/history` | 无 |
| 右 | 用户昵称 + 剩余额度（`额度 14/20`） | `GET /api/me` 的 `user.nickname` / `quota.remaining` / `quota.limit` |
| 右上小字 | `PROVIDER=real` 时显示 `真实模式`，`mock` 时显示 `本地模式` | `GET /api/health` 的 `provider.mode`（`18-本地开发指南.md` §5.2：前端在标题栏以一行小字显示，避免误用真实额度） |

worker 未存活提示的落点：**上传页顶部**（不是全站），文案与命令取自 `14-接口契约.md` §2.3 —— 文案 `后台还没启动，图片处理会卡住`，紧跟一行 `pnpm worker`（`micro` 字号、`text-ink-soft`）。判定条件：`GET /api/health` 的 `worker.alive === false`；对齐检查项 `ERR-04`。

## 5. 路由表

App Router 页面目录 `app/(pages)/`（`03-后端-模块总览.md` §2 已声明 `(pages)` 见本文件）。

| 路径 | 页面文件 | 渲染方式 | 需要登录 | 主要数据来源 |
|---|---|---|---|---|
| `/` | `app/(pages)/page.tsx` | Server Component | 否 | 无（上传入口链接到 `/upload`） |
| `/login` | `app/(pages)/login/page.tsx` | Server Component 骨架 + Client Component 登录面板 | 否 | `POST /api/auth/code`、`POST /api/auth/login`、`GET /api/me` |
| `/upload` | `app/(pages)/upload/page.tsx` | Server Component 骨架 + Client Component 上传面板 | 是 | `GET /api/health`、`POST /api/photos`、`POST /api/photos/:id/preprocess`、`POST /api/anchors` |
| `/confirm/[anchorId]` | `app/(pages)/confirm/[anchorId]/page.tsx` | Server Component 骨架 + Client Component 轮询区 | 是 | `GET /api/anchors/:id`、`POST /api/anchors/:id/confirm`、`POST /api/anchors/:id/retry` |
| `/choose/[anchorId]` | `app/(pages)/choose/[anchorId]/page.tsx` | Server Component 骨架 + Client Component 选择区 | 是 | `GET /api/config/era-scene`、`POST /api/generations` |
| `/result/[generationId]` | `app/(pages)/result/[generationId]/page.tsx` | Server Component 骨架 + Client Component 轮询区 | 是 | `GET /api/generations/:id`、`POST /api/generations/:id/retry`、`POST /api/results/:id/feedback` |
| `/history` | `app/(pages)/history/page.tsx` | Server Component 骨架 + Client Component 列表 | 是 | `GET /api/history` |

规则：

1. **页面组件一律 Server Component**，只做静态骨架渲染与「cookie 存在性」的软校验；**真实数据一律在 Client Component 里通过 `src/shared/api-client.ts` 取**，不违反 `14-接口契约.md` §6（前端只通过端点取数据，不直读数据库），也避免在 RSC 里为转发 cookie 拼绝对 URL。
2. `[anchorId]` / `[generationId]` 必须用 zod 在页面入口解析为整数，非法值直接 `notFound()`（不要发起请求）。
3. 「需要登录」的页面在 `app/(pages)/layout.tsx` 统一做**软重定向**：`cookies().has('sid')` 为假 → `redirect('/login')`。服务端仍是唯一裁判（`UNAUTHENTICATED` → `ErrorNotice` 页面级，见 §8）。
4. `next/link` 做站内跳转（保持 SPA 体验，`useEraSceneConfig` 的模块级缓存才能生效）；图片一律 `<img>` 或 `next/image` 的 `unoptimized`，因为 `url` 由服务端给出且带查询参数 `?w=`。

## 6. 状态管理方案

### 6.1 决定：不引入 redux / zustand / jotai / react-query

| 备选 | 否掉的理由 |
|---|---|
| redux / zustand / jotai | 全站**没有真正的跨页共享状态**：`User`+`quota` 每次导航由 `SiteHeader` 重取即可；年代/场景配置是一次只读加载（`useEraSceneConfig` 模块级缓存）；流程状态天然由路由参数表达。引入库只会把「服务端是唯一裁判」（`14-接口契约.md` §6 禁忌 2）的判断复制到客户端 |
| react-query / SWR | 全部查询都是「进页面取一次 + 轮询一个任务」，`useJobPolling` + `useEffect` 已足够；多一个依赖就多一套缓存失效语义要维护 |
| Next Server Actions | 会绕开冻结的 HTTP 契约；本期前后端并行开发依赖 `14-接口契约.md` 的端点形状 |

技术手段：**React Server Components（页骨架）+ 少量客户端 state（`useState`/`useRef`）+ URL 参数（流程事实源）**。

### 6.2 哪些状态放 URL

| URL 参数 | 载体 | 理由 |
|---|---|---|
| `anchorId` | `/confirm/[anchorId]`、`/choose/[anchorId]` 的路径段 | 流程的**事实**，刷新/回退/分享都必须成立 |
| `generationId` | `/result/[generationId]` 的路径段 | 同上；历史页可直接链到结果 |
| `era` | `/choose/[anchorId]?era=E4` | 未提交的选择，刷新后不丢；不落库 |
| `scene` | `/choose/[anchorId]?scene=3` | 同上（`scenes.id`，非 `code`） |
| `count` | `/choose/[anchorId]?count=2` | 与 `POST /api/generations` 的 `count` 同名同义；缺省不写，服务端默认 2 |
| `cursor` | `/history?cursor=<opaque>` | `14-接口契约.md` §3.6 的不透明游标，前端**只回传不解析**（§6 禁忌 4） |

写 URL 一律用 `router.replace(...)`（`useRouter` + `usePathname` + `useSearchParams`），**不用 `push`**：选年代/场景不是导航，不该污染历史栈。

### 6.3 哪些状态放 local state

| 状态 | 位置 | 说明 |
|---|---|---|
| 上传中的 `File[]` 与每张的进度 | `/upload` 的 Client 组件 `useState` | 尚未提交，无服务端身份 |
| 「请求进行中」按钮禁用标志 | 各提交按钮的 `useState` | `POST /api/anchors`、`POST /api/generations` 是**非幂等**的（`14-接口契约.md` §1.5），请求期间必须禁用按钮 |
| `useJobPolling` 的内部状态 | `hooks/use-job-polling.ts` | 见 §7，组件只读不改 |
| 两个授权勾选（`photo_usage`、`family_agreement`） | `/confirm` 的 `useState`，初始全为未勾选 | **绝不写入 URL / localStorage**：授权必须是每次显式动作 |
| 结果页当前放大的那张图 | `useState<number \| null>`（`resultId`） | 纯视图状态 |
| 当前 `ErrorNotice` 的消息 | 各 Client 组件 `useState<{code,message} \| null>` | 不放全局 store：错误是局部的 |

**禁止**：把 `prompt`、`anchorText`、授权勾选、上传中的文件放进 `localStorage` / `sessionStorage`。

## 7. 轮询 Hook：`useJobPolling`

对齐 `14-接口契约.md` §2.1 的协议；实现在 `hooks/use-job-polling.ts`。

```ts
export const ANCHOR_POLL_INTERVAL_MS = 1500;
export const ANCHOR_POLL_TIMEOUT_MS = 90_000;
export const GENERATION_POLL_INTERVAL_MS = 2000;
export const GENERATION_POLL_TIMEOUT_MS = 180_000;

export type PollPhase = 'idle' | 'polling' | 'done' | 'timedOut' | 'error';

export interface JobPollingOptions<T> {
  /** 每次轮询执行的请求；内部只负责调用，不做错误处理 */
  fetchJob: () => Promise<T>;
  /** 从响应里取状态字符串，如 (a) => a.anchor.status */
  getStatus: (job: T) => string;
  /** 终止状态集合；锚点传 ['succeeded','failed']，生成传 ['succeeded','partial','failed'] */
  terminalStatuses: readonly string[];
  intervalMs: number;
  timeoutMs: number;
  /** false 时不发起任何请求（如锚点尚未创建） */
  enabled: boolean;
}

export interface JobPollingState<T> {
  job: T | null;                     // 最近一次成功响应
  phase: PollPhase;
  jobStatus: string | null;
  elapsedMs: number;                 // 仅用于「还在处理」文案，不用于倒计时
  error: { code: string; message: string } | null;
  /** 手动「再看一眼」：重置 elapsedMs 后立即再请求一次（超时后保留的按钮） */
  refreshNow: () => void;
}

export function useJobPolling<T>(options: JobPollingOptions<T>): JobPollingState<T>;
```

实现要点（每条都对应一个可测断言）：

1. **只排下一次、不叠加**：用 `setTimeout` 递归，不用 `setInterval`；下一次调度发生在**本次响应（或失败）回来之后**（`14-接口契约.md` §2.1）。
2. **并发护栏**：`useRef<boolean>('inFlight')`，进入请求前置 `true`、`finally` 置 `false`；已在飞行中则本轮直接跳过调度。
3. **终止即停**：`getStatus(job) ∈ terminalStatuses` → `phase = 'done'`，不再排下一次；`enabled` 变 `false` 或组件卸载（`useEffect` 清理）时清 `setTimeout` 并把 `inFlight` 复位。
4. **超时不停轮询能力**：`elapsedMs >= timeoutMs` → `phase = 'timedOut'`（页面展示 `还在处理，可以先去别处看看`，见 §9）。**自动轮询停止，但 `refreshNow()` 保留**，调用后 `intervalMs` 继续走（`14-接口契约.md` §2.1：「继续保留轮询按钮（不自动停）」这句话在实现上就是这条）。
5. **错误不吞**：`ApiClientError` → `error = { code, message }`、`phase = 'error'`，停止自动轮询，把错误交给 `ErrorNotice`；`PROVIDER_TIMEOUT` / `PROVIDER_ERROR` 场景由用户点重试，不在前端自动补轮询（后端最多自动重试 1 次，见 §2.2）。
6. **首帧立即请求**：`enabled` 为真时先请求一次，再按间隔排下一次（避免进页面空等 1.5s）。
7. **不轮询终态**：`GET /api/health` 之外，任何已进入终态的 `anchorId` / `generationId` 不得再次发起轮询（`14-接口契约.md` §6 禁忌 5）。
8. 两个调用方各传一组常量：`/confirm/[anchorId]` 用 `ANCHOR_*`；`/result/[generationId]`、`/choose/[anchorId]`（提交后跳转）用 `GENERATION_*`。

## 8. 错误呈现：`ErrorNotice`

实现在 `components/error-notice.tsx`；是 `14-接口契约.md` §5 错误码在前端的**唯一落点**。

```ts
import type { ReactElement, ReactNode } from 'react';

export interface ErrorNoticeProps {
  error: { code: string; message: string } | null;
  /** 'page' 占满内容区（该页无法继续），'inline' 贴在触发控件下方 */
  variant?: 'inline' | 'page';
  /** 点击「再试一次」；不传则不显示重试按钮 */
  onRetry?: () => void;
  /** 附加动作插槽，如「换一张」「去确认」「去看那一组」 */
  action?: ReactNode;
}
export function ErrorNotice(props: ErrorNoticeProps): ReactElement | null;
```

呈现规则：

- 主文案**直接用服务端 `error.message`**（`14-接口契约.md` §1.3：`message` 是可直接展示给用户的中文文案），前端**不重写、不改写、不二次加工**；
- 未知 `code`（响应里出现表外错误码）→ 按 `INTERNAL` 渲染，仍显示服务端 `message`；
- 视觉：`bg-surface` + 1px `border-danger` + `text-danger` 标题行 + `text-ink` 正文，`note` 字号；无图标、无红色大面积填充、无感叹号堆叠；
- `page` 形态在 `/confirm`、`/result` 上用于「这一页已经没有可看的东西」（如 `ANCHOR_NOT_FOUND`）。

错误码 → 形态与动作（文案来自服务端 `message`；括号内为前端附加动作）：

| code | 形态 | 附加动作 | 重试按钮 |
|---|---|---|---|
| `UNAUTHENTICATED` | page | 「去登录」→ `/login` | 否 |
| `FORBIDDEN` / `NOT_FOUND` | page | 「回历史」→ `/history` | 否 |
| `INVALID_PARAM` | inline | 若 `details.fields` 存在，仅用于前端高亮对应控件（不展示原文） | 否 |
| `INVALID_FILE_TYPE` / `FILE_TOO_LARGE` | inline | 「换一张」唤起文件选择 | 否 |
| `CODE_INVALID` / `CODE_EXPIRED` / `CODE_RATE_LIMITED` | inline | 聚焦验证码输入框；`CODE_RATE_LIMITED` 时禁用「发送」按钮 60 秒（**显示剩余秒数在此处允许，因为它是按钮可用性而非任务倒计时**） | 否 |
| `CONSENT_REQUIRED` | inline | 滚动并聚焦授权勾选区 | 否 |
| `ANCHOR_NOT_FOUND` | page | 「回历史」 | 否 |
| `ANCHOR_NOT_CONFIRMED` | inline | 「去确认」→ `/confirm/{anchorId}` | 否 |
| `ANCHOR_LOW_QUALITY` | inline | 展示 `details.quality.warnings[]`（原文，不加工）+「换一张」 | 否 |
| `GENERATION_IN_PROGRESS` | inline | 「去看那一组」→ `/history` | 否 |
| `QUOTA_EXCEEDED` | inline | 显示 `quota.remaining` / `quota.limit` | 否 |
| `CONTENT_REJECTED` | inline | 无附加动作；不回显审核原因 | 否 |
| `PROVIDER_ERROR` / `PROVIDER_TIMEOUT` | inline | — | **是**（`onRetry`） |
| `STORAGE_ERROR` / `INTERNAL` | inline | — | **是**（`onRetry`） |

worker 未存活的特殊提示**不走 `ErrorNotice`**（它不是 API 错误，没有 `code`）：由 `useHealth()` 驱动，在上传页顶部渲染一条 `bg-surface` 中性提示，文案 `后台还没启动，图片处理会卡住` + `pnpm worker`（§4.2）。这样「错误红」只留给真正的错误。

## 9. 文案语气规范

### 9.1 规则

1. **第二人称**（「你」），不说「您」、不说「用户」；
2. **平实**：陈述事实与下一步动作，不抒情、不承诺效果、不安慰式收尾；
3. **不说教**：不解释技术原理，不教育用户该怎么做人（不出现「请珍惜」「思念」「逝去」这类情绪引导）；
4. **不用祈使堆叠**：一句话最多一个动作，如「挑一张看得清脸的旧照片」；
5. 每句话必须**能推出下一步动作**（换一张 / 勾选 / 点确认 / 等一会儿 / 下载）；
6. 不出现技术词：`prompt`、`锚点`、`token`、`API`、`候选`（对外统一说「这几张」）；
7. **进度用定性描述**，不用数字倒计时、不用「最后 30 秒」。

### 9.2 示例文案（可直接进 `16-前端-页面规格.md`）

| 3 | 上传页引导 | `挑一张看得清脸的旧照片，正面最好，1 到 5 张都行。` |

## 10. 对外接口与数据读写

- **端点**：前端只调用 `14-接口契约.md` §3 列出的端点，逐一对应关系见本文 §5 路由表；不新增端点、不新增字段。
- **类型**：全部响应类型从 `src/shared/types.ts` 引入（`User`、`Quota` 所在的 `GET /api/me` 响应、`Photo`、`Quality`、`Anchor`、`EraSceneConfig`、`Generation`、`GenerationResult`、`HistoryItem`、`ApiError`），对齐 `API-02`（每个端点用 `src/shared/types.ts` 的 zod schema 校验形状）。
- **前端不直读数据库**、不读 `promptPack` / `spacePack` / `constraintPack` / `promptOverride`（`API-06` 断言响应里没有它们）。
- **数据流**：`src/shared/api-client.ts` → 页面 Client 组件 `useState`；无全局缓存层。唯一例外是 `useEraSceneConfig()` 的**模块级 memory 缓存**（同一标签页只请求一次 `GET /api/config/era-scene`，`14-接口契约.md` §3.4：登录后于年代选择页加载一次并缓存）——用普通 `Map<string, EraSceneConfig>`，key 为响应的 `version`；不做 `localStorage` 持久化。
- **列表**：`GET /api/history` 的 `nextCursor` 原样回传，`cursor` 从不解析。
- **写操作**：`POST /api/anchors`、`POST /api/anchors/:id/retry`、`POST /api/generations`、`POST /api/generations/:id/retry` 均非幂等 —— 前端在 `await` 期间禁用触发按钮（§6.3），且不做自动重投。
- **额度**：`POST /api/generations` 预扣张数（`14-接口契约.md` §3.5），成功后前端重新拉 `GET /api/me` 刷新 `SiteHeader` 的剩余额度。
