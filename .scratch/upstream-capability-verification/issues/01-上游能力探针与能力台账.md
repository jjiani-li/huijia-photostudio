# 01: 上游能力探针与能力台账

**What to build:** 三条决定产品承诺的上游能力从假设变成有证据的结论，并留下可复核的原始报文；台账成文，"未验证的能力不得进 schema、检查项或对外承诺"这条闸门规则写进施工纪律。

需要真机凭证，且其中一条要人眼判断"像不像本人"，因此这条是人工执行项，不是代理可自行完成的。

**Blocked by:** 无（可立即开始）

**Status:** ready-for-human

- [ ] `seed` 探针结论明确：是否被接受、响应是否回传、同一 seed 连发两次是否得到同一张图（用文件哈希比较），原始请求与响应留存
- [ ] 参考图探针结论明确：带一张预处理图的生成是否成功、身份是否一致（人眼判断并留存结果图）；本次未覆盖的上限类假设标注为"未覆盖"，不自动视为成立
- [ ] `negative_prompt` 探针结论明确：被拒则为确实不支持；被接受则标记为必须回改
- [ ] 台账成文：一行一条能力，含证据等级（已验证 / 间接验证 / 无证据 / 与证据冲突）、证据位置、对实现的影响、不成立时的降级方案
- [ ] 闸门规则已写进施工纪律
- [ ] 结论为否时，受影响的 schema 与对外表述已按 spec 的降级规则回改
