## 1. 职责与边界

### 1.1 做什么

把"生成真人影像"这件事的四类法定/伦理义务，逐条固定到**表、列、端点、文件**上：

| # | 义务 | 落点 |
|---|---|---|
| 1 | 生成合成内容的隐式标识 | §3 · `src/server/images/mark.ts` + `audit_logs(action='photo.mark')` |
| 2 | 使用授权的事前声明与留痕 | §5 · `consents` 表 + `POST /api/anchors/:id/confirm` |
| 3 | 随时彻底删除、不残留、不用于训练 | §6 · 软删列 + purge worker + 受控文件端点 |
| 4 | 生成前后内容审核 | §7 · `content_reviews` 表（口径见 `modules/M07-生成后复核与内容审核.md` §5.6） |

另有两条贯穿性约束：**额度与限流**（§8）与**措辞禁令**（§9）。

### 1.2 明确不做什么

- ❌ **不做实名认证**：不做身份证校验、人脸比对、手机号实名核验。本期登录只有验证码（`SMS_PROVIDER=console`），它不是身份认证，**不得在任何文案或文档里把它描述成"实名"**。
- ❌ **不做投诉受理与下架通道**：没有对外投诉入口、没有工单系统、没有下架后台。§10 说明留了什么。
- ❌ **不做人工审核后台**：`verdict='review'` 本期等同放行并留痕（`modules/M07-生成后复核与内容审核.md` §1.2）。
- ❌ **不做可见标识开关 UI**：见 §4。
- ❌ **不做金额计费**：只有 `usage_counters` 计数，无账单、无支付（`spec/01-领域模型与数据库.md` §6）。
- ❌ **不做分享功能**：因此不存在"分享到目标平台时补充平台侧可见标识"的实现。
- ❌ 不新增 HTTP 端点、不新增表；本文件只新增**一列都不加**，全部落点复用既有结构（唯一例外是 `audit_logs.action` 增加一个取值，见 §3.3）。

## 3. 隐式标识（必须落代码）

依据《人工智能生成合成内容标识办法》，生成合成内容须写入**隐式标识**（文件元数据中的生成合成内容属性信息）。**必须写入**，不是可选项。

### 3.1 唯一产物：`mark.ts`

```ts
// src/server/images/mark.ts
export const AIGC_MARKER =
  'AIGC:service=home-photo-studio;model=doubao-seedream-5-0-lite-260128;v=1';

/** 只在 kind='generated' 的输出上调用。就地返回带标识的新 Buffer，失败的判定见 §3.4。 */
export async function markGeneratedImage(
  buf: Buffer, format: 'png' | 'jpeg',
): Promise<{ marked: Buffer; implicit: boolean }>;
```

- `AIGC_MARKER` 是**纯 ASCII**，不含中文：PNG 的 `tEXt` 值与 EXIF 的 `UserComment` 都是字节串，写入中文会引入编码歧义，也让 `CMP-01` 的断言难以逐字符比对。
- 标识串里必须含 `AIGC` 字面量与 `service=`：前者是识别标志，后者是"由谁生成"的服务商信息。
- 模型名与 `spec/08-本地开发指南.md` 的 `ARK_IMAGE_MODEL` 默认值必须一致；换模型时同批更新（`CMP-01` 断言这一致性）。

### 3.2 按格式的写入位置

| 格式 | 写入位置 | 实现 |
|---|---|---|
| `png`（本期固定） | 新增 `tEXt` 块，关键字 `AIGC`，值 `AIGC_MARKER` | 手工插入 chunk：`length(4) + "tEXt"(4) + keyword\0text + CRC32(4)`，插在 IHDR 之后、IDAT 之前 |
| `jpeg` | `EXIF IFD0.ImageDescription` 与 `IFD3.UserComment` | `sharp(buf).withMetadata({ exif: { IFD0: { ImageDescription: AIGC_MARKER }, IFD3: { UserComment: AIGC_MARKER } } })` |

插入 PNG chunk 需要 CRC-32（PNG 规范 §5.5，多项式 `0xEDB88320`）。若运行时的 Node 版本提供 `zlib.crc32` 则直接使用，否则实现标准查表版本。**这是本文件唯一需要手写二进制处理的点，必须配单元测试**（§12）。

> **与 `modules/M02-预处理与质量评分.md` §5 的禁令不冲突**：M02 禁止 `.withMetadata()` / `.keepMetadata()`，禁的是**输入归一化**路径（源图必须剥离 EXIF，见本文件总表第 11 项）。`mark.ts` 只作用于 `kind='generated'` 的输出，方向相反、对象不同。两条规则互不覆盖，**不得因本条而放开 M02 的禁令**。

### 3.3 调用点与服务端标识记录

调用点唯一：**生成结果转存时**（`modules/M06-生成编排.md` §5 第 3 步）。顺序固定：

```
上游 data[].url → 下载 → markGeneratedImage() → LocalStorageProvider 写 .tmp → rename
                → INSERT photos(kind='generated', bytes=marked.length)
                → INSERT audit_logs(action='photo.mark', target='photo:<id>')
```

- `photos.bytes` 必须取**标识写入之后**的长度，否则 `E2E-06`（磁盘字节数与 `bytes` 一致）会失败。
- `audit_logs(action='photo.mark')` 是"服务端标识记录"，**无论是否真的写入了元数据都要写**，`meta_json` 记实际状态：

| 场景 | `meta_json` |
|---|---|
| 按配置写入成功 | `{ implicit: true, format: "png", marker: "<AIGC_MARKER>" }` |
| `AIGC_IMPLICIT_MARKER=false`，按配置不写 | `{ implicit: false, mode: "off", format: "png" }` |
| 尝试写入但失败 | `{ implicit: false, mode: "failed", format: "png", reason: "<错误摘要>" }` |

`mode` 三态是必要的：没有它就无法区分"合规地关掉了"与"写挂了"，而后者必须被看见。

- 需在 `spec/01-领域模型与数据库.md` §3.14 的必记 `action` 清单中增加 `photo.mark`。

### 3.4 写失败不阻断交付

标识写入失败**不**把任务置为失败：记 `mode: "failed"` 的审计行 + `logger.warn`，照常交付并落盘**未标记**的文件。理由是本期为本地 MVP，元数据写入的失败不应让用户拿不到图；但失败必须留痕，由 `CMP-03` 在验收中要求 `mode='failed'` 为零。

### 3.5 开关

| 变量 | 默认 | 语义 |
|---|---|---|
| `AIGC_IMPLICIT_MARKER` | `true` | 是否为生成图写入隐式标识元数据 |

**生产环境必须为 `true`**。允许在本地设为 `false` 以便做"看起来像不像真照片"的对比；该开关**只控制元数据写入**，不影响审计行（§3.3）。

## 4. 可见标识（本期口径）

| 形态 | 本期做法 | 依据 |
|---|---|---|
| 图片上的可见水印 | **默认不加**：`WATERMARK_DEFAULT=false` 传给 Seedream 的 `watermark`。开关存在但不暴露给用户 | `spec/00-总纲.md` §4.2（真实感优先）；`docs/raw/AIGC_PRD.md` §8.1 |
| 界面上的"AI 生成"角标 | **本期不做**：无全局开关 UI、无角标组件 | `pages/P00-设计基准与路由.md` §13；`pages/P01-页面规格.md` §10.1 |
| 响应头显式标识 | **做**：`kind='generated'` 的文件响应带 `X-AIGC-Generated: true`，其余 `kind` 不带 | `modules/M01-照片资产与存储.md` §4.2、`U14` |

口径统一为：**本期的"可见标识"只有响应头这一种，且它不是给人看的**。它存在的意义是让任何拿到文件的程序都能判别来源，同时不给用户界面增加任何"AIGC"字样——后者会直接损害 §4.2 的真实感目标。

**将来补做可见标识时的硬约束**（现在不实现，但先冻结规则，避免以后随手加）：开关默认值必须是"关闭"、必须保留服务端记录（复用 §3.3 的审计行，不加表）、且开关状态不得出现在生成结果页的主视区内。

## 5. 授权与留痕

口径与字段细节以 `modules/M04-身份确认与授权.md` 与 `spec/01-领域模型与数据库.md` §3.11 为准。本文件只固定四条不可动摇的规则：

1. **两项 scope 缺一不可**：`photo_usage`（对照片中人物拥有合法使用权）与 `family_agreement`（已获其他近亲属同意）。`spec/03-接口契约.md` §3.3 的 `consents` 数组必须同时含两项，否则 `400 INVALID_PARAM`。
2. **确认在生成之前，且是硬前置**：未确认 → `409 ANCHOR_NOT_CONFIRMED`；已确认但授权被吊销 → `403 CONSENT_REQUIRED`。判定顺序固定为"先确认、后授权"（`modules/M04-身份确认与授权.md` §5.3）。
3. **吊销是法律事件，删除不是**：`DELETE /api/photos/:id` 与 `DELETE /api/anchors/:id` **都不写** `consents.revoked_at`、**都不删** `consents` 行。`revoked_at` 只由吊销入口写入，"同意 → 吊销 → 再同意"必须留下完整轨迹。
4. **`consents` 历史行永不删改**：`agreed_at` 不可改写；重新确认插入新行。授权留痕所依附的锚点记录（`consents.anchor_id`）因此也必须保持当时的样子——这是"重新提取锚点 = 插入新行、不覆盖"的合规理由之一。

## 6. 彻底删除与隐私

### 6.1 两级删除

| 级 | 触发 | 效果 |
|---|---|---|
| 软删 | `DELETE /api/photos/:id` / `/api/anchors/:id` | 写 `deleted_at`，立刻从 `/api/history` 与文件端点消失；写 `audit_logs(action='photo.delete')` |
| 物理清理 | purge worker 定时执行 | 删磁盘文件 → 删 `generation_results` → 物理 `DELETE photos` 行；写 `audit_logs(action='photo.purge')` |

阈值与批处理常数（`PURGE_GRACE_MINUTES=10`、`PURGE_BATCH_SIZE=200`、`PURGE_INTERVAL_MS`）见 `modules/M08-账号历史与彻底删除.md` §5.3。**本文件不重复数值**。

### 6.2 删除的完备性

删除一张 `original` 图时，必须连带处理：`preprocessed` 派生图、引用该派生图的 `identity_anchors`、这些锚点下的 `generations` 与 `generation_results`、这些生成任务产出的 `photos(kind='generated')` 及其磁盘文件；命中被删锚点的 `consents` 行**写 `revoked_at`（不删行）**。完整规则表见 `modules/M08-账号历史与彻底删除.md` §3.3，验收为 `DEL-01`–`DEL-04`。

**"彻底"的判定标准**：删除后 `storage/` 下不存在任何未被 `photos` 行引用的残留文件，且 `photos` 行本身也不再存在。仅软删不算彻底。

### 6.3 最小权限与不落公网

- 源图与生成图只存本地 `./storage/`，库里只存 `storage_key`；**任何表、任何响应都不含公网图片地址**（`spec/00-总纲.md` §6.2）。
- 文件读取走受控端点 `GET /api/photos/:id/file`，先校验 `user_id` 归属，越权返回 `404`（不返回 `403`，避免资源探测；`API-04`）。
- 上游返回的签名临时 URL（86400s 有效期）只在上游响应中存在，**必须立即转存并丢弃**，不得写入数据库。
- 登录标识符在响应中脱敏（含 `*`，`API-05`）。

### 6.4 不用于模型训练

**承诺：用户上传的照片与生成结果不用于训练任何模型。** 该承诺落在两处：① 本项目不实现任何"数据回流/样本导出"通道，代码中不存在把 `./storage/` 内容上传到训练侧或标注侧的路径；② 该承诺出现在用户可见的使用说明中。

**诚实边界**：上游方舟侧是否将请求用于训练，由平台条款决定，不受本项目控制。因此对外表述只能是"我们不会用你的照片训练模型"，**不得**表述为"你的照片不会被用于任何训练"。此点须在实现注释与用户可见说明中同时体现。

## 7. 内容审核

三阶段的触发点、判定对象、落库行、reject 路径与失败语义，**全部以 `modules/M07-生成后复核与内容审核.md` §5.6 为准**。本文件固定三条不可动摇的规则：

1. **审核是硬约束，不放过未审核的结果**：审核调用超时/报错时按 `spec/03-接口契约.md` §2.2 自动重试 1 次，仍失败则任务 `failed` 并写对应 `error_code`——**不得**把"没拿到结论"当作"通过"。这与年代复核"失败就留空"（M07 §5.3）是刻意的不对称。
2. **任何 `reject` 都必须留痕**：额外写 `audit_logs(action='moderation.reject')`，`meta_json` 记 `{stage, targetId, reason}`。三个阶段的 `reject` 都适用。
3. **`review` 等同放行**：三个阶段一致，仅留痕，无人工处置通道。

**诚实说明**（必须写进实现注释，不许当成已解决）：本期用户输入面极小，`prompt` 阶段真正能拦到的只有"模型从照片里读到的违规文字"，它**是防线不是主力**；主力是 `upload` 与 `result` 两个对着真实图像的阶段。

## 8. 风控与额度

| 手段 | 规格 | 落点 |
|---|---|---|
| 单次生成张数上限 | `count ∈ {2,3,4}`，超出 `400 INVALID_PARAM` | `spec/03-接口契约.md` §3.5 |
| 每日额度 | 判断读 `users.daily_image_quota`，计数写 `usage_counters(user_id, day)`；超出 `429 QUOTA_EXCEEDED` | `security/` |
| 额度预扣与回滚 | 入队时预扣 `count`，worker 内未产出的张数回滚 | `modules/M06-生成编排.md` §5 |
| 并发闸门 | 已有非终态生成时再次发起 → `409 GENERATION_IN_PROGRESS` | 同上 |
| 验证码限流 | 同 `identifier` 60 秒内二次发码 → `429 CODE_RATE_LIMITED` | `modules/M08-账号历史与彻底删除.md` §5.1 |
| 异常调用发现 | **本期无自动风控**：不做行为分析、不做黑名单、不做频率熔断 | 留审计行（`generation.create` / `auth.login`），由人工查库 |

**明确不做**：不基于 IP 或设备指纹做风控，不做自动封禁。本期风控的全部产出是**可事后审计的记录**，不是自动拦截。

## 9. 措辞与情感安全

### 9.1 禁用措辞（出现即返工）

以 `pages/P00-设计基准与路由.md` §9.3 为唯一清单：`复活` · `重生` · `重获新生` · `让ta回来` · `ta` · `一键还原青春` · `年轻时的样子` · `完美的全家福` · `太棒了` · `奇迹` · `惊喜` · `修复` · `逝者` / `离开的人` / 任何殡葬语境词。

本文件补充一条口径：**`修复` 是禁用词，因为在产品语境里它是虚假承诺**——本链路没有修复步骤（`README.md` §0.2），任何"修复""变清晰""还原清晰度"的表述都在承诺一件系统不做的事。同理禁止对修复能力的任何暗示性描述。

### 9.2 首次使用的情感安全提示

首次进入生成结果页前，必须展示一次温和说明，语义固定为：**"我们会尽力还原照片的样子，但这是基于照片的重建，无法替代真实。"** 措辞可调，语义不可改，且不得使用 `逝者` / `离开的人` 这类指涉。

### 9.3 与"不做"清单的呼应

不做视频生成、不做语音合成、不做数字人对话、不做"让照片动起来"（`spec/00-总纲.md` §6.2）。这不只是范围问题：上述形态会显著放大心理伤害与合规风险，是**合规决定**，不是排期决定。

## 13. 非目标与待定决策

### 13.1 非目标

见 §1.2 与 §10，不重复。

### 13.2 待定决策（必须由 `tickets/T06` 在 `## Comments` 补齐）

1. **PNG `tEXt` 的插入位置**：插在 IHDR 之后（规范推荐，见 PNG 规范 §11.3.4）还是所有既有 chunk 之后。两种都能被解析，但只有前者对"IDAT 之前"的读取器友好。**选定后写进 `mark.ts` 注释与 `U-06-01` 的实现**。
2. **CRC-32 来源**：`zlib.crc32` 可用则直接用，否则查表实现。取决于锁定的 Node 版本，实现时确认。
3. **`jpeg` 路径是否同期实现**：本期 `params_json.outputFormat` 固定 `'png'`（`modules/M05-年代场景配置与Prompt拼装.md` §9.2），`jpeg` 分支在 MVP 内不会被触发。建议**同期实现并单测**（`U-06-03`），因为换模型时会立刻用到；若为省工而只留 `throw`，必须在 T06 的 `## Comments` 写明"jpeg 分支未实现"。
