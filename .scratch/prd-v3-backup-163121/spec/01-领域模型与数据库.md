## 1. 实体关系

```
users ─┬─< sessions
       ├─< login_codes
       ├─< photos ──────────< photos(source_photo_id 自引用: preprocessed → original)
       ├─< identity_anchors >── photos(input_photo_ids / preprocessed_photo_id)
       ├─< generations ──────< generation_results >── photos(kind=generated)
       ├─< consents
       ├─< usage_counters
       ├─< content_reviews
       └─< audit_logs

eras ─────< era_scene_profiles >───── scenes
                       │
                       └──< generations >── identity_anchors
```

三类配置资产（`eras` / `scenes` / `era_scene_profiles`）是**纯数据**：新增年代或场景只插数据、不发版，也不改代码。

## 2. 状态机

### 2.1 `identity_anchors.status`（F1 提取任务）

```
queued ──▶ running ──┬──▶ succeeded ──▶ [用户确认] confirmed_by_user=1
                     │                        │
                     │                        └─ 用户重新提取 → 新建一行（不覆盖旧行）
                     ├──▶ failed  ──▶ 重试(retry)= 新建一行 attempt=旧+1
                     └──▶ queued  (worker 崩溃回收：started_at 超时 → 回退 queued)
```

约束：

- `succeeded` 时 `anchor_text` / `features_json` 必须非空；
- `failed` 时 `error_code` 必须非空；
- **只有 `succeeded AND confirmed_by_user = 1` 的锚点才能用于生成**；
- 重新提取 = 插入新行。旧行保留，供历史追溯。

### 2.2 `generations.status`（F2 生成任务）

```
queued ──▶ running ──┬──▶ succeeded  (requested_count 张全部成功)
                     ├──▶ partial    (至少 1 张成功、至少 1 张失败)
                     └──▶ failed     (0 张成功)
                     (worker 崩溃回收：started_at 超时 → 回退 queued)
```

约束：

- `succeeded` / `partial` 必须至少有 1 行 `generation_results`；
- `attempt` 用于"失败自动重试 1 次"；超过 1 次不再自动重试，交由用户手动"再来一组"（新建一行 `generations`）；
- "再来一组"= 新建 `generations` 行，继承上一层全部设定，`created_at` 更新；**绝不覆盖旧任务**。

### 2.3 `photos` 生命周期

```
active (deleted_at IS NULL)
   │
   ├─ 用户删除 → deleted_at = now → 立即从所有读取路径消失
   └─ 物理清理 worker：deleted_at 早于 N 分钟 → 删除磁盘文件 + 物理删除行
```

删除是**级联语义**（在 repository 层实现，不启用 SQLite 外键级联）；只有 `photos` 与 `consents` 有软删除/吊销列，故各表删除方式不同：

| 表 | 删除方式 | 理由 |
|---|---|---|
| `photos` | **软删除**（写 `deleted_at`），由清理任务延迟物理删除 | 磁盘文件删除不可逆，先让它从所有读取路径消失，再从容清理 |
| `identity_anchors` | **立即物理删除** | 无 `deleted_at` 列；`anchor_text` / `features_json` 是敏感面部特征文本，不应在"已删除"状态长期留存 |
| `generations` | **立即物理删除** | 无 `deleted_at` 列；`prompt` 含身份锚点全文，同上 |
| `generation_results` | **立即物理删除**（随其 `generations`） | 仅指向生成图，无独立留存价值 |
| `consents` | **吊销**（写 `revoked_at`），不删行 | 合规留痕：授权与吊销的历史必须可查 |

级联范围：删除一张 `original` 图时，其 `preprocessed` 派生图（`source_photo_id` 指向它）、引用该派生图的 `identity_anchors`、这些锚点下的 `generations` 与 `generation_results`、以及这些生成任务产出的 `photos(kind='generated')` **全部**被处理；`consents` 中 `anchor_id` 命中被删锚点的行写 `revoked_at`。删除锚点时**不动**原图与预处理图。完整规则表见 `modules/M08-账号历史与彻底删除.md` §3.3。

## 3. 表字典

> 约定：
> - 主键统一 `INTEGER PRIMARY KEY AUTOINCREMENT`（除 `eras.code` 用业务主键）。
> - **所有时间戳为 `TEXT`，UTC ISO-8601**，形如 `2026-09-17T15:07:42.000Z`。
> - **所有 JSON 列名为 `*_json`，类型 `TEXT`**，存序列化 JSON；写入前用 zod 校验。
> - 所有布尔用 `INTEGER` 0/1。
> - `storage_key` 一律是**相对存储根的相对路径**，绝不存公网 URL。

## 4. 设计决策（以及为什么）

| 决策 | 备选 | 理由 |
|---|---|---|
| 单一 `identity_anchors` 表兼作提取任务 | 拆成 `anchor_jobs` + `identity_anchors` 两张表 | 提取任务与锚点 1:1，拆表只会让 worker 和查询多一次 join。状态机仍然清晰（§2.1） |
| `generations` 兼作生成任务，不引入通用 `jobs` 表 | 通用队列表 + 领域表 | 本期只有两种异步操作（提取、生成），通用队列是过度抽象，且会让"可复现参数"分散两处 |
| 无对象存储，`storage_key` 指向本地文件 | S3/OSS | 本期目标是本地可跑；`StorageProvider` 抽象保留替换能力（见 `modules/M01-照片资产与存储.md`） |
| 时间戳存 TEXT/ISO-8601 | INTEGER 毫秒 | 可直接用 SQLite 字符串比较与 `date()` 函数，可读性高，跨工具无歧义 |
| 配置资产（E/S/Profile）落库而非代码常量 | 写死在 `constants.ts` | `docs/raw/AIGC_PRD.md` §10 明确要求"新增年代或场景无需发版"；且 prompt 需要版本化与 A/B |
| 不启用 SQLite 外键级联删除 | `ON DELETE CASCADE` | 业务要求"软删除 + 延迟物理清理"，级联会绕过软删除语义 |
| 重新提取/再来一组 = 插入新行 | 更新原行 | 可复现与可追溯；旧结果不能被覆盖 |

## 5. 迁移与种子策略

### 5.1 迁移

- 目录 `migrations/`，文件 `001-init.sql`、`002-xxx.sql`…（`001-init.sql` 的内容就是 `spec/02-schema.sql`）。
- 一个极简 `migrate.ts`：建 `schema_migrations(version TEXT PRIMARY KEY, applied_at TEXT)` 表，按文件名顺序执行未应用的迁移，**每个文件在单个事务里执行**。
- 迁移**只前进不后退**；开发期重置就删库重跑。

### 5.2 种子

- 种子数据源：`spec/era-scene-seed.json`（本仓库的唯一权威副本）。
- `pnpm seed` 读取该文件，以**幂等 upsert** 写入 `eras` / `scenes` / `era_scene_profiles`。
- 种子**不覆盖**已存在的 `generations` 等业务数据；只 upsert 配置表。
- 校验：种子写入后必须断言 `eras=4`、`scenes=5`、`era_scene_profiles=20`，否则 `pnpm seed` 非零退出。

### 5.3 库文件位置

- 路径由 `DATABASE_PATH` 环境变量决定，默认 `./data/app.db`。
- `./data/` 与 `./storage/` 均在 `.gitignore` 中。
