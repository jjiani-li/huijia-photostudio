## 1. 产品定义

### 1.1 一句话

> 上传一张（模糊的）旧照片，提取人物的**面部特征锚点**，再按用户选择的【年代 × 场景】生成该人物在**全新场景**下的真实感照片。

### 1.2 这是一个什么产品，不是什么产品

| 是 | 不是 |
|---|---|
| **特征保真**的面孔复用：同一个人，出现在他从未拍过的新场景里 | ❌ 老照片修复/超分/去划痕（那是 F1 以前的错误定位） |
| **年代质感重建**：生成结果要"像是那个年代拍出来的" | ❌ AI 换脸、数字复活、让照片动起来 |
| 照片层面的"补拍"：把缺失的那张照片补上 | ❌ 视频生成、语音合成、数字人对话 |

### 1.3 为什么"修复"不是这个产品

旧照片的价值在于它是这个人的唯一证据：若第一步是"用 AI 把照片重画清楚"，后续所有生成图锚定的都是一张 **AI 想象的脸**，身份保真从根上断掉——所以第二步做的是**读**（提取特征），不是**画**（重建图像）。

### 1.4 三个不可让步的属性

1. **像他**——生成图必须逼近**旧照片里那个人**，不能被理想化、年轻化、美化；
2. **像那个年代**——色调、颗粒、光比、道具、服饰必须属于所选年代或更早；
3. **像拍出来的**——第一反应必须是"这是一张照片"，而不是"这是一张 AI 图"。

## 2. 目标用户

| 用户 | 特征 | 核心诉求 | 主要风险 |
|---|---|---|---|
| 主要用户 · 中青年子女（30–55 岁） | 替父母/自己整理旧照片，手机操作，不懂 AI | 让逝去的父亲重新出现在一张像样的照片里 | 生成结果"一眼 AI"→ 二次伤害 |
| 次要用户 · 年长亲属（55 岁+） | 由子女引导使用，对"假"极度敏感 | 全家福/生活照要"看着是真的" | 面部失真 → 直接否定整个产品 |
| 边界用户 · 影像修复从业者 | 批量处理 | 效果稳定、可控、可复现 | 无 |

**本期只为「主要用户」做设计**，其余两类不做专门适配。

## 3. 核心链路（权威版）

```
┌─────────────┐
│ ① 上传旧图   │  1–5 张，jpg/png/heic
└──────┬──────┘
       │  photos(kind=original)
┌──────▼──────────────┐
│ ② 预处理与质量评分    │  归一化、方向/格式/尺寸统一、可读性评分（不修复、不美化）
└──────┬──────────────┘
       │  photos(kind=preprocessed) + quality_json
       │  ← 若不可用：明确告知"建议换一张"，不硬走
┌──────▼──────────────┐
│ ③ 特征锚点提取（F1）  │  多模态模型读图 → anchor_text + features_json
└──────┬──────────────┘   显式防美化：写出皱纹深度/老年斑/皮肤松弛
       │  identity_anchors(status=succeeded)
┌──────▼──────────────┐
│ ④ 身份确认 + 授权     │  ★ 强制节点：用户必须点"这就是他"
└──────┬──────────────┘  + 勾选授权确认（consents）
       │  identity_anchors(confirmed_by_user=1)
┌──────▼──────────────┐
│ ⑤ 选择年代 × 场景     │  E1–E4 × S1–S5，低置信组合给温和提示
└──────┬──────────────┘
       │  eras / scenes / era_scene_profiles
┌──────▼──────────────┐
│ ⑥ Prompt 拼装         │  身份锚点 + 年代质感包 + 场景空间包 + 写实锚定 + 正向化年代约束
└──────┬──────────────┘
       │  prompt（落库，带版本号与 hash）
┌──────▼──────────────┐
│ ⑦ 生成（异步）        │  Seedream lite，参考图 = 预处理图，2–4 张候选
└──────┬──────────────┘
       │  generations + generation_results + photos(kind=generated)
┌──────▼──────────────┐
│ ⑧ 生成后复核          │  年代穿帮复核 + 年龄偏差估计 + 内容安全审核
└──────┬──────────────┘
       │  generation_results.era_check_json / age_delta
┌──────▼──────────────┐
│ ⑨ 挑选 / 再生成 / 下载 │  历史记录按链路展示，可"用同样设定再生成"
└─────────────────────┘
```

**链路铁律**：

- ③④ 之间是**强制确认节点**。未确认的锚点不得用于生成（接口层直接拒绝，见 `spec/03-接口契约.md` 错误码 `ANCHOR_NOT_CONFIRMED`）。
- ⑥ 的 prompt 必须由 `spec/05-Prompt工程.md` 的模板拼装，**不得在业务代码里内联 prompt 字符串**。
- ⑦ 的每一次调用都必须把 prompt、参考图 id、锚点 id、年代、场景、模型、size、seed 全部落库。

## 4. 真实感定义（最高优先级约束）

> 与 `docs/raw/AIGC_PRD.md` §2 一致，**任何功能与之冲突时以本节为准**。

### 4.1 三类目标质感

| 年代 | 参考样态 |
|---|---|
| E1 · 50–70 | 黑白/极轻泛黄胶片扫描：颗粒、划痕灰点、四角暗角、高反差 |
| E2 · 80–90 | 彩色胶卷：偏青或偏暖红、明显彩色颗粒、闪光灯直打 |
| E3 · 00 | 早期数码：略灰、偏冷/偏绿、数码噪点、低动态范围、闪光灯压脸 |
| E4 · 10–20 | 智能手机：通透、白平衡基本准确、构图随意、轻微算法痕迹 |

### 4.2 必须保留（Preserve）

- 面部身份特征：五官比例、痣、疤、牙齿形态、发型、脸型轮廓、**年龄痕迹**；
- 皮肤真实纹理：毛孔、细纹、法令纹、老年斑、肤色不均；
- 年代感：色调偏移、颗粒/噪点、轻微对焦不实、镜头畸变、闪光灯痕迹。

### 4.3 严禁出现（红线）

| 类别 | 禁止项 |
|---|---|
| 皮肤 | 塑料感、蜡像感、过度磨皮、零毛孔 |
| 质感 | 3D 渲染感、CG、插画风、HDR 过度、锐化过度 |
| 面部 | 五官完美对称、AI 高光、牙齿过白过齐 |
| **年龄** | **把老人磨年轻**（皱纹、老年斑、皮肤松弛被抹平） |
| 背景 | 过饱和、与年代不符的现代物件、虚化逻辑错误 |
| 整体 | "一眼 AI"的精致感、影楼摆拍感 |

### 4.4 可度量目标

| 指标 | 定义 | 目标 |
|---|---|---|
| 面部相似度 | 生成图与源照片人脸特征向量余弦相似度 | ≥ 0.55 |
| 年龄保真度 | 自动估计的年龄偏差 \|age_delta\| | ≤ 5 岁 |
| 年代一致性 | 评审判断"像那个年代拍的"通过率 | ≥ 70% |
| 年代穿帮率 | 生成图出现该年代之后物件的比例 | ≤ 3% |
| 盲测真实率 | 生成图被误判为真实老照片的比例 | ≥ 60% |
| AI 感投诉率 | 用户主动反馈"太假/塑料感"占比 | ≤ 5% |

前两项与年代穿帮在 MVP 内**自动化检查**（见 `spec/07-验收标准.md`）；后三项依赖人工评审样本集，MVP 只交付检查工具与流程。

## 5. 术语表

| 术语 | 含义 | 代码中的载体 |
|---|---|---|
| **身份锚点 / anchor** | 用于保证跨图一致的人物面部特征约束文本 | `identity_anchors.anchor_text` |
| **特征结构 / features** | 结构化的面部特征（性别、年龄段、发型、脸型…） | `identity_anchors.features_json` |
| **预处理图** | 归一化后的原图，作为生图模型的参考图 | `photos.kind = 'preprocessed'` |
| **参考图 / reference** | 传给 Seedream 的 `image` 参数，身份一致性主要承载 | `generations.reference_photo_ids` |
| **年代包 / Era Pack** | 决定性影像质感的 prompt 片段（E1–E4） | `eras.prompt_pack` |
| **空间包 / Scene Pack** | 决定性空间光线的 prompt 片段（S1–S5） | `scenes.space_pack` |
| **约束包 / Constraint Pack** | 年代一致性的**正向化**约束描述 | `eras.constraint_pack` |
| **组合档案 / Profile** | 年代×场景单元格的微调与视觉特征 | `era_scene_profiles` |
| **常见度 / confidence** | 组合稀有度，低值触发界面温和提示 | `era_scene_profiles.confidence` |
| **年代穿帮** | 画面中出现所选年代之后才存在的物件 | `generation_results.era_check_json` |
| **年龄保真度** | 生成人物年龄与源照片年龄的偏差 | `generation_results.age_delta` |
| **反 AI 感** | 消除塑料感/过度磨皮等生成痕迹的整体要求 | `spec/05-Prompt工程.md` §3 |
| **防美化** | 显式禁止理想化、减龄的指令与约束 | 三处落点，见 `README.md` §0.3 |

## 6. 本期范围与非目标

### 6.1 本期做（P0）

| 编号 | 功能 | 说明 |
|---|---|---|
| F1′ | **关键特征提取与预处理** | 预处理 + 质量评分 + 锚点提取（重定义后的 F1） |
| F2 | **年代 × 场景 真实感生成** | 主功能：20 组合矩阵驱动的生图 |
| F5 | **极简账号与历史记录** | 验证码登录 + 链路历史 + 彻底删除 |
| F6′ | **支撑能力** | 身份确认节点、候选与重试、prompt 版本管理、情感安全提示、授权确认、内容审核 |
| — | **横切合规** | 标识、授权、删除、审核的代码落点 |

### 6.2 本期明确不做

| 不做项 | 原因 | 留的扩展位 |
|---|---|---|
| **图像修复/超分/去划痕** | 与产品定位冲突（见 §1.3） | `photos.kind` 可扩展；预处理层可加 `EnhanceProvider` |
| **F3 多人全家福融合** | 单人链路的稳定性优先；单独需要 3–4 条 ticket | `generations` 预留 `reference_photo_ids` 数组；`scenes`/`eras` 与人数无关 |
| **F4 图片反推提示词（含推荐年代/场景）** | 控制权增强项，不阻塞主链路 | `identity_anchors` 的读图能力可直接复用为 `prompt_reverse` 任务类型 |
| **自定义场景描述（"自己描述"入口）** | 引入 prompt 注入与审核成本 | `scenes` 表可插入自定义行，`prompt_override` 与 `space_pack` 结构已支持 |
| **用户直接编辑底层 prompt** | 与"用户只选年代与场景"的定位冲突 | `generations.prompt` 已落库，可做高级模式只读展示 |
| **视频生成 / 语音 / 数字人** | 与"真实照片"定位冲突，合规风险 | 无 |
| **云部署、对象存储、真实短信通道** | 本期目标是本地可跑通 | 三个 Provider 抽象（Storage / SMS / Ark）已就位 |
| **盲测平台/标注后台** | 依赖人工流程 | 交付可执行检查脚本（`spec/07-验收标准.md`） |

### 6.3 里程碑（本期压缩为 M1–M3）

| 阶段 | 内容 | 出口条件 | 覆盖 ticket |
|---|---|---|---|
| **M1 · 链路打通** | 脚手架 + 数据层 + 上传 + 预处理 + 锚点提取 + 身份确认 | 上传一张旧照片，能拿到 anchor_text 并由用户确认 | `tickets/T01`–`T07` |
| **M2 · 生成打通** | 年代场景配置 + prompt 拼装 + 生成编排 + Seedream + 生成后复核 | 选 E4×S3 能生成 2–4 张候选并落库、可通过复核 | `tickets/T08`–`T11` |
| **M3 · 产品闭环** | 账号 + 历史 + 删除 + 前端全流程 + 验收工具 | 真实用户可完整走完一次流程；验收脚本全绿 | `tickets/T12`–`T18` |

## 7. 成功判据

MVP 交付时，必须能在本地一条命令跑通：

```bash
pnpm dev          # 前端 + 后端
pnpm worker       # 异步任务 worker
```

并且：

1. 用 `docs/老照片/*.jpg` 作为输入，走到生成出图（`PROVIDER=mock` 离线，`PROVIDER=real` 真实）；
2. 数据库里能查到完整的链路记录：`photos → identity_anchors → generations → generation_results`；
3. `pnpm check:acceptance` 全绿（见 `spec/07-验收标准.md`）。
