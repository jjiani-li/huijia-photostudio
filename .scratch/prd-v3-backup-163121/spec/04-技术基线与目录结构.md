## 1. 技术基线

| 项 | 选择 |
|---|---|
| 运行时 | Node.js ≥ 20.11，TypeScript strict |
| 框架 | Next.js 15 App Router（Route Handlers 作后端，React 作前端） |
| 数据库 | SQLite + `better-sqlite3`（同步 API），手写 SQL，无 ORM |
| 校验 | `zod`（请求解析 + 响应断言 + fixture 校验） |
| 图像处理 | `sharp`（预处理、质量评分、缩略图） |
| 测试 | `vitest` |
| 样式 | Tailwind CSS |

**不使用**：Prisma / Drizzle（避免 schema 双源）、Redis / BullMQ（SQLite 表即队列）、axios（用内置 `fetch`）。

## 3. 模块边界与依赖方向

```
                  app/api/**/route.ts
                          │  只做：鉴权 → zod 解析 → 调 service → 封装响应
                          ▼
        ┌─────────── domain/*Service ───────────┐
        │  编排与规则；唯一允许跨 repository 的地方  │
        └───┬────────┬─────────┬────────┬───────┘
            │        │         │        │
        security/  auth/    prompt/  ark/     images/
            │        │         │        │        │
            └────────┴─────────┴────────┴────────┘
                          │  只允许向下调用 repository
                          ▼
                  db/repositories/*  ←→  db/connection
                          │
                     storage/local
```

### 3.1 依赖方向铁律

1. **`app/api/**` 不允许直接调用 repository**，必须经过 `domain/*Service`（简单查询除外：`/api/me`、`/api/history`、`/api/config/era-scene`、`/api/health` 可直接调 repository）；
2. **repository 层不允许调用 `ark/`、`images/`、`storage/`**，它只做 SQL；
3. **`prompt/build.ts` 不允许访问数据库**，它接收已查好的 `era` / `scene` / `profile` 对象；
4. **`shared/types.ts` 不允许 import 任何 `server/` 下的东西**（它会被前端打包）；
5. `jobs/handlers/*` 可以调用 `domain/*Service` 与 repository，但不允许调用 `app/api`。

## 4. 跨模块约定

### 4.1 错误处理

`src/server/domain/errors.ts` 定义唯一错误类型：

```ts
export class AppError extends Error {
  constructor(
    public code: ErrorCode,          // 见 spec/03-接口契约.md §5
    message: string,                 // 用户可见中文文案
    public status: number,           // HTTP 状态码
    public details?: unknown,
  ) { super(message); }
}
```

- Route handler 不得自行组装错误 JSON，**一律 `throw new AppError(...)`**，由 `http/respond.ts` 的 `withErrorHandling()` 包装器转换；
- `withErrorHandling()` 捕获顺序：`AppError` → 按 `status` 返回；`ZodError` → `INVALID_PARAM`；其他 → 记日志并返回 `INTERNAL`（**不把原始 message 透给用户**）；
- worker handler 不得抛 `AppError` 出去，必须捕获并写入任务的 `error_code` / `error_message`。

### 4.2 时间

- 唯一入口 `src/server/domain/time.ts`：`nowIso(): string` 返回 UTC ISO-8601（毫秒精度，`Z` 结尾）；
- 禁止在业务代码里直接用 `new Date().toISOString()` 以外的方式生成时间字符串，禁止本地时区格式；
- "今天"（额度日）用 UTC 日期：`dayKey(): string` → `YYYY-MM-DD`。

### 4.3 数据库

- `getDb()` 返回单例 `Database`，启动时执行 `PRAGMA journal_mode=WAL`、`PRAGMA foreign_keys=OFF`；
- **所有写操作必须包在事务里**（`db.transaction(...)`）。跨表写（如"建锚点 + 写审计"）必须在同一事务；
- repository 函数签名遵循：接收**原子值或 DTO**，返回**领域对象**（camelCase），永不返回数据库原始行；
- 所有 JSON 列：写入前 `JSON.stringify`，读取后立即 `JSON.parse` 并在 repository 边界用 zod 校验。

### 4.4 响应

`http/respond.ts`：

```ts
export const ok = <T>(data: T, status = 200) => NextResponse.json(data, { status });
export const withErrorHandling = (handler) => async (req, ctx) => { /* 见 spec/04-技术基线与目录结构.md §4.1 */ };
```

### 4.5 上传与文件

- 文件系统是唯一存储介质；`storage_key` 由 `storage/index.ts` 的 `buildKey(userId, ext)` 生成：`u{userId}/{uuid}.{ext}`；
- 任何直接拼 `path.join` 的地方都要经过 `LocalStorageProvider`，禁止业务代码散落路径逻辑；
- 写文件用"先写 `.tmp` 再 rename"的原子方式。

### 4.6 异步任务

- 任务来源只有两张表：`identity_anchors(status='queued')` 与 `generations(status='queued')`；
- worker 是**单进程、串行为主**（并发度 `WORKER_CONCURRENCY`，默认 1）：本期不考虑高并发，正确性优先；
- 每个 handler 结构固定：`claim → 置 running → 执行 → 写结果 → 置终态`，任何异常都必须落到 `failed`；
- 心跳：每 5 秒 touch `.<DATA_DIR>/worker-heartbeat`。

### 4.7 命名

| 层 | 约定 |
|---|---|
| 数据库 | `snake_case` |
| TypeScript / API | `camelCase` |
| 文件 | `kebab-case.ts`（类型文件用 `.ts`，React 组件用 `.tsx`） |
| 错误码 | `SCREAMING_SNAKE_CASE` |
| 日志 | `logger.info({ job: 'generate', generationId }, 'msg')`，JSON 结构化 |

## 5. 明确不做（后端）

- ❌ 多进程 / 多 worker 协调（本期单 worker）
- ❌ 通用任务队列抽象
- ❌ 图片修复/超分（见 `spec/00-总纲.md` §6.2）
- ❌ 对象存储、CDN、图片外链
- ❌ 用户可编辑 prompt 的接口
- ❌ 多人全家福（`generations.reference_photo_ids` 已预留数组形状，但本期只写 1 个元素）
