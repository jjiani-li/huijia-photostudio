> **层级**：实现规格层 · 前端页面
> **上游**：`docs/raw/AIGC_PRD.md` §8 ／ `pages/P00-设计基准与路由.md`、`spec/03-接口契约.md`

> 逐页定义「回家照相馆」六个路由的目标、守卫、数据来源、状态、组件树、交互与逐字文案。

## 1. 职责与边界

**做**：把 `spec/03-接口契约.md` 冻结的端点组装成一条用户能走完的链路（上传 → 身份确认 → 选年代场景 → 生成 → 结果 → 历史），并给出每个界面状态的**逐字中文文案**与降级方案。

**不做**：

- ❌ 不新增端点、不新增响应字段——数据形状以 `spec/03-接口契约.md` §4 的 `src/shared/types.ts` 为准；
- ❌ 不读数据库、不解析 `storage_key`、不自行拼图片 URL（`spec/03-接口契约.md` §1、§6.3）；
- ❌ 不在前端拼 prompt、不把 prompt 回传服务端（`spec/03-接口契约.md` §6.1）；
- ❌ 不做"是否可生成"的完整判断——服务端是唯一裁判，前端只置灰按钮（`spec/03-接口契约.md` §6.2）；
- ❌ 不做登录页/登录路由（不在本文档页面清单内，以 `pages/P00-设计基准与路由.md` 的路由表为准）；
- ❌ 不在此重复定义视觉基调、Token 取值、全局状态管理与轮询 hook 的实现（见 `pages/P00-设计基准与路由.md`）。

Token 一律用 Tailwind 工具类指称，固定为：`bg-background` / `bg-surface` / `bg-wood` / `bg-primary` / `bg-primary-soft` / `text-ink` / `text-ink-soft` / `border-border` / `text-danger`。**正文色是 `text-ink`，不要写 `text-primary`**（`colors.primary` 会占用 `text-primary` 这个类名，原因见 `pages/P00-设计基准与路由.md` §3.2 的命名说明）。

## 3. 数据读写

前端不直接读写数据库。下表说明每页触发的端点及其服务端落库（表与字段名以 `spec/01-领域模型与数据库.md` §3 为准）：

| 页面 | 端点 | 服务端落库 |
|---|---|---|
| `/upload` | `POST /api/photos`、`POST /api/photos/:id/preprocess` | 写 `photos(kind='original'/'preprocessed', storage_key, mime, bytes, width, height, sha256, quality_json)`；同请求写 `content_reviews(stage='upload')` |
| `/upload` → `/confirm` | `POST /api/anchors`（+ 写 `audit_logs(action='anchor.extract')`） | 写 `identity_anchors(input_photo_ids, preprocessed_photo_id, status='queued')` |
| `/confirm` | `GET /api/anchors/:id`、`POST /api/anchors/:id/retry` | 读 `identity_anchors(anchor_text, features_json, quality_json)`；retry 插新行 `attempt = 旧 + 1` |
| `/confirm` | `POST /api/anchors/:id/confirm` | 写 `identity_anchors(confirmed_by_user=1, confirmed_at)`、`consents(scope='photo_usage'/'family_agreement', anchor_id, agreed_at)`、`audit_logs(action='anchor.confirm'/'consent.agree')` |
| `/choose` | `GET /api/config/era-scene`、`GET /api/me` | 只读 `eras` / `scenes` / `era_scene_profiles`；读 `users.daily_image_quota`、`usage_counters(user_id, day, images)` |
| `/choose` | `POST /api/generations` | 写 `generations(prompt, prompt_hash, reference_photo_ids, params_json, requested_count, status='queued')`；预扣 `usage_counters.images` |
| `/result` | `GET /api/generations/:id`、`POST /api/results/:id/feedback`、`POST /api/generations/:id/retry` | 读 `generations` + `generation_results(era_check_json, age_delta, user_feedback)`；写 `generation_results(user_feedback)`；插新 `generations` 行并继承设定 |
| `/history` | `GET /api/history`、`DELETE /api/photos/:id` | 读 `identity_anchors` + `photos` + `generations` + `generation_results`（仅未软删除）；软删除 `photos.deleted_at` 并级联标记派生行 |

## 4. 对外接口

**不新增任何端点。** 逐页引用（形状不在此重复定义，小节号一律指 `spec/03-接口契约.md`）：

- `/`：无请求（点按钮时才探测 `GET /api/me`）；
- `/upload`：`GET /api/health` → §3.7；`POST /api/photos`、`POST /api/photos/:id/preprocess` → §3.2；
- `/confirm`：`POST /api/anchors`、`GET /api/anchors/:id`、`POST /api/anchors/:id/confirm`、`POST /api/anchors/:id/retry` → 均 §3.3；
- `/choose`：`GET /api/config/era-scene` → §3.4；`GET /api/me` → §3.1；`GET /api/anchors/:id` → §3.3（校验确认状态）；`POST /api/generations` → §3.5；
- `/result`：`GET /api/generations/:id`、`POST /api/results/:id/feedback`、`POST /api/generations/:id/retry` → 均 §3.5；`GET /api/photos/:id/file` → §3.2（下载与 `?w=` 缩略）；
- `/history`：`GET /api/history` → §3.6；`POST /api/generations/:id/retry` → §3.5；`DELETE /api/photos/:id` → §3.2。

图片地址只使用响应中的 `url` 字段。

## 5. 关键流程与状态机

### 5.1 跨页流转

```
/  ──点"上传一张老照片"──▶ /upload
/upload  ──POST /api/anchors 202──▶ /confirm/[anchorId]
/confirm ──POST .../confirm 200──▶ /choose/[anchorId]
/choose  ──POST /api/generations 202──▶ /result/[generationId]
/result|/history ──"用同样设定再来一组"──▶ /result/[新的 generationId]
任意页 ──401 UNAUTHENTICATED──▶ 登录路由（见 `pages/P01-页面规格.md` §10.2 决策 1），next 记回本页
```

### 5.2 守卫（前端只做体验优化，服务端仍会拦）

| 页面 | 守卫 | 不满足时 |
|---|---|---|
| `/` | 无 | — |
| `/upload`、`/history` | 需登录 | 401 → 跳登录路由，带 `next` |
| `/confirm/[anchorId]` | 需登录；`anchor` 存在且属于当前用户 | 404 → `这次的人物特征记录找不到了` |
| `/choose/[anchorId]` | 需登录；`anchor.confirmedByUser === true` | 未确认 → 重定向 `/confirm/[anchorId]` |
| `/result/[generationId]` | 需登录；`generation` 存在 | 404 → `这组生成记录找不到了` |

### 5.3 异步任务与轮询（协议见 `spec/03-接口契约.md` §2）

| 任务 | 端点 | 间隔 / 超时 | 终止条件 |
|---|---|---|---|
| 锚点提取 | `GET /api/anchors/:id` | 1.5s / 90s | `status ∈ {succeeded, failed}` |
| 生成 | `GET /api/generations/:id` | 2s / 180s | `status ∈ {succeeded, partial, failed}` |

超时后**不自动停**：展示 `还在处理，可以先去别处看看`，保留 `继续看进度` 按钮；请求串行（上一次响应回来再排下一次），不得 `setInterval` 叠加。

### 5.4 幂等与按钮禁用（`spec/03-接口契约.md` §1.5）

`POST /api/anchors`、`/api/anchors/:id/retry`、`/api/generations`、`/api/generations/:id/retry` 非幂等：请求期间禁用触发按钮并显示加载文案；`DELETE *` 幂等，重复删除按成功处理。

## 6. 逐页规格

### 6.1 `/` 首页

- **目标**：一句话说明 + 上传按钮，仅此而已。
- **进入条件与守卫**：公开页，不校验登录，不发任何请求。
- **数据来源**：无。登录态在点击按钮时才探测（`GET /api/me` 401 → 跳登录路由）。
- **状态**：仅静态渲染，无 loading / empty / error（唯一分支是点击后的未登录跳转）。
- **组件树**：`app/(pages)/page.tsx` → `HeroCopy`（标题 + 一句话说明）、`PrimaryAction`（上传入口）。
- **交互与按钮**：唯一可点元素是上传按钮；已登录 → `/upload`，未登录 → 登录路由（`next=/upload`）。无"了解更多""示例图"等次级入口。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 / 按钮 | `回家照相馆` / `上传一张老照片，让他出现在一张从没拍过的新照片里。` / `上传一张老照片` |
| 页脚小字（`text-ink-soft`） | `生成的是新照片，不是把旧照片修清楚。` / `AI 生成，仅供家人留存。` |

**边界与降级**：不在此页提示 worker 存活（`spec/03-接口契约.md` §2.3 规定在上传页顶部）；不做年代/场景预览，一屏一重点。

### 6.2 `/upload` 上传与质量评分

- **目标**：多选上传 1–5 张，逐张展示 `quality`，标注哪张更适合作为基准，`usable=false` 给替代建议。
- **进入条件与守卫**：需登录。`GET /api/health` 的 `worker.alive === false` 时页面顶部提示，**不禁用**后续操作。
- **数据来源**：`GET /api/health`（§3.7）→ worker 提示与 `provider.mode` 小字；每张一次 `POST /api/photos`（§3.2，`multipart/form-data`，字段名 `file`）；每张一次 `POST /api/photos/:id/preprocess`（§3.2）→ `photo` + `quality`；`POST /api/anchors`（§3.3，body `{ photoIds, preprocessedPhotoId }`）→ 202 → 跳 `/confirm/[锚点 id]`。
- **状态**：
  - **loading**：逐张上传/预处理在途 → 卡片骨架 + `正在上传…` / `正在读取照片…`，按钮禁用；
  - **empty**：未选文件 → 空态文案 + 文件选择按钮；
  - **error**：某张返回 `INVALID_FILE_TYPE` / `FILE_TOO_LARGE` / `STORAGE_ERROR` / `INTERNAL` / `CONTENT_REJECTED` → 该行显示错误文案 + `重试上传`，其余张不受影响；
  - **成功**：至少 1 张 `usable = true` → 卡片显示质量摘要与基准标记，`开始提取面部特征` 可点。

```
UploadPage
├── WorkerBanner            (worker.alive=false / provider.mode)
├── FilePicker              (multiple, accept=jpeg|png|webp|heic)
├── PhotoQualityCard × n    (Thumbnail / QualityBadge / WarningList / AdviceBlock / BaselineTag)
├── UploadErrorList         (逐行错误文案 + 重试)
└── ExtractCta              ("开始提取面部特征")
```

- **交互与按钮**：选文件超过 5 张按 `readability` 降序取前 5，其余忽略并提示；基准图在 `usable = true` 中按 `readability` 降序、同值按 `sharpness` 降序取第一张，`usable = false` 一律排后，用户可手动改选（只改 `preprocessedPhotoId`，不重传）；`photoIds` = 全部上传成功的 `original` 图 id（≤5）；按钮 `继续添加` / `删掉这张` / `重试上传` / `开始提取面部特征`；禁用条件：无 `usable = true` 的图、仍有上传或预处理在途、`POST /api/anchors` 请求期间。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 | `选几张他的照片` / `清楚一点的、正脸的最好。选 1 到 5 张。` |
| 空态 | `还没选照片。点上面的按钮，从相册里挑几张。` |
| 上传中 / 预处理中 | `正在上传…` / `正在读取照片…` |
| 基准标记 | `这张最适合当基准` |
| 质量摘要 | `清晰度 {sharpness} · 可读性 {readability}` |
| 不可用替代建议 | `这张的人脸看不清，用它提取出来的特征会不准。建议换一张正脸、光线亮一点的。` |
| 超过 5 张 | `一次最多 5 张，先按前 5 张处理。` |
| 全部不可用 | `这几张都不太适合提取特征。换一张清楚的正面照试试。` |
| 文件类型错误 / 文件过大 | `暂时只支持 jpg、png、webp、heic` / `这张照片太大了，换一张小一点的` |
| worker 未启动 | `后台还没启动，图片处理会卡住` + 命令行 `pnpm worker` |
| 提取质量过低（`ANCHOR_LOW_QUALITY`） | `这张照片的人物特征看不清，建议换一张更清楚的` |
| 主按钮 | `开始提取面部特征` |

**边界与降级**：`quality.warnings` / `quality.advice` 为服务端产出，前端**原样展示、不改写不翻译**，`advice = null` 时不渲染该块；`usable = false` 的图不放行为基准图；其余错误码文案见 `pages/P01-页面规格.md` §7；heic 见 `pages/P01-页面规格.md` §12。

### 6.3 `/confirm/[anchorId]` 身份确认

- **目标**：展示预处理图与 `sourcePhotos`、`anchorText` 与 `features`（可折叠）、`这就是他` 确认按钮、两项授权勾选；覆盖提取中、失败重试、已确认三种进入情形。
- **进入条件与守卫**：需登录；`GET /api/anchors/:id` 404 → `这次的人物特征记录找不到了`，不给重试入口（避免对他人资源探测）。
- **数据来源**：`GET /api/anchors/:id`（§3.3）轮询 1.5s / 90s；`POST /api/anchors/:id/confirm`（§3.3）；`POST /api/anchors/:id/retry`（§3.3，202 返回**新行** → `router.replace` 到新 id）。
- **状态**：
  - **loading**：`status ∈ {queued, running}` → `AsyncStatus` + 三步步骤提示，90s 后转超时态；
  - **empty**：`anchor === null`（首个响应未回）→ 骨架屏；
  - **error**：`status='failed'` → `error.message` + `重新提取一次`；404 → 不给重试；
  - **成功**：`status='succeeded'` → 预处理图 + `sourcePhotos` 缩略 + `anchorText` + 折叠 `features` + 确认区；
  - **已确认**：`confirmedByUser === true` → 展示 `anchorText` 与 `这个人物特征已经确认过了`，主按钮改为 `去选年代和场景`。

```
ConfirmPage
├── AsyncStatus              (queued/running + 步骤提示 + 超时"继续看进度")
├── PreprocessedPreview      (anchor.preprocessedPhoto.url，无则占位)
├── SourcePhotoStrip         (anchor.sourcePhotos[].url)
├── AnchorText               (anchor.anchorText)
├── FeatureList              (默认折叠，12 项)
├── ConfirmPanel             (ConsentCheckbox × 2 + ConfirmButton "这就是他")
└── ErrorNotice              (failed 的 error.code/message + "重新提取一次")
```

- **交互与按钮**：`features` 默认折叠；两项勾选都勾上后 `这就是他` 才可点（服务端仍是唯一裁判，缺任一项 → `400 INVALID_PARAM`）；确认成功跳 `/choose/[anchorId]`；`重新提取一次` 触发 retry，旧锚点保留在历史。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 | `这是照片里的那个人吗` / `下面是系统从照片里读到的外貌特征。先确认一下，是不是他。` |
| 提取中步骤 1 / 2 / 3 | `正在读取照片` / `正在辨认脸部特征` / `正在整理成文字` |
| 轮询超时 | `还在处理，可以先去别处看看` + `继续看进度` |
| 折叠标题（收起 / 展开） | `他长这样（12 项特征）` / `收起` |
| 特征标签 | `性别` `年龄段` `发型` `脸型` `额头` `眉毛` `眼睛` `鼻子` `嘴部` `皮肤` `显著特征` `体型`（依次对应 `gender` `ageRange` `hair` `faceShape` `forehead` `eyebrows` `eyes` `nose` `mouth` `skin` `distinctive` `build`） |
| 确认按钮 | `这就是他` |
| 勾选 1（`photo_usage`） | `我确认对这张照片有合法的使用权。` |
| 勾选 2（`family_agreement`） | `我确认已经获得其他近亲属的同意。` |
| 未勾满提示 | `两项都要勾上才能继续` |
| 已确认标记 / 主按钮 | `这个人物特征已经确认过了` / `去选年代和场景` |
| 重试按钮 | `重新提取一次` |
| 不可确认（`ANCHOR_NOT_CONFIRMED`） | `需要先确认"这就是他"，才能开始生成` |

**边界与降级**：`preprocessedPhoto = null` 时占位显示 `照片还在处理`；`features = null` 而 `status='succeeded'` 时只渲染 `anchorText` 并隐藏折叠区（`pages/P01-页面规格.md` §10.2 决策 4）；`anchorText` 为空时不渲染确认按钮；三步步骤提示只是文案分段，不与服务端进度绑定（服务端只给 `status`）。

### 6.4 `/choose/[anchorId]` 年代 × 场景选择

- **目标**：四个年代大卡片、五个场景卡片、组合预览（`visualSignature` + 常见度提示）、张数 2/3/4、发起生成、额度不足呈现。
- **进入条件与守卫**：需登录；先 `GET /api/anchors/:id` 校验 `confirmedByUser === true`，否则重定向 `/confirm/[anchorId]`。
- **数据来源**：`GET /api/config/era-scene`（§3.4，登录后加载一次并缓存）；`GET /api/me`（§3.1，取 `quota.remaining`）；`POST /api/generations`（§3.5，body `{ anchorId, eraCode, sceneId, count }`）→ 202 → 跳 `/result/[generationId]`。
- **状态**：
  - **loading**：config 与 me 未回 → 卡片骨架；
  - **empty**：`eras` 或 `scenes` 为空 → `年代和场景还没准备好，先跑一次 pnpm seed。`；
  - **error**：401 / 网络失败 → 统一错误块 + `重新加载`；
  - **成功**：年代区 + 场景区 + 预览区 + 张数 + 生成按钮。

```
ChoosePage
├── EraSection               (EraCard × 4：name + caption + sampleUrl，null 时纯文字)
├── SceneSection             (SceneCard × 5：name + caption + coverUrl，null 时纯文字)
├── ComboPreview             (visualSignature + 常见度提示)
├── CountPicker              (2 张 / 3 张 / 4 张)
└── GenerateCta              ("开始生成" / "今天的额度不够了")
```

- **交互与按钮**：年代与场景各选一个；两者都选定后从 `profiles` 按 `(eraCode, sceneId)` 匹配展示 `visualSignature`，匹配不到则不渲染预览区（不推断）；`profile.confidence < config.confidenceHintThreshold` 时在预览区加一行温和提示，**不禁用**该组合；年代卡片用 API 的 `isMono` 标注黑白年代；张数默认选中 2 张（`pages/P01-页面规格.md` §10.2 决策 2）；禁用条件（任一命中即置灰并给对应文案）：未选年代、未选场景、`quota.remaining < count`——"已有非终态生成"服务端才可知，前端靠 `409 GENERATION_IN_PROGRESS` 反馈。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 说明 | `让他出现在哪个年代、哪个地方` / `先选年代，再选场景。两个都可以随时改。` |
| 分区标题 | `先选年代` / `再选场景` / `你选的组合` |
| 常见度提示 | `该组合比较少见` |
| 张数标题 / 选项 | `生成几张` / `2 张` `3 张` `4 张` |
| 未选完 | `上面先各选一个` |
| 主按钮 / 生成中 | `开始生成` / `正在生成，大概要等一会儿` |
| 额度不足（前端） | `今天的额度不够了`；附注 `今天还能生成 {remaining} 张` |
| 额度用尽（`QUOTA_EXCEEDED`） | `今天的生成额度用完了，明天再来吧` |
| 并发冲突（`GENERATION_IN_PROGRESS`） | `上一组还在生成，稍等一下` |
| 授权缺失（`CONSENT_REQUIRED`） | `需要先确认照片使用授权` |
| 种子未跑 | `年代和场景还没准备好，先跑一次 pnpm seed。` |

**边界与降级**：`caption` 为服务端文案，前端不改写；样片与封面全为 `null` 时整页仍是可用的纯文字选择（`pages/P01-页面规格.md` §12）；不提供"自己描述场景"输入框，不提供 prompt 预览（`spec/03-接口契约.md` §3.4 明确不下发 prompt 资产）。

### 6.5 `/result/[generationId]` 生成结果

- **目标**：轮询进度、网格展示、放大查看、每张 `eraCheck` 状态与 `ageDelta` 提示、喜欢/不喜欢、下载、用同样设定再来一组、`partial`/`failed` 呈现与重试。
- **进入条件与守卫**：需登录；`GET /api/generations/:id` 404 → `这组生成记录找不到了`。
- **数据来源**：`GET /api/generations/:id`（§3.5）轮询 2s / 180s；`POST /api/results/:id/feedback`（§3.5）；`POST /api/generations/:id/retry`（§3.5，202 新行 → 跳 `/result/[新 id]`）；下载用 `results[].url`（§3.2）。
- **状态**：
  - **loading**：`status ∈ {queued, running}` → 进度态 + 已到位候选网格（`results` 可能为空数组），180s 后转超时态；
  - **empty**：非终态且 `results.length === 0` → `正在生成，大概要等一会儿` + `共 {requestedCount} 张`；
  - **error**：`status='failed'` → `这次没生成出来` + `error.message` + `再试一次`；
  - **成功**：`succeeded` → 完整网格 + 每张反馈与下载；
  - **部分成功**：`partial` → 成功网格 + `这几张只成功了一部分` + `再试一次`。

```
ResultPage
├── AsyncStatus / GenerationHeader   (eraName × sceneName、requestedCount、status)
├── ResultGrid
│   └── ResultCard × n               (Thumbnail / EraCheckBadge / AgeDeltaNotice /
│                                     FeedbackButtons / DownloadLink)
├── PartialNotice                    (partial / failed)
└── RetryCta                         (用同样设定再来一组)
```

- **交互与按钮**：点击缩略图打开 `Lightbox`（左右切换、Esc 或点空白关闭、键盘 ← →）；`EraCheckBadge` 按 `eraCheck.verdict` 四态渲染，`review` 时展开列出 `findings[].item` / `findings[].reason`；`AgeDeltaNotice` 仅当 `ageDelta !== null` 且 `Math.abs(ageDelta) > 5` 时出现（阈值同 `spec/00-总纲.md` §4.4、`spec/05-Prompt工程.md` §4）；反馈写 `1` / `-1`，再点同一按钮写 `null` 取消，请求期间该按钮禁用；下载支持单张与 `全部下载`（逐张触发，单张失败不影响其余），文件名 `回家照相馆-{eraName}-{sceneName}-{ordinal + 1}.png`；`用同样设定再来一组` 与 `再试一次` 都调 retry（新行、不覆盖历史）后跳新 id。

| 位置 | 逐字文案 |
|---|---|
| 页头 | `{eraName} · {sceneName}` |
| 进度态 / 附注 | `正在生成，大概要等一会儿` / `共 {requestedCount} 张` |
| 轮询超时 | `还在处理，可以先去别处看看` + `继续看进度` |
| 年代徽标 | `年代没问题`（`pass`） / `年代可能有对不上的东西`（`review`） / `这张年代有问题`（`reject`） / `还没检查`（`eraCheck === null`） |
| 年龄偏小 / 偏大提示 | `这张看着比原照片年轻 N 岁` / `这张看着比原照片年长 N 岁`（N 取 `ageDelta` 的绝对值） |
| 反馈按钮 | `喜欢` / `不喜欢` |
| 下载 | `下载这张` / `全部下载` |
| 放大查看 | `按 Esc 或点空白处关闭` |
| 再来一组 / 失败重试 | `用同样设定再来一组` / `再试一次` |
| 部分成功 / 失败 | `这几张只成功了一部分` / `这次没生成出来` |
| 上游超时 / 上游错误 | `生成花的时间有点长，请重试一次`（`PROVIDER_TIMEOUT`） / `生成服务暂时不可用，请稍后重试`（`PROVIDER_ERROR`） |

**边界与降级**：`eraCheck = null` 与 `ageDelta = null` 均按"尚未有结论"处理，不显示推测性提示；`partial` 时不隐藏成功结果（`spec/03-接口契约.md` §3.5：非终态返回已有部分）；`seed` 与 `realismScore` 本期不在界面展示（`realismScore` 恒为 `null`，见 `spec/07-验收标准.md` §6）。

### 6.6 `/history` 历史记录

- **目标**：按链路展示（原图 → 锚点 → 生成图）、标注年代与场景、沿用同样设定再生成、删除（含二次确认）。
- **进入条件与守卫**：需登录；`GET /api/history` 401 → 跳登录路由。
- **数据来源**：`GET /api/history?cursor=&limit=20`（§3.6）；`POST /api/generations/:id/retry`（§3.5）；`DELETE /api/photos/:id`（§3.2，删该链路原图并级联标记派生行）。
- **状态**：
  - **loading**：首屏请求未回 → 链路骨架；
  - **empty**：`items.length === 0` 且 `nextCursor === null` → `这里还没有记录。先去生成一张试试。`；
  - **error**：401 / 网络失败 → 错误块 + `重新加载`；
  - **成功**：链路卡片列表 + `再往下看`。

```
HistoryPage
├── HistoryChain × n           (SourceThumb / AnchorSummary /
│                               GenerationRow × m / HistoryActions)
│   └── HistoryActions         ("用同样设定再生成" / "删掉这次记录")
├── ConfirmDialog              (删除二次确认)
└── LoadMore                   ("再往下看"，nextCursor === null 时隐藏)
```

- **交互与按钮**：链路三段顺序连接 `sourcePhoto → preprocessedPhoto/anchorText → generations[].results[]`；每条 generation 标注 `eraName` × `sceneName` 与 `status`（`partial` / `failed` 文案同 `pages/P01-页面规格.md` §6.5）；`用同样设定再生成` 对某条 generation 调 retry 后跳 `/result/[新 id]`；`删掉这次记录` 打开 `ConfirmDialog`，确认后调 `DELETE /api/photos/{sourcePhoto.id}`，成功后移除该链路并展示级联数量；`再往下看` 把上次 `nextCursor` 原样回传（不解析，`spec/03-接口契约.md` §6.4）。

| 位置 | 逐字文案 |
|---|---|
| 标题 / 链路标签 | `生成过的记录` / `原照片` → `人物特征` → `生成的照片` |
| 空态 | `这里还没有记录。先去生成一张试试。` |
| 复用按钮 | `用同样设定再生成` |
| 删除按钮 | `删掉这次记录` |
| 删除确认标题 / 正文 | `删掉这次记录？` / `照片、人物特征和生成结果都会一起删掉，删了拿不回来。` |
| 删除确认按钮 / 取消 | `删掉` / `算了` |
| 删除成功 / 级联提示 | `删掉了` / `一起删掉了 {results} 张生成图` |
| 分页按钮 | `再往下看` |
| 未确认锚点 | `这个人还没确认过，不能用来生成` |

**边界与降级**：只展示服务端返回的**未软删除**内容，前端不做本地过滤；不展示 `generations.prompt`（`spec/03-接口契约.md` §6.1）；每条锚点的 generation 条数以服务端返回为准（上限 10 条）。

### 6.7 `/login` 登录

**目标**：用验证码登录。不做密码、不做注册流程、不做社交绑定。

**进入条件与守卫**：**不需要登录**。从受保护页面被软重定向而来时 URL 带 `next`（缺省 `/upload`）；登录成功后 `router.replace(next)` 并 `router.refresh()`，让 Server Component 重新读到 `sid`。

**数据来源**：`POST /api/auth/code`、`POST /api/auth/login`（`spec/03-接口契约.md` §3.1）。

**组件树**

```
app/(pages)/login/page.tsx              Server Component（无数据需求）
└─ <LoginPanel />                       Client Component
   ├─ <input inputMode="tel" />        手机号或邮箱
   ├─ <button>获取验证码</button>
   ├─ <input inputMode="numeric" maxLength={6} />   验证码
   └─ <button>登录</button>
```

**状态**

| 状态 | 呈现 |
|---|---|
| 初始 | 只显示 identifier 输入框与「获取验证码」 |
| 已发码 | 追加验证码输入框与「登录」按钮；「重新获取」禁用 60 秒，按钮文字固定为 `稍等一下`，**不显示倒计时秒数**（`pages/P00-设计基准与路由.md` §3.1 禁止倒计时压迫感） |

**逐字文案**

| 位置 | 逐字文案 |
|---|---|

| 重发按钮 | `重新获取` |

| 底部小字 | `我们不会把你的照片用在别的地方。` |

- 不做「记住我」「忘记密码」「第三方登录」「一键登录」。
- 不发码也可以直接手输验证码提交（服务端仍会校验），不额外加前端门槛。
- identifier 前端只做去空格与非空校验，格式判定交给服务端（`INVALID_PARAM`）。

## 7. 边界与错误

前端只做一处映射：`ApiError.error.code` → 逐字文案。**默认取服务端 `error.message` 原样展示**（`spec/03-接口契约.md` §1.3 规定该字段可直接展示），下表用于 `message` 缺失或页内需要更具体措辞时兜底；文案与 `spec/03-接口契约.md` §5 逐字一致。

| code | 触发条件 | 用户可见文案 |
|---|---|---|
| `UNAUTHENTICATED` | 未登录或会话过期 | `请先登录` |
| `FORBIDDEN` | 访问他人资源 | `没有权限访问这张照片` |
| `NOT_FOUND` | 资源不存在或已删除 | `这张照片找不到了` / 页内：`这次的人物特征记录找不到了`、`这组生成记录找不到了` |
| `INVALID_PARAM` | 参数校验失败 | `选择有误，请重新选一下` |
| `INVALID_FILE_TYPE` | 非 jpg/png/webp/heic | `暂时只支持 jpg、png、webp、heic` |
| `FILE_TOO_LARGE` | 超过 `MAX_UPLOAD_MB` | `这张照片太大了，换一张小一点的` |
| `CONSENT_REQUIRED` | 未勾选授权确认 | `需要先确认照片使用授权` |
| `ANCHOR_NOT_FOUND` | 锚点不存在 | `这次的人物特征记录找不到了` |
| `ANCHOR_NOT_CONFIRMED` | 锚点未成功或未确认 | `需要先确认"这就是他"，才能开始生成` |
| `ANCHOR_LOW_QUALITY` | 提取质量过低 | `这张照片的人物特征看不清，建议换一张更清楚的` |
| `GENERATION_IN_PROGRESS` | 已有非终态生成任务 | `上一组还在生成，稍等一下` |
| `QUOTA_EXCEEDED` | 超过每日额度 | `今天的生成额度用完了，明天再来吧` |
| `CONTENT_REJECTED` | 内容审核拒绝 | `这张照片暂时无法处理` |
| `PROVIDER_ERROR` / `PROVIDER_TIMEOUT` | 上游错误 / 上游超时 | `生成服务暂时不可用，请稍后重试` / `生成花的时间有点长，请重试一次` |
| `STORAGE_ERROR` / `INTERNAL` | 磁盘读写失败 / 兜底 | `保存失败，请重试` / `出了点小问题，请重试` |

跨页规则：受保护端点的 401 统一触发登录跳转并记录 `next`；网络层失败（fetch 抛错）按 `INTERNAL` 文案 + `重试` 处理，不得白屏；轮询失败**不终止**轮询，页内显示一行错误后继续（超时规则见 `pages/P01-页面规格.md` §5.3）；文案语气遵守 `spec/00-总纲.md` §1 与 `docs/raw/AIGC_PRD.md` §8.1——第二人称、平实、不煽情，禁用"复活""重生""让 ta 回来"等词。

## 9. 测试要点

单元测试（`vitest`，纯函数优先，不依赖网络）：

- `pickBaseline(cards)`：`readability` 降序、同值按 `sharpness` 降序、`usable=false` 排最后；全不可用返回 `null` —— 对齐 `E2E-01`（前端段）；
- `ageDeltaNotice(ageDelta)`：仅在 `|x| > 5` 时返回文案，`= 5` / `0` / `null` 返回 `null` —— 对齐 `spec/00-总纲.md` §4.4；
- `eraCheckBadge(eraCheck)`：`pass`/`review`/`reject`/`null` 四态文案互不相同且穷尽；
- `confidenceHint(confidence, threshold)`：`< threshold` 返回 `该组合比较少见`，否则 `null` —— 对齐 `DB-04`；
- `apiErrorMessage(code)`：对 `src/shared/types.ts` 的全部 `ErrorCode` 有映射，与 `spec/03-接口契约.md` §5 逐字一致（穷尽 switch，无 `default`）—— 对齐 `API-02`；
- `downloadFileName(eraName, sceneName, ordinal)`：`回家照相馆-{eraName}-{sceneName}-{n}.png`；
- `usePolling`（mock fetch）：间隔 1.5s / 2s、上一个响应回来才发下一个、终态停止、超时后不自动停 —— 对齐 `spec/03-接口契约.md` §2.1。

端到端与守卫（手工或检查项覆盖）：

- 未登录访问 `/upload`、`/confirm/*`、`/choose/*`、`/result/*`、`/history` → 跳登录路由并保留 `next`（`API-03`）；用他人的 `anchorId` / `generationId` 打开 → "找不到"文案而非 403（`API-04`）；
- `/history` 手机号脱敏含 `*`（`API-05`）；年代/场景卡片数据源不出现 prompt 相关字段（`API-06`）；
- 未确认锚点直接打开 `/choose/[anchorId]` → 重定向 `/confirm/[anchorId]`（`SEC-01`）；只勾一个授权项点确认 → `400 INVALID_PARAM` 且 `confirmed_by_user` 仍为 0（`SEC-02`）；
- 吊销 `photo_usage` 后点生成 → `403 CONSENT_REQUIRED` 文案（`SEC-03`）；`daily_image_quota` 改为 1 后选 2 张 → 按钮前置灰为 `今天的额度不够了`，强发返回 `429 QUOTA_EXCEEDED`（`SEC-04`）；
- 已有非终态生成时点生成 → `409 GENERATION_IN_PROGRESS` 文案（`SEC-05`）；`/history` 删除链路后该链路立即消失（`DEL-01`）；
- worker 未启动时 `/upload` 顶部出现 `后台还没启动，图片处理会卡住` 与 `pnpm worker`（`ERR-04`）。

ticket 归属：页面与组件对应 `tickets/T15` / `tickets/T16` / `tickets/T17`；通用完成判定见 `spec/07-验收标准.md` §5。

## 10. 非目标与待定决策

### 10.1 非目标（本期不做）

- 自定义场景描述入口、用户可编辑 prompt、prompt 只读展示页；多人全家福入口与"家人参考图"上传；
- 盲测/评分后台、点赞数据看板；可见 AIGC 标识开关 UI（规则以 `spec/06-合规与风控.md` 为准）；
- 深色模式、多语言、PWA、离线缓存；图片裁剪/旋转等编辑能力（预处理由 `POST /api/photos/:id/preprocess` 完成，不提供手动参数）。

### 10.2 待定决策

1. **登录路由不在本文档页面清单内**：所有守卫按"跳登录路由并带 `next`"书写，路径与形态以 `pages/P00-设计基准与路由.md` 的路由表为准。
2. **`GENERATION_DEFAULT_COUNT` 没有下发通道**：`GET /api/me` 与 `GET /api/config/era-scene` 都不返回该值，前端因此在 `/choose` 固定默认选中 2 张（与其默认值一致），不读环境变量；若要服务端驱动，需在契约新增字段——本期不改契约。
3. **`HistoryItem.generations` 的类型声明与响应示例不一致**：`spec/03-接口契约.md` §4 声明为 `Generation[]`，§3.6 示例对象却缺 `prompt` / `params` / `templateVersion`。前端只使用 §3.6 示例中出现的字段；是否统一由 `spec/03-接口契约.md` 的维护者决定。
4. **`status='succeeded'` 但 `features = null`**：`spec/01-领域模型与数据库.md` §2.1 要求 `succeeded` 时两项非空，前端仍按"只展示 `anchorText`、隐藏折叠区"降级，避免白屏。
5. **提取中的"三步步骤提示"是纯前端文案分段**，与服务端进度无对应字段；不得据此显示百分比或剩余时间。
6. **`features` 的中文标签映射**需与 `modules/M03-身份锚点提取.md` §3 的键定义逐项核对；`pages/P01-页面规格.md` §6.3 的映射以 `spec/03-接口契约.md` §4 的 `AnchorFeatures` 为准。

## 12. 本期降级项清单

以下四项是本期**接受的功能降级**，界面须用上述文案诚实表达，不得用占位图或假数据掩盖：

1. **组合样片缺失 → 组合预览只有文字**。`GET /api/config/era-scene` 的 `profiles` 只含 `eraCode` / `sceneId` / `confidence` / `visualSignature`，`eras.sample_photo_id` / `scenes.cover_photo_id` 多为 `NULL`（对应 `sampleUrl` / `coverUrl = null`）。年代卡片、场景卡片、组合预览区在无样片时一律退化为**纯文字卡**（`name` + `caption`，组合区用 `visualSignature`），不显示灰色占位图，也不生成替代样片；`spec/era-scene-seed.json` 本身不含样片字段。
2. **heic 已知限制**：`POST /api/photos`（`spec/03-接口契约.md` §3.2）声明接受 `image/heic`，但 `sharp` 若未编译 heif 支持，本地会返回 `INVALID_FILE_TYPE`（`spec/08-本地开发指南.md` §8）。前端因此：文件选择器仍允许 heic；收到该错误时展示 `暂时只支持 jpg、png、webp、heic` 并建议改用 jpg，不阻断其他已选文件。
3. **无自定义场景入口**：只有 `scenes` 表中的 5 个场景（S1–S5）可选，界面不提供任何文本输入框描述场景，也不提供"其他"选项（`spec/00-总纲.md` §6.2）。
4. **无用户可编辑 prompt**：界面不展示、不编辑、不提交任何 prompt 内容（`spec/03-接口契约.md` §6.1、`spec/05-Prompt工程.md` §10）。`/result` 只呈现 `eraName` × `sceneName` 与年代徽标，用户对生成的控制面只有「年代 × 场景 × 张数」三项。

附带降级（同属本期，记录在此便于对照）：**无可见 AIGC 标识开关 UI**（隐式标识由服务端写入，可见标识规则待 `spec/06-合规与风控.md` 定稿）；**无面部相似度自动展示**（`generation_results.realism_score` 恒为 `null`，见 `spec/07-验收标准.md` §6）。
